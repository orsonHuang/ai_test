# 独立游戏市场调研流程

本 Skill 定义调研的标准步骤与报告格式，调研一律结合联网搜索，结论必须给出处。

## 调研流程

1. **明确问题**：先确认调研目的——品类趋势 / 竞品对比 / 定位验证 / 定价参考，不同目的问题集不同。
2. **检索来源**：优先 TapTap（国内玩家评价、预约量）、Steam（销量区间、好评率、评测数）、SteamDB（销量/峰值曲线）、独立游戏媒体与开发者分享（GDC、itch.io、Reddit r/gamedev、B站/机核等）。使用联网搜索逐条验证。
3. **竞品筛选**：选取 3~5 款同品类标杆，覆盖「爆款、中腰部、失败案例」三档，避免只挑成功的。
4. **数据采集**：对每款竞品记录——发布时间、平台、销量/下载量级、价格、好评率、更新节奏、开发者团队规模（如可查）。
5. **玩家反馈挖掘**：重点读差评与低星评价，归类成「痛点清单」；这些痛点即机会点。
6. **差异化分析**：对比自家定位，输出「我们做什么不同」的可执行结论。

## 报告模板

报告按以下结构输出，建议写入工作区 `.md` 文件：

```
# <品类> 市场调研报告（<日期>）
## 1. 结论摘要（3~5 条，先给结论）
## 2. 品类趋势
## 3. 竞品对比表（名称/平台/量级/定价/好评率/更新节奏/团队）
## 4. 玩家痛点清单（带出处）
## 5. 机会与差异化建议
## 6. 待验证问题（数据缺口、需进一步调研的点）
## 7. 来源链接
```

## 输出约定

- 所有数据结论附来源链接，区分「核实数据」与「推断/估计」。
- 对比用表格，不用长段落；趋势用时间线或短句列表。
- 不确定的数据明确标注"未能核实"，不编造数字。
- 差异化建议必须落到自家游戏可执行的动作上，而非泛泛而谈。
