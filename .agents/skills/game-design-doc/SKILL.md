# 游戏策划案撰写规范

本 Skill 定义设计文档的标准结构与产出格式，保证文档可执行、可评审、可迭代。

## GDD 标准结构

产出设计文档时默认包含以下章节（可按项目裁剪，但不得缺核心闭环）：

1. **一句话定位**：40 字内说清"谁在什么场景下做什么、获得什么体验"。
2. **核心玩法循环**：分三层写——单局内循环（秒级）、单局循环（分钟级）、局外循环（小时/天级）。每个循环画成「动作→反馈→奖励」链。
3. **目标用户与平台**：目标平台（本机为 Godot 4，参考桌面/Steam/TapTap 发布路线）、用户画像、参考竞品。
4. **核心机制清单**：每条机制写「名称 / 目的 / 规则 / 边界条件」，明确哪些是必须、哪些可砍。
5. **系统设计**：系统间依赖关系、数值来源、UI 入口。
6. **数值表**：用 Markdown 表格或可导入的 CSV 格式（先给表头与示例行，再列完整数值）。
7. **美术与音频方向**：风格参考、关键资产清单、技术约束（分辨率、包体）。
8. **MVP 范围**：按「必须 / 重要 / 以后」分级，给出可玩的垂直切片定义。
9. **里程碑**：M0 原型 → M1 垂直切片 → M2 内容量产 → M3 打磨上线，每阶段附验收标准。

## 输出约定

- 文档默认写入工作区 `.md` 文件（如 `docs/GDD.md`），文件名见名知意，可迭代更新。
- 数值一律给"表"而非散文；公式用代码块或 LaTeX 风格写出并解释含义。
- 每节末尾可加「待定项」清单，明确哪些决策需要制作人拍板。
- MVP 范围必须可衡量：写出"完成 = 玩家能 A/B/C"这样的验收句。

## 需求澄清

- 用户只给一句话想法时，先按上述结构出**骨架 + 核心循环草案**，再逐步填实，不要一次写完大而全的文档。
- 用户已有明确机制时，围绕机制补全系统与数值，保持文档与实现同步。
