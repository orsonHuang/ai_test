# 兽境小憩 V2 · 亮将暗走

状态：设计提案，尚未改动试玩代码。2026-09-22。

## 定位与用户反馈
一句话：看出小动物的意图，用假动作抢下森林热点。

用户希望偏休闲，但 V1 体验反馈为策略性偏低、博弈点不足，基本是交替观察后走一步。
目标仍为 Cocos / 微信小游戏；下一轮验证继续使用已授权的浏览器原型。

## V1 的问题诊断
- 检查当前代码：双方每次只走一只动物，所有状态可见；AI 对可见局面做两层搜索。因此很多局部威胁都允许对手先看结果再处理，缺少承诺和同时冒险。
- 棋盘两端各有一个永久得分点，容易出现分区驻守；不能断言每局如此，但当前目标没有持续将双方引向同一场争夺。
- 四类动物中，部分决策主要是比较等级和距离，缺少把对方诱向错误位置的收益。
- 回合制本身并不缺乏策略。V1 的问题是棋盘关系、收益与行动代价不足以产生丰富取舍；增加难度更高的 AI 不能直接解决。

## 推荐机制 A：亮将暗走（必须）
目的：给休闲玩家一个范围有限、可推理的预判问题。

每轮流程：
1. 双方在同一份公开棋盘上秘密选择本轮行动的动物，锁定后不能改。
2. 同时亮出所选动物。棋盘显示双方可走范围，但不显示实际走向。
3. 双方秘密选择该动物的合法目标格，或选择原地等待。提交前可以反复预览。
4. 双方锁定后，同时亮出箭头并结算。

只隐藏当轮目的地，不隐藏棋子身份、等级、地形、比分和历史行动。通过公开所选动物缩小预判范围，避免面对全队的全部未知走法。

休闲 UX：点动物 → 看对手亮将 → 点落点/原地 → 确认；箭头动画解释结果。无强制倒计时。不是速度比拼。AI 阶段一在看见玩家选择前确定动物；阶段二只读取亮将和公开棋盘，在读取玩家落点前固定指令。需要单独断言无偷看。

### 行动合法性
- 使用轮初快照验证所有命令。保留现有上下左右、己方兽穴限制、鼠入水、虎跳河和水陆不能吃子的规则。
- 不能走入己方棋子轮初所在格，也不能预选按原吃子规则无法攻击的敌方轮初所在格。
- 河鼠阻断按轮初快照判定，即本轮鼠离开也不能临时使原本不合法的跳河变合法。
- 原地等待总是合法。选择后没有合适走法的动物仍可等待。

### 结算边界（程序实现依据）
每方只移动一枚棋子，按棋子终点同时结算；不按动画播放顺序结算。

| 场景 | 结果 |
|---|---|
| 双方终点不同，互不交换起点 | 各自移动；到达敌方未移动棋子的格子时按普通吃子规则吃子 |
| 追击对手原位置，对手同时离开 | 追击者进入空格，攻击扑空；无追踪命中 |
| 双方进入轮初同一空格 | 在该格碰面，按等级决定胜方；鼠与象相遇鼠胜；败方退场 |
| 同级双方进入同一空格 | 相互挡住，两者回到各自起点，不吃子 |
| 双方互换起点 | 在途中相遇；同级相互挡住留在起点。沿用当前合法性后，异级互换通常不合法，防御性实现仍按鼠象/等级处理 |
| 移动路线交叉但终点不同且非互换 | 互不影响；虎跳河只在落点发生战斗 |
| 双方都等待 | 棋盘保持原样，仍推进热点轮次并结算得分 |

先处理棋子生死与最终站位，再判断兽穴与清场；再结算热点得分与轮数上限。同一优先级双方同时达到胜利条件则平局；兽穴/清场优先于集星。同级同时碰撞不相杀，区别于单方攻击静止同级棋子，必须在教学和预览明确解释。

原地等待不是无敌防御：如果被更强动物攻击，照常被吃。局面预览提示潜在捕食者与碰撞风险，不替玩家泄漏对手实际命令。

## 推荐机制 B：轮换热点（必须）
目的：集中争夺、制造提前换边的取舍。

保留左右两个营地位置，但每轮只有一个营地产星；另一个熄灯。亮灯营地结算时由占领者获得一星，进入当轮即可得分，取消 V1 的己方回合开始结算，避免同时制下产生先后手歧义。

热点先左后右，按固定节奏轮换，双方始终看到当前和下一阶段位置与剩余轮数。轮换不是临时随机事件。热点分数不增加任何战斗能力。

| 测试参数 | 初值 | 调整原因 |
|---|---|---|
| 棋盘 | 沿用 5×7 | 先隔离行动机制变化，避免同时改太多变量 |
| 每方动物 | 象、虎、猫、鼠各一只 | 沿用已理解的角色 |
| 同时行动 | 每方每轮一只，可等待 | 保持计算量可控 |
| 热点持续 | 3轮后换边 | 给争夺时间，同时迫使重新调度 |
| 热点收益 | 每轮结算占领者+1星 | 清楚、即时的奖励 |
| 集星胜利 | 5星 | 暂沿用原版便于比较，不宣称已经平衡 |
| 对局上限 | 24轮 | 结算后若无人获胜，星多者赢，同分平局 |
| 体验目标 | 约3—5分钟 | 待真人实测；无强制计时 |

## 可验证的博弈例子
1. 追还是堵：虎与敌方猫相邻，猫处于虎可吃范围；猫既能原地，也能向营地走。虎进猫原格可以吃原地猫，但会扑空逃走的猫；虎抢猫的潜在下一格则可拦截走来的猫，但会放过原地猫。必须用实际合法局面验证，不用叙事代替实现。
2. 抢还是绕：双方亮出象与鼠。象知道鼠有机会抢它想占的位置，但鼠也可能走向营地拿分。象的克制关系变成对落点的限制，而不只是当前相邻格能否吃。
3. 再赚还是先走：热点即将换边，当前位置可以继续赚星；提前移动可能抢到下一处，但会让出当前收益。信息公开，取舍可解释。

三者分别对应预测落点、利用克制施压、跨轮资源取舍。实际能否稳定出现仍需试玩验证。

## 核心循环
- 决策：读棋盘与热点 → 选动物并亮将 → 预测走向、秘密下令 → 同时揭晓 → 获得位置/吃子/星星反馈。
- 单局：试探习惯 → 争夺热点与换边 → 用克制关系诱敌 → 集星或偷家 → 看关键碰撞回放。
- 局外：复看一次成功/失败预判 → 再来一局尝试另一种选择。暂不设计养成与每日任务。

## 画面与反馈
- 保留休闲森林棋盘；所选动物竖起旗子，公开强调谁要行动。
- 目的地只有自己可见的虚线箭头；确认后显示“等对手选好”。
- 双方箭头一起亮，播放移动和结果；用“扑空啦”“正好堵到你”“互相挡住”解释。
- 营地灯和剩余轮数必须始终位于棋盘附近，手机不依赖侧栏。
- 不需要新角色立绘，优先完成棋盘标识、箭头、碰撞和得星反馈。

## 第一轮原型范围与阶段验收
- 必须：秘密选动物、同时亮将、秘密落点/原地、确认与同时结算；轮换热点；克制与碰撞说明；不偷看的AI；可回看双方指令。
- 重要：固定教学局面，让玩家体验追空、截击、换边；调试模式可比较同一轮其他选择。
- 以后：一次性冲刺、动物主动技能、行动疲劳、装备、卡牌、隐藏棋子。当前全部不加。
- M0：用固定命令测试碰撞、追空、水陆、虎跳、双方同时达成胜利，且输入提交先后不改变结果。
- M1：玩家能完整完成亮将→暗走→揭晓→热点得分→结束→再来一局；手机可操作且AI无偷看。
- M2：与V1交替试玩，记录是否出现可描述的预判和设局；确认方向后才迁移Cocos。

## 验收问题与失败条件
- 玩家能否说明猜测对手落点的依据，而不是只说“运气好”？
- 是否主动用过原地等待、拦截潜在落点或提前换边？
- 相同亮将局面是否有多个合理选择，还是始终存在唯一安全动作？
- 揭晓后是否能清楚理解为什么扑空/被吃？
- 若多数反馈为纯猜拳，先调整可见信息与局面收益，不能继续叠随机性。
- 若两阶段操作被认为繁琐，可实验合并为暗选完整指令；需重新评估未知范围扩大是否损害休闲体验。
- 第一轮重点验证“预判对方”的新体验；本提案尚未经真人平衡与乐趣验证。
