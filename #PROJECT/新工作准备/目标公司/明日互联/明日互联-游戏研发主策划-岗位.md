## 二、关键词解读

### 「回合制 MMO」是什么

回合制 MMO 的核心不是"回合"这个操作形式，而是围绕**长期养成 + 社交关系 + 经济系统**的一套生态：

```
回合制 MMO = 角色养成 + 装备系统 + 宠物/伙伴 + 社交(帮派/结婚/师徒) + 经济(交易/摆摊) + 活动运营
```

- **养成**：等级、技能、装备、宠物、法宝等多线养成
- **装备系统**：JD 特别点名的模块——打造/强化/洗炼/镶嵌/套装/鉴定
- **社交**：回合制 MMO 的灵魂是"聊天挂机 + 组队 + 帮派"
- **经济**：自由交易、摆摊、拍卖行是回合制 MMO 的留存命脉

### 为什么 JD 点名「装备系统设计」

装备系统是回合制 MMO 的**核心付费点 + 核心长线目标**，通常包含：

| 模块 | 含义 | 类比 |
|---|---|---|
| 打造/制造 | 玩家自己造装备 | 梦幻西游打造 |
| 强化 | 等级提升，失败惩罚 | 强化+12 |
| 洗炼/重铸 | 属性随机刷新 | 梦幻装备鉴定 |
| 镶嵌 | 宝石系统 | 问道法宝 |
| 套装 | 多件套效果 | 梦幻特技/套装 |

### 「3ds MAX」「EXCEL」的含义

- **3ds MAX**：说明该团队美术/策划可能需要会看模型、摆场景、调资源——小团队主策往往要多面手
- **EXCEL**：策划基本功——配置表、数值表、掉落表，回合制 MMO 的数值策划重度依赖 Excel

## 四、核心知识点（按优先级）

### 1. 回合制 MMO 的核心系统

**经济系统（回合制 MMO 的命脉）**：
- 产出端：任务、活动、副本、挖宝
- 消耗端：强化、洗炼、升级技能、修理装备
- 交易端：摆摊、拍卖行、自由交易
- 核心：控制**通货膨胀**，让货币和道具保值

**装备系统（JD 点名模块）**：
- 打造：材料 + 运气 → 白/绿/蓝/紫/橙品质
- 强化：等级提升，失败风险（掉级/碎装）
- 洗炼：属性随机刷新，追求极品
- 镶嵌：宝石孔位 + 宝石等级
- 套装：集齐多件触发套装效果

**宠物/伙伴系统**：
- 捕捉、洗资质、打书、进阶、合宠
- 回合制 MMO 的另一大付费点和收集驱动

### 2. 主策划 vs 系统策划的差异

| 维度 | 系统策划 | 主策划 |
|---|---|---|
| 关注点 | 单个系统设计 | 项目整体方向 + 数据 |
| 产出 | 系统方案 | 立项方案 + 里程碑规划 |
| 协作 | 与程序美术对接 | 统筹程序/美术/策划全部 |
| 责任 | 系统上线效果 | 项目成败 + 最终品质 |

### 3. 立项方法论（主策划必备）

- **市场判断**：为什么做这个品类？对标谁？差异化是什么？
- **立项一页纸**：核心玩法一句话 + 目标用户 + 商业化模型 + 里程碑
- **数据负责**：留存、付费、DAU 等核心指标的目标值和监控

### 4. 竞品拆解清单

| 产品 | 品类 | 核心系统 |
|---|---|---|
| 梦幻西游 | 回合制 MMO | 经济 + 装备 + 宠物 |
| 大话西游 | 回合制 MMO | 自由交易 + 社交 |

## 五、面试高频 Q&A

### Q1：你怎么从 0 到 1 立项一款回合制 MMO？
> 四步走：
> 1. **市场**：为什么现在还做回合制 MMO？（存量用户 + 情怀 + 差异化）
> 2. **差异化**：对比梦幻/问道，我们的创新点在哪？
> 3. **商业化**：经济系统 + 装备系统怎么设计付费点
> 4. **里程碑**：Demo → 首测 → 公测的节奏和验证指标

### Q2：回合制 MMO 的经济系统怎么设计，防止通胀？
> 核心是**产出与消耗的动态平衡**：
> 1. 产出口控量（任务/活动产出有上限）
> 2. 消耗口做强（强化/洗炼是主要货币回收）
> 3. 交易抽税（摆摊/拍卖收手续费）
> 4. 数据监控：货币存量、流通速度、物价指数

### Q3：装备系统从 0 到 1 怎么搭？
> 五个核心决策：
> 1. 装备产出（掉落/打造/任务）
> 2. 成长线（强化/洗炼/镶嵌/套装）
> 3. 品质分层（白→橙，驱动追求）
> 4. 随机性（鉴定/洗炼的运气成分）
> 5. 保值与回收（装备交易、分解、继承）

### Q4：你怎么管理策划团队？
> 用你的真实经验：奕兆执行主策，审核团队文档、跨部门协调。
> 强调：定目标 → 拆任务 → 盯进度 → 培养人（帮成员提升）。

### Q5：主策划对数据负责，具体怎么做？
> 1. 立项时定核心指标目标值（留存/付费/DAU）
> 2. 研发阶段用埋点 + 测试数据验证
> 3. 上线后看数据迭代，用数据驱动优化
