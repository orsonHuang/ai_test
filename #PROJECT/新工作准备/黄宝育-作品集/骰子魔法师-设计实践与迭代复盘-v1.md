# 《骰子魔法师》：从随机组合到战斗构筑的设计实践

黄宝育｜系统与玩法策划作品集｜第二部分·第一版｜2026.09.26

**项目定位：** 通过选骰、重摇与骰面养成应对怪物意图的骰子构筑 Roguelike。

**项目身份：** 个人独立项目，原名《骰子怪兽》，对应工程 `DiceMonsterTT`。结合 AI 完成玩法设计、文档、Lua 实现、配置和调参工具，当前为持续迭代中的 Demo。

**技术环境：** TapTap Maker / UrhoX / Lua。主线包含三层、每层八行的路线地图，以及战斗、奖励、替换、商店、休息和事件。

**本章依据：** 截至 2026.09.26 的项目代码、配置、设计决策文档及开发记录。规则推演不等于玩家测试；本章未重新运行游戏，也不以本地实现或既有回归记录代表全流程平衡完成。

## 1. 从《小丑牌》的分析转向自己的设计问题

上一章讨论了构筑如何改变玩家对随机结果的评价。《骰子魔法师》要解决的具体问题是：**让玩家在一次投掷后，有理由比较多种选骰方案，并通过后续养成改变这些方案的价值。**

项目采用骰子作为核心载体。每回合投掷五颗骰子，玩家可以消耗次数重摇指定骰子，再选择三颗组成牌型攻击。局内成长则通过替换骰子、修改单个骰面、附魔和获得能力实现。

与分数达标型玩法相比，这个项目加入了生命损耗和怪物意图。玩家的目标除了输出，还包括保留生命、规避危险行动、为后续回合准备。这要求成长系统与敌人设计共同参与决策。

本章重点展示三个设计问题：

1. 怎样让骰子替换超出“选择平均点数更高的骰子”？
2. 怎样让不同牌型改变操作，而不只是附加不同增伤？
3. 怎样让玩家理解选择的后果，并保证预览与执行一致？

这些是对当前项目的设计复盘，不代表所有机制都在《小丑牌》分析之后才产生。

## 2. 当前核心循环与完成范围

### 2.1 每回合：读取意图，再处理随机结果

```text
查看怪物意图 → 投掷五骰 → 比较牌型与后果
                         ↓
              直接选三 / 重摇选中骰子
                         ↓
              查看伤害与生命变化预览
                         ↓
              确认出牌 → 结算 → 怪物行动
```

基础每回合有两次主动重摇，能力可以增加次数。重摇作用于选中的骰子，空选不扣次数。必须恰好选三颗才能出牌，牌型按三条、顺子、对子、散牌的优先级判定。

固定五选三，一次投掷有十种按骰子身份区分的组合。同点骰带有不同附魔时，选择仍可能不同。十种是组合数量，不等于每回合都有十种有价值的方案；实际有效选择需要用战斗情境检验。

### 2.2 一局：战斗结果影响下一次构筑

```text
选择路线 → 战斗 / 事件 / 商店 / 休息
                 ↓
      获取或消耗金币、生命与构筑机会
                 ↓
         替换骰子 / 改面 / 附魔 / 获得能力
                 ↓
          在下一场战斗中检验改造结果
```

骰池保持五颗，新骰需要与已有骰子比较并替换，也可以放弃。战斗奖励中的金币需要领取，其他奖励按节点配置生成；当前奖励生成代码中，掉落骰子已自带附魔。初始骰与商店基础槽不因此自动获得附魔。

### 2.3 实现状态

| 范围 | 当前证据与边界 |
| --- | --- |
| 核心主线 | 地图、战斗、奖励、商店、休息、事件和三层流程已有实现 |
| 骰子构筑 | 正常可获得骰子统一六面，支持点值构型、单面修改与附魔 |
| 战斗内容 | 当前配置有 34 只怪物，包含条件攻击、护盾、毒、蓄力与适应机制 |
| 新构筑能力 | 接力阶梯、辅骰战术、败中求胜已接入本地奖励与战斗，尚待长局与实机验证 |
| 测试工具 | 有本地规则回归、怪物试炼入口及可视化调参工具 |
| 尚未完成 | 全流程数值平衡、持久化存档、局外技能树与装备、无尽模式、音效及发布验收 |

项目仍在验证“现有机制是否形成稳定、有区分度的玩法”。内容数量和规则回归通过，不能替代这一验证。

## 3. 关键迭代一：统一六面载体，把成长放进点值分布

### 3.1 旧方向的问题

早期设计包含 D4、D6、D8、D10、D12 等骰型。更多面数往往带来更高平均点数，容易让替换决策偏向直接比较数值大小。不同面数也增加了表现与规则说明的成本。

2026.09.22 的已确认设计决定，将正常流程的骰子收束为 D6。当前差异来自六个面分别写什么数字，以及附魔和能力如何配合。

这次调整的目标是把问题从“要不要换更大的骰子”，转向“这组概率分布是否适合我的构筑”。这里描述的是设计动机，尚无玩家数据证明所有替换都已形成有效取舍。

### 3.2 相同平均点数，可以产生完全不同的策略条件

当前配置中的三个例子：

| 构型 | 六面点值 | 单颗均值 | 对组合的影响 |
| --- | --- | ---: | --- |
| 均衡 D6 | 1、2、3、4、5、6 | 3.5 | 覆盖全部基础点值，保留多种组合可能 |
| 稳健 D6 | 2、3、3、4、4、5 | 3.5 | 点值集中，3与4出现概率提高 |
| 爆发 D6 | 1、1、1、6、6、6 | 3.5 | 结果集中为1与6，完全失去中间点值 |

为了检验分布差异，本次对五颗同构型骰子的初次投掷进行了穷举。假设每颗骰子的六个面等概率、投掷相互独立，不使用重摇、附魔或能力，只判断五颗中能否选出三颗同点：

| 五颗均采用的构型 | 可选出三条的面槽结果数 | 全部结果数 | 概率 |
| --- | ---: | ---: | ---: |
| 均衡 | 1,656 | 7,776 | 21.30% |
| 稳健 | 3,816 | 7,776 | 49.07% |
| 爆发 | 7,776 | 7,776 | 100.00% |

这是当前配置的数学推演，不是实际掉落率、成型率或通关率。重复数字的各个面仍分别计数，因而保留其概率权重。

**设计结论：** 单颗均值不足以评价骰子的价值。相同均值下，重复点数集中程度会显著改变牌型可获得性；与此同时，点值覆盖收窄，也会失去部分顺子和调整空间。

### 3.3 暴露的问题：稳定性可能过度消除决策

五颗爆发骰只有1和6两个可能数字，根据抽屉原理，必然至少有三颗同点。因此，这套极端骰池无需重摇即可组成三条。

这不直接证明它最强：组成五颗有获取成本，低点三条伤害、附魔、能力及怪物条件也会改变结果。但它确实削弱了“是否为三条继续重摇”的不确定性，需要防止构筑成型后回合决策退化。

项目的无尽目标设计已提出普通骰至少包含三种不同点值，将二值特殊骰后置。**该约束尚未全面实施，当前主线仍保留上述爆发构型。** 而且“至少三种点值”只是结构约束，不能单独保证平衡，仍需检查各点权重、改面叠加与最终牌型概率。

这个问题说明，构筑成长不能只看“能否让玩家更稳定”，还要检查稳定以后是否仍有值得比较的选择。

## 4. 关键迭代二：单面修改保留概率，而不是锁死整颗骰子

项目早期存在“固定数字”的实现与描述不一致问题：整颗骰子固定，会绕过后续投掷，使原来的点值分布失去意义。现有实现改为选择一颗骰子中的一个面槽进行修改。

例如，均衡骰的一个面从1改为4：

```text
修改前：1、2、3、4、5、6
修改后：4、2、3、4、5、6
```

得到4的概率由1/6变为2/6，同时失去了1。玩家提高了某种组合的稳定性，也支付了点值覆盖缩小的代价。

**D6指六个面槽，不代表点值上限永远为6。** 当前主线的改面奖励代码支持1～7，因此可以出现带7点面的六面骰；初始构型表仍使用1～6。旧文档中部分1～6的限制描述尚未同步，本章以当前代码为准。

这一设计给后续验证留下两个问题：

- 高点改面是否因为同时提高输出与极值收益，压过其他用途？
- 连续改面是否仍可能把普通骰变成单值或二值骰，绕过构型约束？

这些边界应在扩充奖励之前确认，否则内容越多，概率分布越难控制。

## 5. 关键迭代三：让牌型决定行动方式

只有“对子增伤、顺子增伤、三条增伤”时，不同路线可能只是奖励不同牌型。2026.09.26 接入本地版本的三条新能力，进一步尝试改变玩家的选择依据。

以下为一级效果，三条能力均支持同名升级至三级；不是所有旧能力都已采用同一升级规则。

| 能力 | 一级关键规则 | 希望形成的选择 | 已设置的边界 |
| --- | --- | --- | --- |
| 接力阶梯 | 连续两次出顺子，且最小点值不同，当前出牌增伤20% | 保留稳定区间，还是调整成另一段顺子获取收益 | 第一次无加成，同区间不触发，非顺子中断；不会无限累计 |
| 辅骰战术 | 对子之外的辅骰为1～2时治疗2，3～4时临时盾3，5～7时基础伤害加3 | 按血量、敌方意图和斩杀需求选择第三颗骰子 | 三条不触发；治疗不溢出；盾在紧接的敌方行动后到期 |
| 败中求胜 | 消耗主动重摇后仍出非三条可积累准备；三条消耗准备，每层基础伤害加3 | 继续追求三条，还是用其他牌型止损并保留后续机会 | 最多两层，连续第三次非三条清空；免费附魔重投不计主动消耗 |

### 5.1 顺子：让相邻两回合建立联系

接力阶梯中，123接234能够触发，234继续接234不会触发。它为骰池提出了新的要求：除了提高单一区间的成功率，还需要保留跨区间的衔接能力。

但能力不应该强迫玩家忽视敌人。危险回合放弃接力、改用带盾的对子，可以是合理选择。后续要验证玩家是否能理解“连续但不同”的条件，以及收益是否足以补偿更换区间的成本。

### 5.2 对子：让第三颗骰子成为主动决策

对子通常由两颗同点骰决定，第三颗可能只剩补点数作用。辅骰战术把这个位置改成治疗、防御或进攻的选择，使同一个对子能够承担不同任务。

代价是增加一组点值区间规则。界面需要展示当前辅骰产生的具体效果，避免玩家必须反复记忆或试算。即使规则已实现，也需要验证玩家是否真的根据局面换辅骰。

### 5.3 三条：提供有边界的失败积累

败中求胜尝试给追求三条失败的回合留下价值，但并未把失败变成无限储蓄。准备有上限和失效条件，下一次三条会消费已有准备。

这里的风险是诱导玩家故意拖延。需要关注能力是否让“先做低效操作”比直接结束战斗更有利，特别是与治疗、低威胁怪物和其他成长能力结合之后。规则回归可以检查层数是否正确，却无法回答拖延是否成为主流策略。

## 6. 用真实配置推演一次战斗选择

为了展示牌型与意图如何共同作用，取当前配置中的蝙蝠群“群袭”意图：基础攻击8；若玩家所选三骰的原始点数和不超过10，则攻击降为3。

设玩家投出 **2、2、3、5、6**，已获得一级辅骰战术，没有其他附魔、能力、护盾、中毒或怪物减伤。怪物当前28生命，以下方案均不能直接击杀。该情境为依据代码构造的规则示例，不是实际试玩记录。

当前基础伤害为：三条20、顺子10、对子5、散牌0。没有其他修正时，伤害为牌型基础值加点数和，再加入能力的基础伤害加值。

| 选骰 | 牌型 / 点数和 | 对怪伤害 | 能力效果 | 敌方攻击 | 玩家损失生命 |
| --- | --- | ---: | --- | ---: | ---: |
| 2、2、5 | 对子 / 9 | 17 | 高辅骰基础伤害+3 | 3 | 3 |
| 2、2、3 | 对子 / 7 | 12 | 临时盾3 | 3 | 0 |
| 3、5、6 | 散牌 / 14 | 14 | 无 | 8 | 8 |

在这一局面中，“取最大的三颗”并不是最优规则；攻击型对子以更低点数和获得更高伤害，还能降低反击。带盾对子则牺牲5点伤害，换取本回合不损血。

究竟选17伤害还是12伤害，需要继续考虑后续怪物行动、当前血量与下一回合击杀机会。单回合不损血不等于整场损耗最低：拖长战斗也会暴露于更多行动。

**设计判断：** 这个示例证明当前规则可以产生进攻与保命的差异，但不能证明此类选择在实际局中出现得足够频繁。后续应该记录“可行替代方案”和玩家的选择理由，而不只比较平均伤害。

## 7. 怪物意图怎样改变骰子价值

除了低点减伤，当前怪物配置还包含下列约束：

| 意图机制 | 当前实例 | 对玩家选择的影响 |
| --- | --- | --- |
| 主动重摇追击 | 绿皮哥布林每次主动重摇增加2伤害，最多加4 | 重摇除了次数成本，还可能带来生命成本 |
| 达到伤害阈值降伤 | 森林狼重击12，实际扣除至少18HP后降为4 | 输出同时承担防御作用，可能值得主动寻找高伤害组合 |
| 护盾 | 骷髅兵获得6盾，作用于下一次出牌 | 改变相邻回合的有效伤害与击杀预期 |
| 适应护甲 | 守卫骑士建立适应状态，重复牌型受减伤 | 单一牌型稳定性与临时换型之间产生取舍 |
| 多段攻击 | 蝙蝠群两段、每段2伤害 | 按次格挡和数值护盾产生不同价值 |

设计上，敌人应该向同一套骰池提出不同问题，而不仅是逐层增加生命和攻击。

同时，条件必须能够被理解和预测。项目将意图类型、条件和数值存为结构化字段，中文描述用于呈现，不由文本决定行为。预览和执行共用意图规则，减少“文案写了但实际没有生效”的风险。

目前全阵容已有本地实现，项目记录首层已验收，后两层及完整流程仍需试玩。不能据此宣称敌人已经形成成熟的难度曲线。

## 8. 信息反馈与实现：让玩家相信预览

### 8.1 预览要帮助比较后果

当前选满三骰后，玩家可以看到伤害及已知条件下的回合末生命预测。生命预测涉及治疗、临时盾、怪物反击和毒等因素；玩家击杀怪物时，也要正确处理不再反击的路径。

提供预览的设计目的是让精力集中于“选哪种后果”，而不是反复计算基础加法。但它也有代价：如果界面只强调最大伤害，玩家可能忽略防守与后续收益。因此，伤害、保护效果和意图条件需要一起呈现。

### 8.2 伤害阶段固定，避免获取顺序影响结果

当前伤害计算将基础固定加值、牌型与全局增伤、条件倍率等按阶段处理，再完成取整。预览与出牌调用同一计算函数，结算步骤也由这次计算产生。

这一选择与《小丑牌》中部分顺序操作不同。本项目没有把能力获取顺序设计成玩家可操作的策略，因而不应该让先拿后拿形成隐藏收益差异。对没有策略意义的顺序影响进行消除，可以降低解释成本。

### 8.3 预览与确认分开处理

接力区间、三条准备层数等状态，会被反复选骰触发检查。如果预览阶段就修改状态，玩家可能通过点击获得收益，或者看到与确认结果不同的数值。

当前构筑规则将预览结果与下一状态分别返回，确认出牌时再提交状态。项目测试包含预览不改状态、重复确认、能力升级封顶、多段护盾等场景。

这类边界并不直接创造玩法乐趣，但它决定规则是否可信，也是把设计落成可用原型的重要部分。

## 9. 独立开发中的工具与协作方法

项目采用 AI 辅助实现。个人工作的重点包含玩法目标、规则取舍、内容配置与体验验收，并通过文档和本地测试约束实现。代码由 AI 辅助生成和迭代，不以工具生成的代码量作为个人能力证明。

### 9.1 可视化调参

- **战斗布局工具：** 支持控件位置与尺寸调整、状态预览和配置导出，减少每次修改都先进入完整构建流程的成本。
- **怪物编辑器：** 从项目配置导入怪物，编辑数值和意图并查看界面示意，再将调整写回配置。
- **怪物意图试炼：** 提供独立单场入口，用于检查指定怪物，减少必须从整局开头推进才能观察的成本。

这些工具说明已有迭代手段，但没有记录工时对照，因此不声称效率提升了某个百分比。工具预览也不能代替真实引擎的触控、动画和资源加载验收。

### 9.2 文档与实现仍需要持续对齐

项目采用分析稿记录设计理由、设计稿记录当前规则，配置表和代码描述实际运行。复盘时发现部分历史描述尚未同步，例如改面值域、能力数量以及掉落骰附魔规则。

## 10. 下一阶段验证目标

下一步应优先判断现有路线是否改变玩家行为，再决定扩充内容。

| 验证问题 | 建议记录 | 能说明什么 / 不能说明什么 |
| --- | --- | --- |
| 构筑是否有形成机会 | 能力出现、取得、升级和完成搭配的节点 | 区分获取困难与机制本身弱；不以手工配装成功代表正常成型 |
| 构型替换是否有取舍 | 替换前后六面分布、能力、选择及放弃原因 | 检查是否只追求均值或稀有度 |
| 意图是否改变操作 | 面对不同意图的重摇次数、牌型和辅骰分布 | 需要控制骰池、能力和血量，避免把状态差异当作设计效果 |
| 各路线是否能独立发挥 | 相近进度下的伤害、损血、回合数与失败原因 | 小样本用于定位问题，不能直接宣称路线平衡 |
| 新能力是否鼓励拖延 | 已有击杀机会却延迟的次数与理由 | 检查准备、治疗和成长是否形成刷收益行为 |
| 反馈是否可理解 | 玩家能否解释伤害、减伤与重摇代价 | 同时检查规则理解和移动端信息可读性 |

最低体验验收目标是：玩家能独立完成投掷、重摇、选三、替换或改面，并能在一个具体意图下解释为何放弃另一种可行选择。项目既有的自动化回归负责规则正确性，后续试玩负责决策质量与体验。

## 11. 阶段性复盘

这个 Demo 已经把骰子组合、概率分布调整、构筑能力和怪物压力连接成可运行的主线。最有价值的设计进展，是让“换骰子”和“选三颗”开始受到当前构筑与战斗情境共同影响。

现阶段最大的风险也在同一处：当概率被改造得过于稳定，或者某类能力只需要重复操作就能持续获利，构筑会削弱原本想保留的决策。全爆发骰的三条必出，是一个可以由配置直接识别的例子。

因此，下一阶段的目标是以规则推演、受控战斗和真实试玩逐步验证：玩家是否需要理解并使用这些差异，系统是否为不同选择提供了合理收益与代价。

## 附录A：概率推演的复现方式

下列脚本用于本文的配置推演，独立于游戏随机数实现，不模拟重摇、获取过程或完整战斗。本次已执行并核对表中结果。

```python
from itertools import product
from collections import Counter

configurations = {
    "均衡": [1, 2, 3, 4, 5, 6],
    "稳健": [2, 3, 3, 4, 4, 5],
    "爆发": [1, 1, 1, 6, 6, 6],
}
for name, faces in configurations.items():
    hits = sum(
        max(Counter(values).values()) >= 3
        for values in product(faces, repeat=5)
    )
    print(name, hits, 6 ** 5, hits / (6 ** 5))
```
