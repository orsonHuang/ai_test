# 三角洲行动 · 匹配流程全拆解

> 整理目的：深入理解大型竞技射击游戏的匹配系统从"点击开始"到"进入战局"的完整流程
> 整理时间：2026-08-03
> 参考来源：三角洲官方机制说明 + 玩家深度测试 + CSDN技术架构分析 + 知乎/B站玩家实测

---

## 一、匹配系统的整体架构

### 1.1 服务器架构

三角洲采用**分布式区域节点部署**：

```
国服节点分布：
├── 华东节点（上海/杭州）  ← 服务江浙沪
├── 华南节点（广州/深圳）  ← 服务广东/福建/海南
├── 华北节点（北京）       ← 服务北方
├── 西南节点（成都）       ← 服务西南
└── 华中节点（武汉）       ← 服务中部
```

**匹配服务器（Match Server）** 和 **游戏服务器（DS，Dedicated Server）** 是分离的：
- 匹配服务器：负责计算、配对、创建房间
- 游戏服务器（DS）：负责实际运行战局

### 1.2 技术栈

| 层级 | 技术 | 说明 |
|---|---|---|
| 渲染层 | UE5 | PC端高精度光照和物理破坏 |
| 逻辑层 | 自研底层 | 移动端/PC端复用同一套代码，服务器端统一校验 |
| 网络同步 | 混合模式 | 状态同步（低频数据）+ 帧同步（高频操作） |
| 匹配服务 | 自研 | 基于玩家四维数据的实时计算 |
| 反作弊 | 三层 | 动态加密 + AI行为检测 + 硬件指纹绑定 |

## 二、匹配流程：从点击到进入战局（12步）

### 流程图总览

```
玩家点击"开始匹配"
    ↓
[第1步] 客户端参数收集 → 发往匹配服务器
    ↓
[第2步] 匹配服务器接收 → 分配节点（就近接入）
    ↓
[第3步] 计算玩家"隐藏分"（四维数据加权）
    ↓
[第4步] 确定匹配池（模式 + 地图 + 段位门槛）
    ↓
[第5步] 匹配窗口开启 → 候选对手池筛选
    ↓
[第6步] 等待队列管理 → 窗口动态放宽
    ↓
[第7步] 组队玩家特殊处理（小队权重计算）
    ↓
[第8步] 最终配对 → 确认32人名单
    ↓
[第9步] 分配DS游戏服务器（负载均衡 + 就近分配）
    ↓
[第10步] DS创建房间 → 加载地图 → 分配出生点
    ↓
[第11步] 所有玩家连接DS → 网络同步校验
    ↓
[第12步] 对局开始
```

---

### 第1步：客户端参数收集

**触发**：玩家点击"开始匹配"

**客户端收集的数据**：

| 数据 | 来源 | 说明 |
|---|---|---|
| 账号ID | 登录态 | 唯一标识 |
| 当前段位 | 排位数据 | 青铜~传说 |
| 选择模式 | 玩家选择 | 烽火地带 / 全面战场 / 黑鹰坠落 |
| 选择地图 | 玩家选择 | 零号大坝 / 长弓溪谷 / 航天基地 等 |
| 是否组队 | 队伍状态 | 单人 / 双人 / 三人小队 |
| 队伍成员ID | 队伍数据 | 如果组队，附带队友ID |
| 客户端Ping | 网络检测 | 各节点延迟 |
| 设备类型 | 设备信息 | PC / 移动端 |
| 反作弊校验 | 安全模块 | 环境检测结果 |

**目的**：把玩家的基本信息打包，发给匹配服务器。

---

### 第2步：匹配服务器接收 → 分配节点

**触发**：匹配服务器收到请求

**执行逻辑**：

```
1. 读取客户端Ping数据 → 找到延迟最低的匹配节点
2. 如果该节点负载过高 → 分配次优节点
3. 将玩家加入该节点的匹配队列
```

**目的**：
- 就近接入，降低延迟
- 负载均衡，防止单节点过载
- 后续匹配都在同一节点内完成（避免跨节点通信开销）

---

### 第3步：计算"隐藏分"（四维数据加权）

**触发**：玩家进入匹配队列后

**核心公式（玩家实测反推，非官方公布）**：

```
隐藏分 = f(撤离率, 赚损比, KD, 段位) × 时间衰减
```

#### 3.1 四个输入维度

| 维度 | 计算方式 | 数据来源 | 权重（推测） |
|---|---|---|---|
| **撤离率** | 成功撤离局数 / 总局数 | 近期所有对局 | ⭐⭐⭐⭐⭐ 最高 |
| **赚损比** | 带出总价值 / 撤离失败局数 | 近期所有对局 | ⭐⭐⭐⭐ 很高 |
| **KD（战损比）** | 击杀数 / 死亡数 | 近期所有对局 | ⭐⭐⭐ 中等 |
| **段位** | 当前排位段位 | 排位系统 | ⭐⭐ 较低（S8后降低） |

> **重要发现**：玩家用6个60级大号+10多个小号测试300多局后发现——**匹配队友和对手主要看赚损比，排位段位影响很小，和KD、携带物资金额完全无关**。这与传统ELO系统差异很大。

#### 3.2 时间窗口

不是取所有历史数据，而是**近期数据**：
- 核心参考：**近10场** 的战斗表现
- 权重衰减：越近的场次权重越高

```
隐藏分 = Σ(第i场表现 × 衰减系数_i)
衰减系数 = 1.0, 0.9, 0.8, ..., 0.1（第10场）
```

#### 3.3 "战斗分"的定义

战斗分是综合评估玩家战斗表现的核心指标：

| 行为 | 加分 | 说明 |
|---|---|---|
| 击杀玩家 | 高 | 击败真人玩家得分高 |
| 击杀AI | 低 | 击败NPC得分低 |
| 成功撤离 | 高 | 活着出来是核心目标 |
| 带出高价值物资 | 高 | 带出越多越值钱 |
| 死亡/撤离失败 | 扣分 | 核心惩罚 |

#### 3.4 隐藏分的"缸"（玩家社区概念）

玩家社区提出了"缸"的概念——隐藏分被划分成不同的区间：

```
缸1：隐藏分 0-500    → 新手/低水平局（机器人多）
缸2：隐藏分 500-1000 → 普通局
缸3：隐藏分 1000-2000 → 中高水平局
缸4：隐藏分 2000+    → 高压局（全真人高手）
```

**目的**：
- 找到玩家的"真实实力"，而不是"表面段位"
- 让隐藏分相近的玩家匹配到一起
- 防止高隐藏分玩家在低段位炸鱼

---

### 第4步：确定匹配池

**触发**：隐藏分计算完成后

**匹配池的三层筛选**：

```
第一层：模式筛选
├── 烽火地带（生存撤离）
├── 全面战场（大规模攻防）
└── 黑鹰坠落（PVE战役）

第二层：地图筛选（玩家选择的地图）
├── 零号大坝
├── 长弓溪谷
├── 航天基地
└── ...（随赛季更新）

第三层：段位门槛
├── 正常玩家：段位差 ≤ 2段
├── 新手玩家（前N局）：新手保护池
└── 异常玩家（检测到外挂/脚本特征）：隔离池
```

**目的**：
- 保证模式正确（不能把烽火地带的玩家匹配到全面战场）
- 保证地图正确
- 保证段位基本公平

---

### 第5步：匹配窗口开启 → 候选对手池筛选

**触发**：匹配池确定后

**执行逻辑**：

```
1. 以当前玩家的隐藏分为中心
2. 设定初始搜索半径 = ±50分
3. 在匹配池内搜索隐藏分落在 [隐藏分-50, 隐藏分+50] 范围内的玩家
4. 形成候选对手池
```

**目的**：
- 初始严格匹配，保证公平性
- 如果候选池人数不足，后续逐步放宽

---

### 第6步：等待队列管理 → 窗口动态放宽

**触发**：候选池人数不足（32人房需要凑够32人）

**动态放宽策略**：

```
时间轴          | 隐藏分搜索范围 | 段位差限制 | 其他放宽
────────────────────────────────────────────────────
0-10秒          | ±50分          | ≤2段      | 无
10-20秒         | ±100分         | ≤3段      | 无
20-30秒         | ±200分         | ≤4段      | 放宽地图限制（相邻地图合并）
30-45秒         | ±400分         | 不限制     | 放宽模式限制
45-60秒         | 最大范围        | 不限制     | 放宽设备类型（PC+移动端混合）
60秒+           | 触发"补偿机制"  | -          | 机器人填充（仅低段位）
```

**关键机制**：窗口放宽不是瞬间发生的，而是**每5-10秒检查一次候选池人数，人数不够才放宽**。

**目的**：
- 匹配质量优先（先严格匹配）
- 匹配速度兜底（长时间等不到人时放宽）
- 让玩家感知到"正在努力匹配"，而不是"匹配失败"

---

### 第7步：组队玩家特殊处理

**触发**：候选池中有组队玩家

**小队隐藏分计算**：

```
不是简单取平均分，而是：
小队隐藏分 = MAX(队长分, 队员最高分) × 组队系数

组队系数：
- 2人小队：×1.05
- 3人小队：×1.10
```

**设计原因**：
- 组队玩家配合更默契 → 实际战斗力高于个人分
- 必须加权处理，否则组队碾压单排玩家
- 组队系数惩罚组队玩家，保护单排体验

**跨段位组队限制**：
- 组队成员段位差不能超过2个大段（防止高段位带低段位炸鱼）

**目的**：
- 保证组队公平性
- 防止"大号带小号"破坏匹配

---

### 第8步：最终配对 → 确认32人名单

**触发**：候选池人数 ≥ 32 人

**最终配对逻辑**：

```
1. 从候选池中选择隐藏分最接近的32人
2. 如果组队玩家，整队一起进入（不拆队）
3. 检查反作弊校验结果 → 标记的异常玩家移入隔离池
4. 确认最终32人名单
5. 生成对局ID
```

**特殊处理：异常玩家分流**

```
异常玩家类型          | 处理方式
─────────────────────────────────────
外挂检测命中          | 移入隔离池（养蛊局）
脚本/挂机检测         | 移入神人局
近期数据极端（如0撤离率100局）| 移入神人局
近期数据异常高（如100%撤离率+高KD）| 移入高压局
```

**"养蛊局"机制**：
- 将检测到外挂特征的玩家全部丢进同一个对局
- 外挂打外挂，互相伤害
- 保护正常玩家不被外挂污染体验

**"神人局"机制**：
- 将命中率极低、撤离率极低的玩家匹配到一起
- 这些人可能在挂机/脚本/故意送人头
- 不让他们影响正常玩家的匹配体验

**"高压局"机制**：
- 连续带出超高价值物资 → 进入全是高手的对局
- 隐藏分暴增后的"压力测试"
- 本质是验证你是真高手还是运气好

**目的**：
- 最终配对质量保证
- 异常玩家不影响正常玩家
- 形成"好玩家和好玩家玩，坏玩家和坏玩家玩"的分层

---

### 第9步：分配DS游戏服务器

**触发**：32人名单确认后

**DS分配逻辑**：

```
1. 计算32人的地理位置分布
2. 选择延迟最低的DS节点（对32人加权平均Ping最低）
3. 如果该DS负载已满 → 选择次优节点
4. 分配DS实例 → 返回DS IP:Port给所有客户端
```

**国服DS节点分布**：
- 华东（上海/杭州）：服务江浙沪
- 华南（广州/深圳）：服务广东/福建/海南
- 华北（北京）：服务北方
- 西南（成都）：服务西南
- 华中（武汉）：服务中部

**目的**：
- 选择对32人整体延迟最优的服务器
- 负载均衡，避免单DS过载
- 保证战局运行稳定

---

### 第10步：DS创建房间 → 加载地图 → 分配出生点

**触发**：DS收到房间创建指令

**DS执行逻辑**：

```
1. 创建房间实例 → 分配内存和计算资源
2. 加载指定地图（零号大坝 / 长弓溪谷 / 航天基地 等）
3. 初始化地图状态（资源点分布、AI位置、撤离点状态）
4. 分配出生点：
   - 读取32人的隐藏分
   - 隐藏分低的玩家 → 分配到边缘出生点（远离资源区）
   - 隐藏分中等的玩家 → 分配到中等位置
   - 隐藏分高的玩家 → 分配到靠近资源区的位置（更高风险）
   - 组队玩家 → 分配到相邻出生点
5. 初始化撤离点（固定撤离点 + 条件撤离点）
6. 房间状态设为"等待玩家连接"
```

**出生点分配策略**（推测，官方未公布具体规则）：

```
隐藏分区间    | 出生点类型      | 设计意图
──────────────────────────────────────────────
低（新手）    | 边缘区域        | 给新手安全发育空间
中等          | 中等区域        | 正常开局
高（高手）    | 靠近资源区      | 高风险高回报，鼓励高手打架
```

**目的**：
- 不是完全随机出生点，而是有策略分配
- 新手不会被直接丢到修罗场
- 高手有更多机会获得资源，但也面临更大风险

---

### 第11步：所有玩家连接DS → 网络同步校验

**触发**：DS返回IP:Port给客户端后

**连接流程**：

```
1. 客户端收到DS地址
2. 建立UDP连接（射击游戏用UDP，低延迟）
3. 发送握手包（包含账号ID + 对局ID + 反作弊Token）
4. DS校验：
   - 对局ID是否匹配
   - 反作弊Token是否有效
   - 账号是否在黑名单
5. 所有32人连接成功 → 进入加载倒计时
6. 如果有人超时未连接（30秒）→ 取消该玩家，重新匹配
```

**网络同步策略**（混合模式）：

| 数据类型 | 同步方式 | 频率 | 说明 |
|---|---|---|---|
| 角色位置/移动 | 状态同步 | 10-20Hz | 降低带宽 |
| 血量/护甲 | 状态同步 | 变化时同步 | 低频数据 |
| 开枪/换弹 | 帧同步 | 60Hz+ | 高频操作，必须精准 |
| 近战/处决 | 帧同步 | 60Hz+ | 需要精准判定 |
| 开门/互动 | 事件同步 | 触发时同步 | 一次性事件 |

**反作弊校验**（加载阶段）：
- 动态加密验证：关键数据实时轮换密钥
- 环境检测：检查客户端是否被篡改
- 硬件指纹验证：设备是否被标记

**目的**：
- 确保所有玩家连接正常
- 网络同步策略保证公平性
- 加载阶段就开始反作弊检测

---

### 第12步：对局开始

**触发**：所有32人连接成功 + 加载完成

**执行**：
```
1. 倒计时 5-3-1
2. 所有玩家出生在分配的出生点
3. 地图资源刷新
4. AI激活
5. 撤离点激活
6. 对局计时器开始
7. 埋点开始上报
```

**对局中的数据持续上报**：
- 击杀事件
- 死亡事件
- 物资拾取
- 撤离成功/失败
- 对局时长
- → 这些数据回流到匹配系统，更新隐藏分

## 三、特殊机制

### 3.1 补偿局（高爆局）

**触发条件**：玩家近期"亏损"过多
- 连续撤离失败
- 赚损比低于系统预期值
- 带出价值低于系统设定的"期望收获价值"

**触发后的处理**：
- 将玩家降入"高爆率"匹配池
- 该池的地图资源刷新率提高（更容易刷出高价值物品）
- 匹配到的对手隐藏分偏低
- 本质是"补偿机制"——让你赢回来，防止流失

**玩家社区的利用**（"焚诀"）：
- 玩家发现可以通过故意"自雷"（快速死亡）来压低隐藏分
- 压低后系统会触发补偿局 → 进入高爆局 → 刷高价值物资
- 这说明了隐藏分系统的**可被反向利用**

### 3.2 跨平台匹配策略

```
平台组合              | 匹配规则
─────────────────────────────────────
移动端 vs 移动端       | 正常匹配
PC端 vs PC端           | 正常匹配
移动端组队PC端          | 进入PC匹配池（按PC标准匹配）
PC端组队移动端          | 进入PC匹配池（按PC标准匹配）
```

**原则**：只要队伍里有PC玩家，整队进PC匹配池。移动端纯队才进移动端池。这是为了避免键鼠 vs 触屏的不公平。

### 3.3 新赛季重置机制

```
新赛季开始 →
1. 所有玩家段位下降1-2个大段（软重置）
2. 隐藏分不重置（保留真实实力评估）
3. 新赛季前N局隐藏分变化幅度加大（K值提高，快速重新定位）
```

## 四、与传统ELO/MMR的对比

| 维度 | 传统ELO | 三角洲行动 |
|---|---|---|
| 核心指标 | 胜负 | 撤离率 + 赚损比 + KD + 段位 |
| 数据时间窗口 | 全历史 | 近10场（时间衰减） |
| 匹配池 | 单一维度（分数） | 模式 + 地图 + 段位 + 隐藏分 |
| 异常处理 | 无 | 养蛊局 / 神人局 / 高压局 |
| 组队处理 | 简单平均 | 取最高分 + 组队系数惩罚 |
| 补偿机制 | 无 | 高爆局（补偿局） |
| 机器人 | 固定比例 | 动态概率（段位 + 隐藏分联动） |

---

## 五、对面试的参考价值

### 面试可以讲的点

1. **"三角洲的匹配系统不是传统ELO，而是四维加权"**：撤离率、赚损比、KD、段位，四个维度加权计算隐藏分，且权重不同（撤离率>赚损比>KD>段位）

2. **"时间窗口设计很关键"**：近10场数据 + 时间衰减，保证隐藏分反映的是"当前水平"而不是"历史水平"

3. **"异常玩家分层处理是亮点"**：养蛊局、神人局、高压局三层隔离，避免正常玩家被污染

4. **"组队系数惩罚"**：取最高分 + ×1.05~1.10，保证组队公平

5. **"补偿局机制是留存抓手"**：连续亏损触发高爆局，防止流失

6. **"匹配窗口动态放宽是经典方案"**：先严格匹配，再逐步放宽，平衡质量和速度

7. **"DS分配要就近+负载均衡"**：不是选延迟最低的单个玩家，而是对32人加权平均最优

### 如果面试官问"你怎么评价三角洲的匹配系统"

> "三角洲的匹配系统比传统ELO更复杂，也更贴合它的游戏特性。传统ELO只看胜负，但三角洲是搜打撤——撤离率比KD更能反映真实水平。它的隐藏分用了四维加权+近10场时间衰减，这个设计很聪明，既能反映当前水平，又不会被历史数据拖累。另外它的异常玩家分层处理——养蛊局、神人局、高压局——是匹配系统里比较少见的精细化运营，能有效保护正常玩家的体验。但也有一些问题，比如隐藏分可以被玩家'焚诀'反向利用——故意自雷压低分数来触发高爆补偿局，说明系统的透明度不够，或者补偿机制的触发条件太容易被预测。"
