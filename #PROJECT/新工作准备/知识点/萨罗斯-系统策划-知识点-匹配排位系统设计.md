# 匹配系统 · 核心知识

> 整理目的：萨罗斯 系统策划（匹配排位方向）面试准备

---

## 一、匹配算法

### 1.1 ELO 评分系统

**原理**：
- 每个玩家有一个分数 R
- 双方分差 → 预测胜率 → 赛后调整分数
- 公式：`R' = R + K × (S - E)`
  - R'：赛后分数
  - R：赛前分数
  - K：分数变化幅度（新手大、老手小）
  - S：实际结果（胜=1，平=0.5，负=0）
  - E：期望胜率，由分差计算

**期望胜率计算**：
- `E_A = 1 / (1 + 10^((R_B - R_A) / 400))`
- 分差 400 → 胜率约 90%
- 分差 200 → 胜率约 76%
- 分差 0 → 胜率 50%

**K 值选择**：
- 新玩家：K=32（快速定位真实水平）
- 中段位：K=24
- 高段位：K=16（稳定，不会大起大落）
- 职业赛：K=10

**ELO 的优缺点**：
- ✅ 简单、可解释、计算成本低
- ❌ 只考虑结果，不考虑过程（碾压赢 vs 险胜一样）
- ❌ 多人游戏中不适用（只适合 1v1）

### 1.2 MMR（Matchmaking Rating）

**核心概念**：
- **隐藏分**：用于匹配计算，玩家不可见
- **显示段位**：用于展示，玩家可见
- 两个分数的分离是故意的——让玩家追逐段位目标，同时匹配系统独立运作

**MMR 的不确定性**：
- 新账号：MMR 不确定性高 → 匹配范围宽 → 快速定位
- 老账号：MMR 不确定性低 → 匹配范围窄 → 精确匹配
- 回归玩家：重新增加不确定性

**常见 MMR 问题**：
| 现象 | 原因 | 解决方案 |
|---|---|---|
| 匹配段位差太多 | MMR 和显示段位差距大 | 加速段位追赶（连胜跳段） |
| 新号定级太高 | 初始 MMR 过高 | 增加定级赛局数 |
| 炸鱼 | 高 MMR 在低段位 | 表现分加速跳段 + 检测异常 KDA |

### 1.3 TrueSkill

**背景**：微软研究院，用于 Xbox Live 多人游戏匹配

**核心改进**（相比 ELO）：
- 引入 **技能不确定性**：`N(μ, σ²)`，μ 是技能均值，σ 是技能方差
- 新玩家 σ 大 → 分数波动大
- 老玩家 σ 小 → 分数稳定
- 支持**多人对战**（N v N 团队匹配）
- 支持**多人混战**（free-for-all）

**匹配原则**：
- 不是找分数最近的人，而是找"最有可能公平"的对手
- 使用贝叶斯推断更新技能分布

### 1.4 Glicko / Glicko-2

**改进**（相比 ELO）：
- 加入 **评分偏差（RD）**：RD 大 = 不准确，RD 小 = 准确
- 长时间不玩 → RD 增大 → 匹配放宽
- 连续比赛 → RD 减小 → 匹配收紧
- 加入 **评分波动性（σ）**：衡量分数不稳定程度

**适用场景**：
- 国际象棋、在线棋类
- 适合玩家数量中等、对战频率不固定的场景

## 二、匹配池管理

### 2.1 匹配窗口策略

```
优先级递减：
1. 段位匹配（精确）
2. 段位放宽（±1段 → ±2段）
3. 地区放宽（同服 → 跨服）
4. 模式放宽（单人 → 组队混合）
5. 机器人填充（仅低段位）
```

**典型时间窗口设计**：
- 0-10s：精确匹配（段位差 ≤1 段，同地区）
- 10-30s：放宽段位（±2 段）
- 30-60s：放宽地区
- 60s+：机器人/提示重试

### 2.2 特殊匹配策略

**新手保护**：
- 前 N 局只匹配新手
- 前 N 局有机器人（比例递减）
- 前 N 局输不掉分

**连胜/连败处理**：
- 连胜：匹配更强的对手（但要有上限）
- 连败：匹配更弱的对手（防止流失）

**组队匹配**：
- 组队玩家应匹配组队玩家（公平性）
- 组队分差限制（防止带分）
- 组队权重（取最高分 or 平均分 or 加权平均）

## 三、排位/段位系统

### 3.1 段位结构设计

**通用模板**：
```
传说 / 王者       ← 前 0.1%-1%
超凡大师           ← 前 1%-3%
钻石 I-V          ← 前 3%-10%
铂金 I-V          ← 前 10%-25%
黄金 I-V          ← 25%-50%
白银 I-V          ← 50%-80%
青铜 I-V          ← 80%-100%
```

**设计要点**：
- 段位数量：6-8 个大段，每段 3-5 个小段
- 段位分布：正态分布，大多数人应该在黄金-铂金
- 顶端段位：严格控制比例，保证稀缺性

### 3.2 升降级机制

**星数制**（王者荣耀、皇室战争）：
- 赢 +1 星，输 -1 星
- 满星触发晋级赛
- 0 星触发降级赛（或降级保护）

**胜点制**（英雄联盟）：
- 每局获得/失去 LP（League Points）
- 100 LP = 晋级赛资格
- 0 LP 有降级保护

**晋级赛设计**：
- 普通段位晋级：N/M 制（如 2/3 或 3/5）
- 大段晋级：更高的 N（如 3/5 或 4/7）
- 降级保护：刚晋级后 X 场不掉

### 3.3 赛季机制

**赛季时长**：
- 短赛季：1 个月（皇室战争）
- 中赛季：2-3 个月（王者荣耀、Apex）
- 长赛季：6-12 个月（英雄联盟）

**赛季重置**：
- 软重置：按比例降段（如钻石→铂金，王者→钻石）
- 硬重置：全部清空（极少使用，新游戏上线可用）
- 赛季继承：保留部分分数/隐藏分

**赛季奖励**：
- 段位皮肤（王者荣耀）：最有吸引力的奖励
- 边框/称号：社交炫耀价值
- 货币/宝箱：实用奖励
- 赛季结算动画：仪式感

## 四、竞技生态设计

### 4.1 竞技正循环

```
参与排位 → 获得段位 → 获得奖励/炫耀 → 下一赛季继续
    ↑                                              |
    └────────── 段位目标驱动 ←──────────────────────┘
```

### 4.2 防止竞技生态崩溃

| 风险 | 后果 | 预防 |
|---|---|---|
| 段位通胀 | 段位失去意义 | 赛季重置、控制段位比例 |
| 代练/炸鱼 | 低段位体验差 | 表现分跳段、异常检测、举报 |
| 外挂 | 竞技公平性丧失 | 反作弊系统、信誉分 |
| 机器人泛滥 | 竞技信任丧失 | 控制比例、高段位禁机器人 |
| 玩家流失 | 匹配池缩小 | 放宽匹配、合服、PVE 补充 |

### 4.3 竞技 vs 休闲的平衡

- 不是所有玩家都打排位
- 提供多种竞技出口：排位、娱乐赛、限时赛、自定义房
- 休闲玩家也需要"成就感"（收集、社交、PVE）

## 五、数据分析

### 5.1 匹配系统核心指标

| 指标 | 含义 | 健康值 |
|---|---|---|
| 平均匹配时长 | 从点匹配到找到对手 | <30s（低段位），<60s（高段位） |
| 匹配成功率 | 超时前成功匹配的比例 | >95% |
| 段位差 | 匹配双方段位差 | ≤2 段 |
| 胜负比 | 匹配双方胜率 | 40%-60% |
| 取消率 | 匹配后取消的比例 | <5% |

### 5.2 排位系统核心指标

| 指标 | 含义 | 健康值 |
|---|---|---|
| 段位分布 | 各段位玩家比例 | 正态分布 |
| 排位参与率 | 活跃玩家中打排位的比例 | 30%-50% |
| 段位流动率 | 段位变化的玩家比例 | 活跃 |
| 连胜/连败率 | 极端连胜/连败比例 | <3% |
