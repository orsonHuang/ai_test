## 投递前优先核实

| 事项 | 需要确认 | 确认后的写法 |
| --- | --- | --- |
| 职位与管理时间 | 晋升执行主策的年月；10 人是否直接管理；对应项目 | 在公司任职日期下标明职位阶段，例如“系统策划 → 执行主策（具体年月）” |
| 竞技场参与率 | 指标定义、统计周期、改版前后数值；30% 为相对增幅还是百分点 | “上线后【周期】参与率由 A% 升至 B%” |
| 竞技场胜率 | 新玩家统计范围、是否处于保护期、机器人对局占比及观察周期 | 如需恢复，分别说明新手保护阶段与成熟玩家的胜率，不混为同一口径 |
| 弹珠机收益 | 收益是流水、付费收入还是其他指标；达到原来的 5 倍还是增加 5 倍；活动时长和规模是否可比 | “在【可比条件】下，活动【指标】达到上期的 X 倍” |
| 《点消》ROI | 次日单日或累计回收；计算是否计入红包成本；统计窗口 | 明确口径后恢复“投放后次日累计 ROI≥1”等真实表述 |
| KA 运营数据 | 4,880 万与 1,100 万是广告消耗还是游戏流水；统计主体及个人职责 | 若为消耗，可写“负责客户单月广告投放消耗峰值……”；若为游戏流水，应说明客户产品规模，避免归为个人成果 |
| 早期时间线 | 2016.01—2016.07 是否实习；创业具体时间 | 必要时拆分实习、正式工作及创业经历，避免“毕业后”与毕业日期冲突 |
| 在职状态 | 当前公司是否仍在职 | 如已离职，将“至今”改为实际结束年月 |

## 建议补充的证据

1. **执行主策案例：** 补一条真实的版本取舍与交付案例，说明项目目标、资源约束、自己的决策及结果。仅列团队人数与审核职责不足以充分体现主策能力。
2. **作品直达链接：** 为两个 Demo 分别补试玩、短视频或设计复盘入口；先检查链接可访问、无需额外权限。
3. **个人项目验证：** 如有真实试玩，补充发现的问题、修改内容和验证结果。不要补写未做过的测试或推测的收益。
4. **项目背景：** 如可公开，补主要商业项目的上线阶段、目标市场与个人负责时间。
