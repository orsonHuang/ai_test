# 游戏方向池

> 发散阶段：所有候选方向以卡片形式记录。不评判，先收集。

---

## 使用说明

每个候选方向包含：
- **名称**：简短命名
- **一句话描述**：核心体验
- **品类**：Roguelike / 模拟经营 / 解谜 / RPG / ...
- **Godot 适配度**：高/中/低（技术可行性）
- **AI 协作潜力**：高/中/低（AI 能在哪些环节发挥价值）
- **参考游戏**：类似作品
- **风险/挑战**：可能的问题

---

## 候选方向

### 方向 #1：Godot-RogueIdle（已有苗头）

- **一句话**：放置肉鸽，"战斗即构筑"——战斗中获得的技能直接变成 Build
- **品类**：放置 + Roguelike
- **Godot 适配度**：高（UI 为主，逻辑驱动）
- **AI 协作潜力**：高（数值平衡、技能组合生成、测试自动化）
- **参考**：Melvor Idle、Loop Hero
- **风险**：放置品类需要长期运营验证

### 方向 #2：DragonQuest-Maze（已有苗头）

- **一句话**：迷宫探索 + 战斗，经典 RPG 框架
- **品类**：迷宫 RPG
- **>Godot 适配度**：高（TileMap 天然适配）
- **AI 协作潜力**：高（程序化迷宫生成、敌人 AI、对话生成）
- **参考**：世界树迷宫、巫术系列
- **风险**：迷宫玩法需要大量内容填充

---

### 方向 #3：Grid 逻辑解谜（Murdoku-like）

- **一句话**：在网格上用逻辑约束排列元素，通过线索推理完成目标——数独骨架 + 任意主题皮肤
- **品类**：逻辑解谜（Puzzle）
- **Godot 适配度**：高（Grid + UI + 约束系统，无物理需求）
- **AI 协作潜力**：极高（关卡自动生成是核心，AI 生成约束条件 + 验证唯一解）
- **参考**：Murdoku（数独+推理）、Zachtronics 系列
- **风险**：纯逻辑解谜受众窄，需要强叙事包装拉新

### 方向 #4：消除类休闲（三消-like）

- **一句话**：基于 Grid 的消除玩法，轻战斗/无战斗，纯休闲体验
- **品类**：消除 / 休闲
- **Godot 适配度**：高（Grid 系统 + 动画，Godot 2D 强项）
- **AI 协作潜力**：高（关卡自动生成、道具系统设计、难度曲线）
- **参考**：喵喵消消乐、Candy Crush、宝石迷阵
- **风险**：三消市场红海，需要玩法变体才能差异化

### 方向 #5：Grid 玩法杂交（Murdoku × 三消 × ?）

- **一句话**：取 Grid 逻辑的深度 + 消除的爽感 + 新机制，做一个市面上没有的 Grid 新品
- **品类**：混合休闲
- **Godot 适配度**：高
- **AI 协作潜力**：极高（玩法组合探索、关卡生成、平衡）
- **参考**：Murdoku + 喵喵消消乐 + 未知元素
- **风险**：杂交可能两头不讨好，需要原型快速验证

### 方向 #6：卡牌桌游（抽牌-打牌-循环）

- **一句话**：抽牌、选牌、打牌，通过卡牌组合产生效果/得分，偏桌游式的策略体验
- **品类**：卡牌策略 / 桌游电子化
- **Godot 适配度**：高（卡牌数据结构 + UI + 计分系统，Godot 2D 强项）
- **AI 协作潜力**：极高（卡牌效果批量生成、多路线平衡验证、AI 对手策略）
- **参考**：小丑牌（牌型+改规则）、种呱得呱（抽卡付费+打牌免费）、七大奇迹（轮抽+多路线得分）
- **风险**：卡牌游戏核心是"卡牌设计质量"，需要大量迭代
- **状态**：已吸收进 #8，不再独立推进

### 方向 #7：放置增量（龟龟潜海记-like）

- **一句话**：点击→自动化→数值爆炸，治愈主题包装的增量游戏
- **品类**：放置 / Idle
- **Godot 适配度**：高（纯数值+UI）
- **AI 协作潜力**：中（数值曲线设计、升级树生成）
- **参考**：龟龟潜海记、Cookie Clicker
- **风险**：玩法深度有限，容易被定义为"小游戏"

### 方向 #8：信息博弈卡牌（Demon Bluff-like）⭐⭐ 最高优先级

- **一句话**：卡牌会说谎——每张卡牌的信息/效果可能为真也可能为假，玩家需要通过交叉验证、逻辑推理来识别真相，最终做出正确决策
- **品类**：信息推理 + 卡牌策略
- **Godot 适配度**：高（卡牌数据模型 + 信息逻辑引擎 + UI）
- **AI 协作潜力**：极高（角色身份生成、谎言模式设计、剧本/场景生成、难度动态调控、AI 作为"说书人"）
- **参考**：Demon Bluff（核心参考）、血染钟楼（原型）、Murdoku（推理验证模式）
- **风险**：信息逻辑系统的设计复杂度较高，需要确保"可推理"（不能纯随机）
- **核心创新点**：引入**信息可信度**维度——传统卡牌的效果是确定的，这里卡牌描述可能为假

### 方向 #6 与 #8 的关系

方向 #6（通用卡牌桌游）是宽泛品类，#8（信息博弈卡牌）是具体切入。
#6 的其他子方向（小丑牌式牌型得分、七大奇迹式轮抽）可以作为 #8 的**辅助机制**引入。

### 方向 #9：选人-验证推理（阿瓦隆 × Demon Bluff）⭐⭐⭐ 确定方向

- **一句话**：玩家作为列车长（队长），每轮选人上车执行任务，被选中角色各自"汇报"结果——但汇报可能为假。玩家通过对比多人汇报、分析矛盾点，推理出真相
- **品类**：信息推理 + 选人策略
- **核心循环**：
  ```
  发牌（角色分配，隐藏身份）
    → 选人上车（策略选择）
    → 执行任务（系统结算）
    → 角色汇报（信息可能为假）
    → 玩家分析推理
    → 下一轮选人
    → 最终判断（指认真相）
  ```
- **Godot 适配度**：高（角色数据模型 + 信息生成引擎 + UI 交互）
- **AI 协作潜力**：极高
  - AI 扮演每个角色的"发言者"（根据身份生成符合逻辑的汇报）
  - AI 生成角色身份 + 信息规则
  - AI 作为"系统"调控真假信息比例
  - AI 生成每局的剧本背景
- **参考**：
  - 阿瓦隆（选人上车 + 任务投票机制）
  - Demon Bluff（卡牌会说谎 + 身份推理）
  - 血染钟楼（说书人 + 信息差设计）
- **与 Demon Bluff 的差异化**：
  - Demon Bluff 是"翻牌看信息"，被动接收
  - 本方向是"选人→看汇报"，**主动选择信息来源**——选谁本身就是策略
- **风险**：需要确保信息逻辑"可推理"（不能纯随机），这是设计难点也是 AI 的用武之地

## 模式识别（更新）

从所有方向中发现的共性：

| 维度 | 观察 |
|------|------|
| **Grid 核心** | 方向 #1-#5 都涉及 Grid 系统，但 #6 打破了这一模式 |
| **卡牌驱动** | #6 引入新范式：卡牌作为"选择"的载体，替代了 Grid 位置 |
| **低战斗/无战斗** | 用户偏好明确，#1-#2 已降优先级 |
| **AI 最大价值点** | 卡牌/关卡/数值的内容生成是共同高价值场景 |
| **首 Demo 策略** | 卡牌类天然适合快速原型：数据驱动，UI 简单 |
