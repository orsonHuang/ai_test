# 晚安小屋 · 执行文档 v0.1

更新：2026-09-26。规则以[GDD](GDD/设计文档.md)为准；本文负责实现顺序与验收。当前完成文档，M0—M3均未实施。首发微信小游戏。

## 1. 技术与职责

建议使用 Cocos Creator＋TypeScript；现有 `cocosProject/Goodnight-House/package.json` 配置Creator 3.8.8，后续核实匹配编辑器与初始工程可运行性，不重新创建或覆盖。以 Cocos 真正可运行工程为交付，浏览器调试不能替代微信真机。

| 模块 | 职责与依赖 |
|---|---|
| 规则核心 | 独立于引擎的数据模型、放置、约束检查、撤销与笔记；客户端、生成器和服务端复用规则定义与测试样例 |
| 规则注册表 | 每种规则的校验器、参数类型、中文模板、图标、相关动物索引、版本；新增类型必须完整登记 |
| 关卡工具 | 离线生成、唯一解求解、人类推理模拟、模板文本预览、难度报告、去重和审核发布；运行时不批量出题 |
| Cocos界面 | 房间／设施／动物卡／房牌预制体；页面只呈现状态、发送操作，不独立维护另一套判定 |
| 提示服务 | 当前局面＋线索 → 可解释推理记录；提示权益与具体推理分开，广告完成后可安全恢复 |
| 微信适配 | 登录、存储、激励广告、前后台生命周期；开发模拟器与生产适配明确隔离 |
| 最小服务端 | 每日题、内容版本、身份验证、按日代表地区、有效提交校验及地区聚合；不得从好友榜直接推断省份总人数 |

集成入口：[Cocos 官方微信发布说明](https://docs.cocos.com/creator/3.0/manual/zh/editor/publish/publish-wechatgame.html)。该链接仅作流程参考，不代表已选定3.0；SDK接口、平台限制与广告完成条件在确定版本时复核。

## 2. 最小数据契约

| 数据 | 必要字段 |
|---|---|
| 关卡 | ID、关卡版本、规则版本、种子、房型、房间坐标／关闭状态／设施、动物ID、结构化线索、显式楼层人数、难度、审核状态 |
| 规则 | type、参数、唯一clueId、文案模板键；涉及动物列表由参数推导；设施栏由本关有效设施数据生成 |
| 作者与验证数据 | 目标答案、解数量结论、完整搜索状态、求解耗时、推理轨迹、难度依据、去重指纹；与客户端发布数据分开 |
| 对局存档 | 关卡版本、局次ID、入住映射、按动物保存的笔记、撤销栈、已交付提示、本局免费次数、通关状态；未消费广告权益独立持久化 |
| UI临时状态 | 选中动物、笔记模式、全部约定滚动位置、详情滚动位置；UI选择不改变入住数据 |
| 每日提交 | 服务端身份、日期、每日题版本、入住映射、请求ID；代表地区取服务端已固定记录，不信任提交中的任意地区 |

核心示例：`{clueId: c02, type: floor_higher_than, subject: cat, target: rabbit}` → 文本“小猫的楼层比小兔高” → 同时进入小猫与小兔详情 → 同一判定函数检查楼层。

| M2 内容与外层 | 最小关卡编辑／预览工具、批量生成筛选、三十关验证池；主线进度、每日题与地区榜服务端、真实微信登录／广告 | 入库题全部唯一且可解释；抽样试玩符合分档；当日同题、重复提交不重复计数；真实广告成功／失败分支验证 |

## 4. 内容生产与提示

1. 策划选择规则家族、目标难度、住客数和关闭布局，生成器生成合法答案。
2. 从模板库提取成立条件，选择能区分其他答案的线索；不够则重生，不自由编造无法判定的中文。
3. 搜索第二解；仅完整证明唯一的题继续。模拟已教推理方法，拒绝普通关必须猜测的题。
4. 调整冗余、阅读量、开局突破口与链长，重新验证；按结构而非仅图片或角色名去重。
5. 输出中文／图标预览、推理轨迹和报告；人工抽样后进入已审核池。
6. 发布固定版本关卡包；主线与每日只从审核池选择；缺题时使用预审备用题，不临时发布未校验题。

提示产物结构：关联clueId、使用的已确认事实、排除动作、理由模板、结论。程序必须能验证该推理；对玩家错误安排先定位可靠冲突，不能将手动错误笔记当成真事实。再次阅读已交付解释不消耗权益。

批量试验建议：固定设备与规则版本生成1000个候选，记录耗时、唯一解通过率、无需猜测通过率、结构重复率、人工留存率。以实测决定能否量产，不预设全部候选都是合格关卡。

## 5. 验收清单

| 类别 | 必验行为 |
|---|---|
| 核心判定 | 全员安置、房间容量、设施／相邻／人数条件；关闭格不能入住；移动取回更新人数与房牌；不能通过自动交换绕过规则 |
| 生成器 | 已知0／1／多解；超时未验证；固定种子可复现；文本与判定一致；未教规则不出现；修改关闭布局后重新验证 |
| 相关线索 | A提到B时，两者详情都显示；线索ID去重；全局规则可访问；全部／详情标题数量准确；返回恢复列表滚动位置 |
| 动物卡片 | 已入住卡片保留原位且顶部显示房牌；移房更新、取回清除；再次点选只取消选择；溢出可纵滑，出现滚动条 |
| 设施与约定滚动 | 设施固定字号、左对齐、横滑；约定换行纵滑且溢出显示滚动条；三个区域互不抢手势；滑动不误触点击；短内容不留多余滚动范围 |
| 顶部与底部 | 左上设置内可返回首页；无右上总入住数；楼层人数有图标；设施栏无旧规则说明；底栏及微信安全区无遮挡 |
| 免费／广告提示 | 首次实际交付免费、随后图标切换；主动重开恢复免费及灯牌图标，清空本局提示记录；完成广告才发放；取消／失败不发放；重复回调幂等；无有效提示不启动广告 |
| 存档 | 重开创建新局并清空局面／笔记／撤销，退出续玩保留当前局次与提示次数；已获未消费广告权益可恢复且不重复发放；强退、损坏与版本升级有恢复策略 |
| 每日与榜单 | 相同日期同题；按服务端日界；每账号每日一次；更换地区按规定生效；提示不扣贡献；重试幂等、过期与离线有反馈、并列同名次 |
| 资源与真机 | 设施与纯装饰不混淆；无锁房穿透点击；小屏文字可读；图集、内存、首屏耗时与包体有实测记录 |

测试分层：规则／生成器自动测试 → Cocos交互验收 → 微信工具与真实广告 → Android/iOS真机。文档检查通过不代表游戏通过。

## 6. 验证指标与依赖

记录关卡进入／完成／退出、主动检查失败、首次提示位置、提示后完成、广告请求／成功／取消／失败、每日有效提交。以完成时长、提示使用、卡点和退出分布调整难度；指标目标待首轮试玩建立，不预设留存或收入承诺。

| 依赖／决策 | 当前处理 |
|---|---|
| 首发平台 | 已确认微信小游戏 |
| Creator版本 | 现有工程配置3.8.8，M0核实编辑器与工程可用性；不擅自安装或升级 |
| 提示次数 | 已确认每次重开刷新首次免费；同一局第二次及以后使用广告提示；退出续玩保留状态作为设计基线 |
| 微信AppID、广告位 | M1构建／M2真实接入前取得；不伪造，不把模拟结果当接入完成 |
| 服务端与部署环境 | M2前选型；先实现身份、日期与幂等提交的接口契约 |
| 章节／奖励／收藏规模 | M1试玩后确定配置，不阻塞核心原型 |

风险处理：生成质量低则先完善模板与推理方法；手机文本过密则调整面板与滚动，不缩小设施文字；广告填充失败保持可继续游玩；地区榜初期人数少如实显示。所有阶段状态以交付证据更新。
