# 晚安小屋 · GDD v0.1

更新：2026-09-26。状态：立项基线，未实现。**已确认**指用户明确选择；其余标为**设计基线**，用于原型验证，不冒充用户定稿。执行顺序见[执行文档](../执行文档.md)。

## 1. 定位与循环

**一句话：通过睡前约定安排动物入住，在短局推理中点亮温暖小屋。**

- 已确认：Cocos、2D 轻量、首发微信小游戏、晚安小屋题材；采用竖屏剖面小屋布局。
- 用户：喜欢轻量逻辑谜题、碎片时间游玩的玩家。参考喵喵数独的排除推理、Murdoku 的场景与角色线索；不沿用其全部规则。
- 体验目标：规则清晰、每步有依据、可撤回、完成后有温暖反馈。深度来自约定交叉与位置关系，美术采用模块复用。
- 秒级循环：读线索 → 标记或安排 → 获得房牌与人数反馈，形成下一步判断。
- 单局循环：完成安排 → 主动检查 → 全屋晚安反馈与通关进度。
- 局外循环：推进主线／完成每日题 → 解锁章节或增加地区通关人数 → 回来挑战新题。

## 2. 核心规则与操作（设计基线）

| 机制 | 规则与边界 | 目的 |
|---|---|---|
| 入住 | 每位动物恰好入住一间开放房间；每房最多一位，可留空房；不限制每行每列只能一位 | 清晰的分配问题 |
| 关闭房间 | 开局固定、整局不可入住，不可通过广告打开；关闭与普通空房视觉区分 | 控制可用规模和布局 |
| 设施 | 有窗户／夜灯／绿植是房间属性；规则设施与装饰分离；关闭房间不作为有效候选 | 位置条件可读 |
| 位置关系 | 左右紧邻＝同层相差一列；正下方一层＝同列相差一层；不跨关闭房间跳格 | 杜绝语义歧义 |
| 楼层人数 | 仅配置了精确人数的楼层显示当前／目标；没有该条件时不能泄露答案人数 | 支持数量推理 |
| 放置与移动 | 点动物再点空房入住；已入住动物选中后可移至空房；目标已占用则反馈占用，不自动交换 | 降低误操作 |
| 取回 | 已入住动物详情提供独立取回入口（设计基线）；重复点击已选动物只取消选择，点击其他动物切换选择 | 支持修正，避免与取消选择冲突 |
| 笔记 | 选中动物后切换笔记模式，点开放空房循环“未标记／候选／排除”；按动物独立保存，不改变入住与人数 | 支持自主推理 |
| 撤销 | 回退上一步入住、移动、取回或笔记；不回退广告权益、已交付提示和通关记录 | 自由尝试 |
| 检查入住 | 检查全部动物、容量和全部线索；不符则反馈未入住／冲突，不自动填答案；全部满足才通关 | 完成闭环 |
| 失败与存档 | 无生命损耗、无强制计时；设置内可重开和返回首页；保存安排、笔记及提示状态 | 轻量无压力 |

点选默认只筛线索，不自动显示标准答案或替玩家推导候选。图中的候选边框作为笔记表现。关闭设施与容量也必须参与生成器校验，不能对已出题目随机关房。

## 3. 关卡与线索生成（设计基线）

**房型与关闭布局 → 合法答案 → 提取成立的候选规则 → 选线索 → 唯一解检查 → 人类推理检查 → 文本与图标渲染 → 去重、审查、入库。**

| 规则族 | 模板示例 |
|---|---|
| 设施条件／组合 | 小兔住在有夜灯、没有窗户的房间 |
| 同层／高低 | 小猫的楼层比小兔高 |
| 水平紧邻／垂直相邻 | 小狐住在小猫左边紧邻的房间；刺猬住在小狐正下方一层 |
| 楼层数量 | 二楼恰好住两位 |
| 后续扩展 | 固定间隔、恰好一位满足条件；先教规则，再加入出题池 |

- 规则以类型与参数保存，同一规则注册表提供判断、中文模板、设施图标与涉及角色列表；不使用自由文本作为判定来源，不依赖在线大模型出题。
- 例如 `{type: floor_higher_than, subject: cat, target: rabbit}` 渲染为“小猫的楼层比小兔高”；小猫和小兔的详情都收录该条，按线索 ID 去重。
- 唯一解：找到首解后排除该安排继续查；第二解存在即不合格；完整搜索证明无第二解才通过，超时算未验证。唯一性按具名动物的入住位置判定，不把笔记状态当答案。
- 玩家推理：单条件排除 → 交集／关系传播 → 成组占位 → 人数交叉；普通关必须能用已教方法解完，保留可解释步骤。
- 有多解则补区分线索；模板无法区分则重生布局／答案。删冗余线索后重新检查唯一性与可推导性，不追求最少线索。
- 难度综合候选规模、最深推理方法、依赖链、阅读量与试玩卡点；开放房间少不保证一定简单。
- 固定种子、规则版本与关卡版本可复现。过滤重复解、镜像换皮及重复推理结构；审核后发布，玩家设备不实时随机制造每日题。

## 4. 关卡界面（用户已确认）

参考：[用户标注图](../references/ui-feedback-20260926.png)。下表包含最新文字修订，优先于图中旧注释。

| 区域 | 最终要求 |
|---|---|
| 顶栏 | 设置按钮放左上角，返回首页合并进设置；删除右上角总入住计数；保留标题、关卡名 |
| 小屋 | 正面剖面、清晰房牌与层列标识；有目标人数的楼层右侧显示人数图标＋当前／目标 |
| 设施栏 | 仅设施图标与名称，删除常驻规则文字；**左对齐、固定字号与图标尺寸，溢出左右滑动，不动态缩小** |
| 左侧住客栏 | 卡片位置保留；入住后卡片顶部出现与房间同风格的房牌号，移动／取回同步更新；超出容器支持上下滑动并出现纵向滚动条 |
| 约定列表 | 默认显示全部约定；单条自动换行，整体纵向滚动；溢出时出现滚动条 |
| 动物详情 | 选中动物后显示头像、姓名、所有涉及它的线索，包含其他动物对它的关系；设施图标嵌入文字；内容过长继续纵向滚动 |
| 详情标题 | 改为“动物名的约定 · N条”；列表恢复“睡前约定 · N条” |
| 取消选择 | 详情返回按钮或再点已选动物均取消选择，恢复全部约定及进入详情前的滚动位置；不取回已入住动物 |
| 底栏 | 撤销、笔记、提示、检查入住；首次免费提示使用灯牌图标，用完后换成灯牌＋广告播放组合图标 |

设计基线：待入住数字只统计未安置动物，但所有卡片保留；全局楼层条件仍显示在小屋，详情不漏掉其他影响全部住客的全局规则。三个列表独立滚动，手势不带动整页；滑动不能触发选卡或入住。入住期间保持选择，便于继续对照约定。

首次引导和设置中的“玩法说明”解释容量、关闭房间与相邻含义，替代已移除的常驻规则文字。小屏通过换行、滚动和安全区适配解决，不以缩小设施栏解决溢出。

## 5. 提示与广告

**已确认：每局第一次提示免费；第二次及以后每次观看广告，按钮图标变为灯牌＋广告播放；每次主动重开关卡重新获得一次免费提示。**

设计基线：提示提供一条完整、可解释的推理，含关联约定、排除理由与结论；同一条提示再次打开不重复收费。当前安排或笔记有错误时，先解释可确认的问题，不在错误假设上继续推导。无有效提示不消耗次数、不启动广告。

| 状态 | 行为 |
|---|---|
| 免费未使用 | 实际交付提示后消耗免费次数，立即切换广告组合图标与“看广告获取提示”说明 |
| 广告提示 | 预检有有效提示 → 玩家主动观看 → 获得完成观看凭据 → 交付一次提示 |
| 中途关闭／无广告／网络失败 | 不交付新提示，不计成功次数；保留局面，可继续解题或稍后重试 |
| 重复回调／连续点击 | 同一请求只交付一次；请求中禁用重复触发 |
| 广告完成后切后台／局面变化 | 保存未消费提示权益；回到当前关卡时重新计算有效提示，不重复要求观看 |

重开创建新一局，清空入住、笔记、撤销栈与本局提示记录，恢复首次免费；这是用户确认的体验取舍，不为限制免费提示额外惩罚重开。设计基线：普通退出重进属于续玩，恢复局面和提示次数；每日新题也从首次免费开始。已获得但尚未交付的广告提示权益单独保存，不因重开或退出丢失。日常收藏奖励广告与插屏均后置，首版不引入；撤销、笔记、重开不收费，广告不增加地区贡献。

## 6. 主线与每日挑战

**已确认范围：主线长期更新；每日挑战按省份展示通关人数，玩家自行选择代表地区。** 以下为实现基线。

| 系统 | 规则 |
|---|---|
| 主线 | 按关卡推进与章节解锁，通关点亮章节小屋；重玩不重复发首通奖励；远端目录支持版本更新与回滚，本地存档按关卡 ID 关联 |
| 轻收藏 | 优先考虑住客晚安卡与章节纪念图；装饰不改变关卡设施含义。奖励数量、章节规模待试玩后配置 |
| 每日题 | 全地区同一道经审核题，按北京时间自然日切换，以服务端日期为准；建议超期可练习但不计前日榜 |
| 代表地区 | 主动选择支持地区，不需要真实定位；建议当日首次参赛后固定，次日可换 |
| 地区榜 | 展示今日各地区有效通关账号数；每账号每日最多贡献一次，重试不重复计数，使用提示仍可贡献 |
| 展示定位 | 属于参与人数榜，不称地区智力排名；并列人数同名次，无数据时显示空态，不伪造人数 |
| 服务端 | 验证每日题版本、用户身份、入住条件与日期；以账号＋日期做幂等去重，服务端汇总；断线重试同一提交，不由客户端直接加人数 |

离线可玩已缓存主线；每日榜需要联网确认资格和提交结果。最小服务端不等于完整反作弊，账号滥用与异常提交监测须在上线前评估。

## 7. 美术、声音与试制参数

| 项目 | 基线／状态 |
|---|---|
| 房屋 | 墙面、地板、床铺、屋顶、边框复用；独立设施层、角色层、房牌和反馈层；每关以配置重组 |
| 首批资产 | 一套小屋模块、窗户／夜灯／绿植、关闭房间状态、八种动物、人数图标、房牌、按钮、免费及广告提示双状态 |
| 动效与声音 | 入住轻反馈、通关入睡／熄灯短演出；轻环境音与按钮音；设置支持音效／音乐开关 |
| 原型棋盘 | 以三层四列十二房为上限样例，通过关闭布局验证不同规模；不视为正式全游戏上限 |
| 试制关卡 | 垂直切片五关，内容验证池三十关（建议验收规模，非承诺上线数量） |
| 时长目标 | 普通关约一至三分钟；实际分档由试玩决定，不强制计时 |
| 适配与包体 | 竖屏、安全区、低端机可读与流畅；UI验证先覆盖360与390逻辑宽度、短长屏；包体／纹理预算按选定引擎与微信实测确定 |
