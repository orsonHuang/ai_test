# DarkIdle｜执行与验收

更新：2026-10-29。当前交付：可在 Godot 直接运行的燃爆法师体验版。

## 试玩入口
1. 在 Godot 打开 `gd-dark-idle/project.godot`，按 **F5**。当前已通过 MCP 启动，停在战前编排。
2. 先保留“燃爆连段”预设，点击“开始战斗”；想看判定时使用暂停、单步或速度选项。
3. “返回编排”后，移动火星或火葬的位置、改触发条件，比较剩余生命与回合数。
4. “?” 查看完整规则；“保存战术”后重开可恢复。保存的是战前设置，不是战斗进度。

当前默认：火墙 → 爆燃 → 火星 → 火葬 → 炼狱 → 炎爆 → 点燃。每回合按序扫描，每行最多一次；AP 不够的行会记录跳过原因。

## 工程与编辑
| 入口 | 职责 |
|---|---|
| `scenes/main.tscn` | 原生主场景；战场、主动/被动面板、日志、控制条 |
| `scenes/rule_row.tscn` | 可复用的原生战术行 |
| `scenes/combatant.tscn` | 角色立绘、生命和燃烧标牌 |
| `resources/balance.tres` | Inspector 可调生命、AP/RP、层伤、减伤、敌人数值与回合上限 |
| `scripts/battle_rules.gd` | 纯规则、技能定义与确定性事件流 |
| `scripts/battle_view.gd` | UI 绑定、事件播放、存档 |
| `scripts/battle_fx.gd` | 运行时粒子/飞弹/飘字；基础 UI 不在运行时拼装 |
| `assets/` | 剪纸背景、透明角色图集、原创合成音效 |

日常修改场景直接在 Godot 进行并保存。`tools/build_scenes.py` 是初始场景和音效的制作脚本，**会重建其管理的场景/主题/音效**，手工调整后不要无意重跑。最终保存的 `.tscn` 是编辑入口。

## 本次实际 Godot MCP 流程
1. 在目标工程启用已有 Godot AI 2.9.0 插件，确认会话真实路径为本项目；使用本机 HTTP MCP 的 JSON-RPC 协议。
2. 将逻辑、原生场景、主题和素材保存为普通工程文件。
3. MCP 执行 filesystem scan → scene open → script attach → scene save → project run。
4. 修改后 stop → scan → force reload 已保存场景 → save → run，确认不是只改运行时节点。
5. 通过游戏调试桥检查状态，并发送实际鼠标事件测试原生控件；截图来自 Godot 运行画面。

工程内 `tools/mcp_bridge.py` 使用 Python 标准库连接 `http://127.0.0.1:8000/mcp`。它从会话列表按项目绝对路径选择唯一目标，不靠默认激活的编辑器。当前编辑器版本为 **Godot 4.7.2-stable (Steam)**。

复跑规则测试，从 Godot 工程目录执行：

```powershell
.\tools\test.ps1
# 其他机器指定 Godot：
.\tools\test.ps1 -Godot '你的Godot可执行文件路径'
```

底层入口为 `godot --headless --path . --script res://tests/run_tests.gd`。Windows GUI 版 Godot 应等待进程并读取输出，不能只凭启动命令退出码认定测试成功。

复跑 MCP 操作验收前需打开工程、启用 Godot AI、运行主场景，再从工程目录执行 `python tools/playtest.py`。该脚本会操作当前战术并测试存档，结束后恢复初始战术。下拉菜单验收使用实际选项点击；此前键盘模拟未稳定选中选项，已改为点击并验证结果。

## 已知边界与下一步
- 当前是一场固定遭遇的战术体验版；路线、奖励、长期构筑、多英雄、反击及 Steam 导出/接入未实现。
- 条件每行一个；生命最低按绝对生命；被动时机固定。与历史 UI 提案的差异在 GDD 中集中说明。
- 使用 Windows 系统中文字体，尚未验证其他系统与字体环境；当前视觉验收分辨率 1440×810，未宣称完成多分辨率/手柄适配。
