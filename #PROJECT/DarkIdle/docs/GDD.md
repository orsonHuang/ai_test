# DarkIdle｜燃爆法师体验版 GDD

版本：0.1 · 2026-10-29。对应 `gd-dark-idle/` 实现。工作名，非正式商品名。

## 1. 一句话定位
编排法术与反应条件，让暗黑剪纸法师自动完成叠火、扩散和核爆。

设计重点：玩家能预测连招，看到执行原因，修改一个顺序或条件后验证差异。当前提供固定遭遇的战术实验台。

## 2. 核心循环
| 层次 | 动作 → 反馈 → 回报 | 当前状态 |
|---|---|---|
| 秒级 | 施法 → 层数、飘字、规则高亮 → 看懂组合生效 | 已实现 |
| 单场 | 查看敌人 → 编排 → 自动战斗 → 复盘 → 再编排 | 已实现 |
| 多场 | 选择路线 → 获得法术变体/遗物 → 改写构筑 → 挑战首领 | 后续方向，未实现 |

买断版的长期乐趣来自新组合和不同敌情。体验版不加入离线收益、每日任务或反复刷数值；先验证战前策略是否有趣。

## 3. 用户、平台与参考
- 目标：喜欢构筑、自动战斗和可解释战术的桌面玩家；Godot 4，未来 Steam 单机买断。
- 当前运行环境：Windows，Godot 4.7.2；尚未完成 Steam 接入、发行构建或商店准备。
- 参考 Auto Rogue 的战前构筑方向；《圣兽之王》提供主动/被动资源、固定时机与附加条件分开的思路。当前项目规则是原创取舍，不是复刻其完整系统。
- 历史视觉及规则提案见 `../../../#AI-NOTEBOOK/auto-battler-art-directions-20261029/战前战术UI-v2.md`。参考来源：[SEGA 战斗说明](https://asia.sega.com/unicorn-overlord/cht/system/stage-battle/) / [ATLUS 指南](https://unicornoverlord.atlus.com/media/pdf/unicorn_overlord_tips.pdf)。

## 4. 核心机制与边界

### 本版采用的规则
| 机制 | 目的与规则 | 边界 |
|---|---|---|
| 主动序列 | 每回合从上至下扫描 7 行，每行最多执行一次 | 可重复配置同一法术；禁用、条件失败、AP 不足均跳过 |
| 条件与目标 | 先筛选合格敌人，再按偏好选一个 | 无合格目标不花费 AP；全体法术存在合格目标即可发动，影响全部存活敌人 |
| 被动反应 | 技能决定固定时机；玩家设置额外门槛并启停 | 本版三个时机不同，不提供被动排序；每次成功消耗 1 RP |
| 燃烧 | 存活敌人持有非负整数层数；每层 8 点伤害 | 回合末一次引爆并清空；不按秒持续扣血 |
| 即时引爆 | 炎爆/炼狱先加层，再引爆 | 保留层数，允许回合末再爆；法术本身仍收费 |
| 蓄能 | 下一次成功施法“新增的燃烧数量”翻倍 | 仅一次；翻倍法术：原 3 层 + 新增 6 层 = 9 层；不加倍直伤和引爆伤害系数 |
| 结算 | 法师行动 → 存活敌人从左到右普攻 → 燃烧清算 | 法师死亡立即失败，不补结算回合末；敌人全灭即胜；最多 8 回合 |

**与之前 UI 提案的差异**：旧提案每次行动重新检查最高优先级。当前采用整条序列每轮走一遍，使“铺火→翻倍→扩散→引爆”的顺序直接可编排，避免无冷却的第一条技能独占 AP。这是本次原型选择，后续多英雄系统需重新评审。

### 需求与暂定值
用户明确：7 个主动法术、3 个被动法术、燃烧回合末引爆清空、3 个普攻小怪、横版暗黑剪纸。

本版补充：AP/RP 每回合重置、各项数值、每轮一次魔力恢复和蓄能、火星复制不转移、7 条规则可重复、单条件编辑。已就“无消耗引爆”发起澄清，超过用户约定的 5 分钟未回复，按“保留燃烧层数；仍支付技能 AP”实现。

### 触发条件与优先目标
| 类别 | 可选项 | 精确定义 |
|---|---|---|
| 主动条件 | 无；目标已有燃烧；目标燃烧 ≥4；自身生命 <50% | 施放前即时检查；生命等于 50% 不满足 |
| 单体目标 | 燃烧最多；生命最低；最前方 | 生命按绝对值；平局按左到右站位 |
| 固定目标 | 爆燃=燃烧最多；火墙/火葬/炼狱=全体 | UI 锁定并显示真实目标 |
| 被动条件 | 总是；自身生命 <50%；RP ≥2 | 消耗 RP 前判断；RP ≥2 可留至少 1 点 |

火星在攻击前记录源目标层数。源目标被其直伤击败仍可扩散到其他存活敌人。阵亡敌人燃烧清零，不再成为目标。未满足条件不会偷偷退回其他目标或免费普攻。

## 5. 系统与 UI

| 区域 | 玩家能做什么 | 战斗反馈 |
|---|---|---|
| 横版战场 | 看敌人生命与固定攻击伤害 | 施法飞弹、短促位移、受击、阵亡淡出 |
| 主动列表 | ↑↓排序、启停、换法术、设条件和目标、查看说明 | 本次实际执行行高亮；重复技能按行定位 |
| 被动列表 | 看固定时机、启停和配置条件 | 炎盾、蓄能和回能文字反馈；RP 更新 |
| 状态条 | 查看回合、生命、AP/RP | 实时状态快照，无隐藏资源 |
| 燃烧标牌 | 看层数和预计单次引爆伤害 | 叠层文字、火焰形状和引爆大飘字 |
| 战斗日志 | 查看最近 45 条记录 | 包含跳过原因、伤害公式和结果 |
| 控制栏 | 3 套预设、开战、暂停/单步、1/2/4倍速、返回编排、保存 | 战斗时锁定配置；返回后可立即重试 |

说明弹窗补充条件筛选和蓄能计算；音效与减弱闪震可切换。战术写入 `user://tactics.json`，重开恢复；坏 JSON 或结构不合法时使用默认战术。当前只保存战术，不保存战斗进度。

实现依赖：`balance.tres` → `battle_rules.gd` 生成确定事件和快照 → `battle_view.gd` 播放 → `battle_fx.gd` 表现。暂停和倍速只影响播放，不改变结果。界面使用保存的 `.tscn` 原生控件，可在编辑器修改。

## 6. 数值表

所有数值为体验版调试值，不是正式平衡结论。

| 基础参数 | 值 |
|---|---:|
| 法师生命 | 120 |
| 每轮 AP / RP | 6 / 3 |
| 每层燃烧伤害 | 8 |
| 炎盾减伤 | 50%，剩余伤害向上取整 |
| 回合上限 | 8 |

| 主动法术 | AP | 直伤/每目标 | 燃烧效果 |
|---|---:|---:|---|
| 点燃 | 1 | 4 | 单体 +1 |
| 火墙 | 1 | 3 | 全体 +1 |
| 爆燃 | 1 | 4 | 燃烧最多敌人层数翻倍 |
| 火星 | 1 | 2 | 源目标层数复制叠加给其他敌人 |
| 火葬 | 2 | 3 | 全体层数翻倍 |
| 炎爆 | 1 | 4 | 单体 +2，再即时引爆且保留 |
| 炼狱 | 2 | 0 | 全体 +1，再即时引爆且保留 |

| 被动 | RP | 时机 | 效果与频次 |
|---|---:|---|---|
| 蓄能 | 1 | 本轮首次成功施法前 | 下一行动新增层数 ×2；本轮首次机会检查一次 |
| 魔力恢复 | 1 | 合格的下一法术 AP 不足时 | 恢复 1 AP；每轮最多成功一次；补足后仍不足则跳过法术 |
| 炎盾 | 1 | 每名敌人攻击前 | 本次减伤 50%；攻击者 +1 燃烧；RP 允许即可重复 |

| 敌人 | 生命 | 普攻 | 轮廓与功能 |
|---|---:|---:|---|
| 灰烬刺球 | 95 | 12 | 低矮刺球，适合观察单体点杀 |
| 鹿面巡守 | 125 | 16 | 高瘦鹿角，与刺球轮廓区分 |
| 枯枝稻人 | 155 | 20 | 草帽长臂，检验扩散与范围伤害 |

伤害：`引爆伤害 = 当前燃烧层数 × 8`。结果统计的“实伤”扣除过量伤害；飘字显示本次攻击的原始伤害。

默认连段示例：

| 步骤 | 剩余 AP / RP | 三敌燃烧层数 |
|---|---|---|
| 蓄能 + 火墙 | 5 / 2 | 2 / 2 / 2 |
| 爆燃 | 4 / 2 | 4 / 2 / 2 |
| 火星 | 3 / 2 | 4 / 6 / 6 |
| 火葬 | 1 / 2 | 8 / 12 / 12 |
| 魔力恢复 + 炼狱 | 0 / 1 | 9 / 13 / 13，即时引爆 |
| 敌人行动，第一次攻击触发炎盾 | 0 / 0 | 10 / 13 / 13 |
| 回合末 | 0 / 0 | 清空，全敌击败；法师剩 78 生命 |

策略取舍：蓄能和回能占用 RP，使本轮仅能抵挡一次普攻；关闭蓄能可多次防守。是否胜利之外，比较剩余生命、回合数和峰值层数，避免以刷高伤害替代策略判断。

## 7. 美术与音频
- 暖灰纸底、黑色剪影、朱红火焰；不同体型区分单位。战场图与角色透明图集已落地，提示词见 [art-prompts.json](art-prompts.json)。
- 1600×900 设计画布，当前窗口 1440×810；适配缩放和黑边。战术字段由原生控件绘制，不把效果图当界面贴图。
- 普通伤害小号暖白数字；引爆大号橙色数字和纸屑粒子；燃烧显示层数及预计伤害；被动使用蓝色文字。减少依赖颜色，保留文字。
- 施法/敌人攻击留可辨识节拍，群体命中和叠层快速连续播放；爆炸短震动，减弱闪震关闭镜头与角色位移。
- 当前 4 个原创合成提示音：施法、受击、引爆、增益。无背景音乐、骨骼或逐帧动作；这些需在玩法成立后制作。

## 8. MVP 范围与验收
| 层级 | 内容 |
|---|---|
| 本版必须 | 一法师七主动三被动、三普攻敌人、顺序/条件/目标编辑、完整胜败、日志、反馈、战术保存、原生编辑场景 |
| 下一版重要 | 一组有明显敌情差异的遭遇；规则选中原因更直观；调优默认节奏；少量法术变体 |
| 以后 | 多英雄、反击/追击事件、双条件 AND、遗物与路线、局外解锁、手柄、完整音画、Steam 发行 |

完成 = 玩家能修改至少一条规则并观察差异，解释一次条件跳过和一次 RP 消耗，打完胜负两种结果，返回重试，保存后关闭重开恢复。

本版炎盾是“攻击前防护并挂火”，不是受伤后的反击。反击是后续独立时机；新增时应禁止反击互相递归，每个事件窗口限制反应数。此版本未实现该能力。

## 9. 里程碑与制作策略
| 阶段 | 范围 | 验收门槛 |
|---|---|---|
| M0 规则原型 | 确定性战斗和条件资源边界 | 自动规则测试、胜败可达、无负资源 |
| M1 当前体验版 | 可编辑战术、剪纸画面、反馈和保存 | 原生输入流程通过，用户能指出想继续调整的战术 |
| M2 小型纵切 | 少量差异敌情与构筑奖励 | 同一套战术不通吃；数个玩家无需讲解能完成循环 |
| M3 买断产品 | 扩内容、完善输入和存档、发行准备 | 性能/兼容/恢复及完整流程验收，再确定上线计划 |

单人 + AI 的制作顺序：先让一套构筑有取舍，再增加第二个流派；优先复用角色动作和少量场景，把成本花在技能效果辨识与战术反馈。当前不承诺正式版工期或内容量。

试玩先验证三件事：能否在一分钟内理解“条件”与“目标”的差别；调整后能否解释结果；是否愿意立即试第二套组合。技术测试通过不能替代这些判断。
