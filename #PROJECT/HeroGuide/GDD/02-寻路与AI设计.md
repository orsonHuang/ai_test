# 02 · 寻路与 AI 设计

> **本文档是整个项目的技术核心。** 寻路逻辑直接决定玩法是否成立。

## 1. 设计原则

### 1.1 勇者 AI = 纯最短路径

勇者的寻路算法是**纯粹的几何最短路径**（A* 算法），不考虑任何危险因素：

- ❌ 不会避开陷阱
- ❌ 不会避开守卫视野
- ❌ 不会主动寻找守卫背后
- ✅ 只认"障碍"（不可通行格）和"可通行格"
- ✅ 只追求路径长度最短

### 1.2 关键分类：障碍 vs 致命

```
障碍（不可通行，影响寻路）：
  → 墙壁、石头（玩家放置）、守卫本体、魔王格、边界

致命（可通行，但不影响寻路，勇者会走进去）：
  → 陷阱、守卫视野格、死胡同
```

**这是整个游戏的核心设计张力**：勇者的寻路算法把"致命格"视为普通可通行格，所以最短路径可能直接穿过陷阱或守卫视野。玩家必须用石头把"致命捷径"变成障碍，迫使算法重新计算。

## 2. 寻路算法详述

### 2.1 算法选择

**A\* 算法**，网格制，4 方向移动（上下左右，不支持斜向）。

- 网格规模小（8×8 ~ 12×12 = 64~144 格），A* 毫秒级完成
- 每次玩家放置/移除物品需重算，性能无压力
- 实现简单，可调试

### 2.2 格子权重

| 格子类型 | 寻路权重 | 说明 |
|----------|----------|------|
| 普通地面 | 1 | 标准通行成本 |
| 陷阱 | 1 | **与普通地面相同**（勇者不知道危险） |
| 守卫视野格 | 1 | **与普通地面相同**（勇者不知道危险） |
| 守卫背后格 | 1 | 与普通地面相同（经过触发击杀） |
| 传送门入口 | 1 | 特殊处理（见 2.4） |
| 墙壁 | ∞ | 不可通行 |
| 石头 | ∞ | 不可通行 |
| 守卫本体 | ∞ | 不可通行 |
| 魔王格 | ∞ | 目标格，到达相邻格即触发胜利 |

> **核心规则**：陷阱和守卫视野的权重 = 1 = 普通地面。这意味着如果最短路穿过它们，勇者会毫不犹豫地走过去送死。

### 2.3 守卫的正/背逻辑

这是最关键的设计点。**勇者不会主动绕后**，但守卫背后格是安全可通行的。

```
场景：守卫挡在必经之路上

             [视野]         ← 可通行但致命（勇者会走进来死）
             [守卫]            ← 障碍（不可通行）
        [安全][背后][安全]     ← 可通行且安全（经过触发击杀）

如果地图拓扑如下：

  起点 ──→ [视野] ──→ [守卫] ──→ 魔王     ← 最短路 = 3 步，但会死
  起点 ──→ [绕路] ──→ [绕路] ──→ [背后] ──→ 魔王  ← 安全路 = 4 步

勇者选 3 步的（因为更短）→ 死
玩家任务：在 [视野] 格放石头 → [视野] 变障碍 → 勇者被迫走 4 步路 → 安全
```

**守卫背后的触发**：
- 勇者走到守卫背后相邻格 → 触发击杀动画 → 守卫消失 → 该格变为普通地面
- 击杀动画播放期间勇者暂停移动
- 动画结束后勇者继续沿路径行走

> **注意**：勇者不会"为了走背后而绕路"。他只在玩家堵住了所有更短的危险路径后，才会走经过背面的路。

### 2.4 传送门的寻路处理

传送门是特殊的可通行格，寻路算法需要特殊处理：

```
传送门 A (x1,y1) ↔ 传送门 B (x2,y2)

勇者走到 A 格时：
  - 下一步不是走到 A 的相邻格，而是直接出现在 B 格
  - 从 B 继续寻路
  - 传送不消耗额外步数（A 算 1 步，B 算 0 步）

A* 处理方式：
  - A 格的"邻居"除了上下左右，额外加上 B 格
  - A→B 的边权重 = 0（不增加路径长度）
  - B 格本身的进入成本 = 已在 A 格时支付
```

**寻路优化**：计算最短路径时，算法会比较"走传送门"和"走普通路"哪个更短，自动选择更优方案。

## 3. 路径实时更新流程

```
玩家放置/移除物品
      ↓
更新网格状态（格子类型变化）
      ↓
重新运行 A* 寻路（勇者位置 → 魔王相邻格）
      ↓
路径存在？
  ├── 是 → 更新虚线显示（绿色/黄色）
  │     ├── 路径经过致命格？→ 虚线在致命段标红 + 警告图标
  │     └── 路径全安全？→ 虚线全绿
  └── 否 → 虚线消失 + 显示"无可达路径"提示 + 禁用出发按钮
```

### 3.1 虚线路径的颜色编码

| 颜色 | 含义 |
|------|------|
| 🟢 绿色虚线 | 路径安全，可放心出发 |
| 🟡 黄色虚线 | 路径存在但经过致命格（陷阱/视野），出发会失败 |
| 🔴 红色（无虚线） | 无可达路径 |

**黄色路径的 UX 设计**：虚线在安全段为绿色，在致命段变为红色并闪烁，同时在致命格上方显示危险图标（⚠️ 陷阱 / 👁️ 守卫视野）。玩家可以直观看到"这段路会死"。

> 这让玩家在准备阶段就能判断"当前布局能不能通关"，而不需要试错。

## 4. 执行阶段的行走逻辑

### 4.1 基本行走

```
准备阶段确定的路径 = [格1, 格2, 格3, ..., 格N]

执行阶段：
  for 每个格 in 路径:
      勇者移动到该格（动画 200ms）
      检查该格事件:
          - 陷阱 → 播放死亡动画 → 失败结算
          - 守卫视野 → 播放被抓动画 → 失败结算
          - 守卫背后相邻 → 播放击杀动画 → 守卫消失 → 继续
          - 传送门 → 播放传送动画 → 勇者瞬移到出口 → 继续
          - 魔王相邻格 → 播放击杀魔王动画 → 胜利结算
```

### 4.2 勇者移动速度

- MVP：固定速度，每格 200ms
- 支持加速播放（点击 2x）
- 击杀/传送/死亡动画单独时长（不计入行走速度）

### 4.3 死胡同的执行期判定

死胡同不是准备阶段判定的，而是执行阶段动态判定：

```
勇者走到格 X：
  检查 X 的相邻格（排除来路）：
      有可通行格 → 继续走（但这不应该发生，因为路径是预先算好的）
      无可通行格 → 死胡同 → 失败
```

> 实际上，由于路径是准备阶段用 A* 预算的，如果路径存在就不会走到死胡同。死胡同失败主要发生在**路径终点不是魔王**的情况——即玩家用物品堵出了一条通往死胡同的最短路。

## 5. MVP 范围内的寻路边界

### MVP 实现 ✅

- 纯最短路径 A*（4 方向）
- 陷阱 = 可通行致命格
- 静态守卫视野 = 可通行致命格
- 守卫背后 = 可通行安全格（触发击杀）
- 传送门特殊寻路处理
- 实时路径重算 + 颜色编码虚线

### MVP 不实现 ❌（V2 演进）

| 功能 | V2 设计方向 |
|------|------------|
| 巡逻守卫 | 视野随时间变化，引入时序谜题（见下方附录） |
| 飞龙 | 固定传送点，踩上即飞到指定位置 |
| 权重差异格 | 如沼泽（通行成本 2）、冰面（滑行）等 |
| 动态障碍 | 执行阶段会变化的门/桥 |

## 6. 附录：V2 巡逻守卫的时序寻路设计（预留）

巡逻守卫引入"时间"维度，寻路需要从纯空间扩展到时空。

### 6.1 时序模型

```
勇者速度：0.5 秒/格
巡逻守卫：固定路线循环，每 2 秒移动 1 格 + 转身

时间 t 时，勇者位置 = 路径第 (t / 0.5) 个格
时间 t 时，守卫位置 + 朝向 = 巡逻路线第 (t / 2) 个状态

安全判定：
  勇者在时间 t 到达格 X
  守卫在时间 t 的视野是否覆盖 X？
    否 → 安全
    是 → 致命
```

### 6.2 准备阶段的时间轴 UI

```
┌─────────────────────────────┐
│        地图区域              │
│   (虚线路径 + 巡逻轨迹)      │
│                             │
├─────────────────────────────┤
│ ◄ t=0  t=1  t=2  t=3 ►     │  ← 时间轴拖拽
│     [▶ 预览执行]            │
└─────────────────────────────┘
```

玩家拖动时间轴 → 地图上巡逻守卫的位置/朝向实时变化 → 虚线路径上的"危险窗口"动态标注。

### 6.3 危险窗口标注

系统自动分析路径上每格的到达时间，与守卫时序比对：

- 安全时段 → 绿色标记
- 危险时段 → 红色标记 + 警告

玩家通过调整物品（增加路径长度 = 延迟到达时间）来错开危险窗口。

> 以上为 V2 预留设计，MVP 不实现。但 MVP 的架构需为时序扩展预留接口（如路径计算返回 `[{x, y, t}]` 而非仅 `[{x, y}]`）。
