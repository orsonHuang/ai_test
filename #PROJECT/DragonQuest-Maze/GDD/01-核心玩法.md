# 核心玩法设计文档

## 1. 游戏概述

**项目名称**：勇者斗恶龙迷宫（暂定）  
**游戏类型**：回合制解谜迷宫  
**目标平台**：微信小游戏  
**画面风格**：勇者斗恶龙 / 鸟山明式明亮卡通奇幻风  
**核心体验**：观察 → 规划 → 绕后 → 击杀

玩家扮演一名持剑勇者，在由石墙围成的迷宫中移动。迷宫中布置了会面朝固定方向巡逻的守卫（龙、恶魔），玩家不能从正面进入守卫的视线格，必须绕到守卫背后将其击晕，才能安全通过。利用传送门抄近路、绕开正面防线，最终走到魔王背后，完成致命一击。

---

## 2. 核心循环

```
进入关卡 → 观察守卫朝向与巡逻路线 → 规划移动路径
    ↓
利用传送门 / 绕后击晕守卫 → 打开通路
    ↓
抵达魔王背后 → 触发击杀动画 → 过关结算
```

单次操作：点击 / 滑动方向 → 勇者向该方向移动 1 格（回合制，每移动 1 格算 1 步）。

---

## 3. 基础规则

### 3.1 移动

- 棋盘为固定大小的网格迷宫（推荐 10×10 / 12×12 / 15×15）。
- 每回合玩家选择上下左右一个方向，勇者移动 1 格。
- 不能走出边界、不能穿过石墙、不能进入关闭的障碍格。
- 支持撤回上一步（可选辅助功能）。

### 3.2 守卫机制

**两种守卫**：

| 类型 | 外观 | 视野 | 特殊 |
|------|------|------|------|
| 龙守卫 | 红鳞双翼龙 | 正前方 3 格直线 | 被击晕后倒地，头上冒星星 |
| 恶魔守卫 | 紫皮持叉恶魔 | 正前方 2 格 + 左右 1 格（扇形） | 击晕后恢复时间更长 |

**守卫规则**：

1. 守卫具有固定朝向（上 / 下 / 左 / 右），部分关卡会按固定路线巡逻。
2. 玩家**不能进入守卫当前面向的视野格**；若进入，游戏失败（被抓住）。
3. 玩家**从守卫背后一格移动到守卫所在格**时，触发击晕，守卫倒地并失去阻挡与视野。
4. 击晕后守卫经过 N 回合（如 3 回合）会恢复；玩家需在恢复前通过。
5. 某些关卡中，魔王本身也视为一个不可正面接近的"超级守卫"，必须从背后击杀。

### 3.3 传送门机制

- 传送门成对出现，入口 A ↔ 出口 B，双向传送。
- 玩家踏入传送门入口格时，立刻传送到对应出口格，不消耗额外步数（或只算 1 步）。
- 传送门出口不能是墙或守卫格；若出口被守卫视野覆盖，则传送后玩家需要立即应对。
- 传送门可用来：跨越石墙、绕到守卫背后、快速接近魔王。

### 3.4 魔王机制

- 魔王位于关卡目标点，拥有固定朝向（通常面向入口方向）。
- 玩家**不能从正面进入魔王所在格**或魔王视野格。
- 玩家**从魔王背后一格移动到魔王格**时，触发击杀动画，关卡胜利。
- 击杀动画：勇者冲刺 → 挥剑 → 屏幕闪白 → 魔王倒下 → 宝箱弹出。

---

## 4. 胜负条件

| 结果 | 条件 |
|------|------|
| 胜利 | 从背后击杀魔王 |
| 失败 | 进入守卫 / 魔王正面视野格 |
| 失败 | 步数超过关卡限制（可选） |
| 失败 | 被困死，无可行移动 |

---

## 5. 关卡设计框架

### 5.1 难度曲线

| 关卡段 | 机制组合 | 难度 |
|--------|----------|------|
| 1-5 关 | 纯迷宫 + 少量石墙 | 教学 |
| 6-15 关 | 加入 1 个龙守卫 | 初级 |
| 16-30 关 | 加入传送门 + 多个守卫 | 中级 |
| 31-50 关 | 恶魔守卫 + 巡逻 + 恢复机制 | 高级 |
| 51+ 关 | 复合机关 + 步数限制 + 多魔王 | 大师 |

### 5.2 关卡验证

每关设计完成后必须通过求解器验证：

- 是否有解
- 最短步数（作为难度指标）
- 分支数（玩家选择空间）
- 是否必须击晕特定守卫才能通关
- 是否必须使用传送门才能通关

求解器采用 BFS / A* 在状态空间 `(玩家位置, 守卫状态集合)` 上搜索。

## 6. 操作与交互

### 6.1 移动端操作

- **点击目标格**：勇者沿最短路径自动移动 1 格（推荐）。
- **滑动手势**：上滑 / 下滑 / 左滑 / 右滑移动 1 格。
- **长按守卫**：显示其视野范围（辅助）。
- **撤回按钮**：撤销上一步移动。

### 6.2 微信适配

- 支持竖屏单手操作。
- 虚拟摇杆或点击式移动，避免遮挡棋盘。
- 排行榜、好友对战、分享复活等微信开放能力接入。

## 7. 扩展机制（后续版本）

| 机制 | 说明 |
|------|------|
| 钥匙与门 | 必须先取得钥匙才能打开通往魔王区域的门 |
| 陷阱地板 | 踩上后触发警报，守卫朝向转向玩家 |
| 隐身斗篷 | 1 回合内可正面穿过守卫视野 |
| 石块道具 | 玩家可推动石块阻挡守卫视野 |
| 多勇者切换 | 同时控制 2 名勇者配合解谜 |
| Boss 多阶段 | 魔王会周期性转身，玩家需把握时机 |

---

## 8. 性能与包体约束

- 主包 ≤ 4MB，总包 ≤ 20MB。
- 关卡数据使用 JSON，每关数据量 < 5KB。
- 素材优先 WebP + TexturePacker 打包。
- 迷宫规模控制在 20×20 以内，保证 BFS 求解器毫秒级响应。

---

## 9. 设计原则

1. **一屏一谜**：每关只教一个核心技巧，避免信息过载。
2. **失败即时反馈**：进入视野格立刻提示失败，允许快速重开。
3. **多解法鼓励**：除最优解外，允许玩家用不同顺序击晕守卫过关。
4. **视觉语言一致**：危险区域（视野）用红色半透明提示，安全绕后用绿色脚印。
