# 存档、事务与验收

状态：v1 目标。核心要求：离开游戏不会重抽内容，也不会重复扣费、战斗或领取奖励。

## 1. 保存内容

| 范围 | 最小字段 |
|---|---|
| 版本 | schema_version、rules_version、内容版本、写入时间 |
| 远征 | run_id、seed、各随机通道状态、当前区域、已访问/揭示区域 |
| 区域 | 活动生成快照、AP、活动完成ID、副本胜利次数、首次战斗成长是否已领 |
| 小队 | 等级、成员ID/阵位、当前HP、装备实例、技能/战术、下一战修正 |
| 奖励 | 套装已获部位账本、待领取reward_id、已应用结果ID |
| 战斗 | battle_id、入场快照、已付费标记、规则版本、回放事件或可重建进度、最终结果是否应用 |
| 局外 | 图鉴、战绩、设置、已结算run_id |

存到user://，不写到res://。不在保存文件放开发机器绝对路径。M1只承诺同一桌面版本续档，HTML与Godot互转不在范围内。

## 2. 原子提交模型

确认活动时：校验状态/资源 → 生成唯一activity_id → 扣AP/金币并记录锁定输入或种子 → 原子保存 → 才开始表现。

战斗可预计算确定性事件流；恢复时以原始规则版本、快照和种子重建并验证结果，播放从保存游标继续且默认暂停。不能再次执行入场扣费。若按回合实时推进，保存完整BattleState，同样保证每个结算事件只应用一次。

领奖时：构造包含新装备/账本/成长/生命与已应用reward_id的完整新状态 → 原子保存 → 切回区域。奖励是否已领不依赖按钮是否消失。保存失败要提示并保留未提交状态，不能对用户显示“已保存”。

使用临时文件＋原子替换、保留最近有效备份、读取校验与版本迁移。新规则不能解释旧存档时保留原文件，提示重新开始或采用明确迁移；不得静默删档。

## 3. 必测恢复位置

| 场景 | 验收 |
|---|---|
| 揭雾后退出 | 活动/候选/商店不变 |
| 确认副本后退出 | AP恰扣一次，重复挑战倍率相同 |
| 战斗中任意回合退出 | HP、状态、冷却、意图、目标与最终结果一致 |
| 胜利待领奖时退出 | 恢复同一装备，不再战斗或增加成长 |
| 领奖后立刻退出 | 物品、套装账本、金币、等级各变一次 |
| 付费事件分支/招募时退出 | 费用与结果同在或同不在，无半次操作 |
| 换装后退出 | 属性一致，无回血漏洞 |
| 魔王结果页反复打开 | 一局仅记一次通关 |
| 写入失败/文件损坏 | 可理解的提示，可恢复备份，不假称成功 |

双击、连续快捷键、重复UI信号也要执行以上幂等检查。日志必须区分“玩家保存后恢复”和“测试重建”，不把两次观察当两次远征。

## 4. 记录方式

测试记录带：构建版本、规则版本、种子、配置、操作、预期、实际、证据路径、未验证项。技术回归、真人试玩、发布检查分开记录。MVP既有通过记录只对其旧规则有效；本轮文档核验报告不等同上述运行测试已通过。
