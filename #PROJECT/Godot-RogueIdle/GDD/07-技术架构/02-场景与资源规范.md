# 场景与资源：交付后仍可在编辑器修改

状态：v1 目标。下列是建议场景职责，不是现有文件清单。具体新建到哪个工程由实施任务确定。

## 1. 场景职责

| 场景 | 必须可选中编辑的节点/资源 | 运行态 |
|---|---|---|
| ExpeditionMap | 地图容器、区域模板、图例、信息栏、活动面板 | 当前位置、可达标记、迷雾 |
| RegionTile | 多边形源资源、标签锚点、首领图标、选中描边 | 是否揭示、是否可进入 |
| PartyPanel | 三成员槽、生命/护盾、阵位调整入口 | 绑定队伍实例 |
| LoadoutPanel | 三装备槽、技能/被动/策略选择控件 | 装备对比、待应用配置 |
| BattleView | 行动条、敌我容器、控制栏、意图和日志 | 战斗事件播放 |
| UnitCard | 头像、生命、护盾、状态与意图标签 | 来自战斗快照 |
| ActivityDialog | 成本标签、选项模板、确认/返回 | 当前活动事务 |
| ResultView | 战报、奖励卡模板、继续/重开 | 唯一结果ID |

静态UI使用Godot原生Control、容器、按钮、标签和Theme；不得把全部UI在_ready中临时拼出，或烘焙成不可逐元素改动的大图。动态卡片/单位来自PackedScene模板，参数来自公开Resource或@export。

## 2. 地图特殊约束

不规则多边形可以程序绘制，但源顶点、标签位置、可见轮廓/迷雾样式必须在Inspector资源中可改，并有编辑预览。通行与邻接来自显式ID列表，不从多边形屏幕位置临时推断。

点击区域按多边形命中，不用大矩形覆盖邻区。图标不能吞掉地图主体的点击或导致同次操作移动两次。缩放只改表现，不改变坐标数据或地图逻辑。

## 3. 保存和可编辑验收

- 选中代表性节点，调整标签、布局或公开参数，保存并关闭重开，检查值仍在。
- 保留子场景实例关系、原生信号连接、资源引用和正确owner，不为保存而递归拆开实例。
- 运行验证该参数确实影响界面/玩法，脚本不会无条件覆盖用户配置。
- 记录正确工程路径、引擎版本、场景、调整项、截图和结果。
- MCP如果可用，先核对工程/场景与插件服务版本，再用编辑器API和可用UndoRedo；不能只改Remote运行树就称源场景已编辑。
- 工具缺失不妨碍编写资源或脚本，但编辑器保存重开与可视化验收须明确未完成。

正式导出前关闭开发调试/MCP入口；本条是发布验收，不要求本次文档任务安装或升级任何工具。
