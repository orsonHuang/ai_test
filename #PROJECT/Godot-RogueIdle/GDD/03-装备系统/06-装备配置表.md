# 装备配置与数据归属

状态：v1 目标。CSV用于评审与导入源，Godot运行使用自定义 Resource，不人工维护两份冲突的平衡表。

| 配置 | 字段/引用 | 编辑源 |
|---|---|---|
| 部位数值 | slot、基础属性、每区域档成长 | [equipment.csv](../data/equipment.csv) |
| 套装 | set_id、piece_count、effect_key、value、触发次数上限、治疗量上限 | [sets.csv](../data/sets.csv) |
| 词条 | affix_id、stat、value、weight | [affixes.csv](../data/affixes.csv) |
| 品质与掉落 | 精良倍率、首领品质权重、部位保护 | [rules.csv](../data/rules.csv) + [掉落规则](01-装备基础.md) |
| 模板 | template_id、slot、set_id或空、图标、文本ID | 3套×3槽＝9套装模板＋3基础散件模板 |
| 运行实例 | 唯一ID、模板、区域档、品质、词条ID、来源奖励ID | 存档，不写回配置资源 |

装备基础属性＝部位基础值＋部位每档成长×(区域档−1)，再乘品质倍率，对每个正数属性取最近整数；最后加词条。零值属性保持零。词条与套装固定效果不受品质和档次放大。

模板ID：thorn_weapon / thorn_armor / thorn_charm，同理storm、ember；散件为plain_weapon / plain_armor / plain_charm。M1三套同槽基础属性一致，区别由套装和词条形成。

Inspector实验调整使用资源副本；正式数值变更须回写CSV并重建资源。生成过程记录数据版本并校验引用，不能把 .tres 与CSV分别当作权威来源。

旧“套装作为概率词条附加”结构撤销：身份属于模板。当前不放入未定义的强化/重铸字段，避免误认为这些系统仍必做。
