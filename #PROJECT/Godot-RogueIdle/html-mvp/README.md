# 雾境远征 · HTML 玩法 MVP

2026-10-04。单文件、离线可玩的远征原型，用于验证「有限区域行动预算 → 刷首领构筑 → 三人自动回合战斗」。正式项目仍以 Godot / Steam 为目标。

## 运行

直接用 Edge / Chrome 双击打开 `index.html`，无需安装依赖或联网。也可以在本目录运行 `python -m http.server 8767 --bind 127.0.0.1`，打开 `http://127.0.0.1:8767/`。

存档自动保存在当前浏览器。刷新后从出发界面选择「继续上次远征」；恢复中的战斗默认暂停。不同浏览器、不同网址、直接打开文件的存档分别保存。新远征覆盖上一局前会确认。浏览器禁止存储时，底部会明确提示。

## 第一局体验路线

1. 选择「坚守反击」与修女，点击启程。
2. 进入荆棘林地：招募同伴 1 时段、打两次副本 4 时段、休整 1 时段。领取装备时点击「装备」，激活两件套。
3. 前往苔石矿谷，继续刷同套装，凑齐三件。根据生命决定刷怪、奇遇或休整。
4. 经霜落高地前往魔王城。不同套装的单件装备不一定值得拆掉已激活的套装。
5. 攻打魔王；查看反击、伤害、灼烧与治疗统计。下一局换游侠与猎风套，或引火术与余烬套。

上述为体验建议，不保证任意操作都能通关。原型数值偏宽松，优先让玩家看见构筑效果。

## 当前规则

| 系统 | 实现 |
|---|---|
| 地图 | 9 个连续不规则地块：村庄 + 7 探索区域 + 魔王城。每局经过 3 个探索区域，可相邻向前选择，不能回退或横移 |
| 迷雾 | 当前区域及直接相邻区域揭雾；首次揭示生成奇遇与招募候选，后续查看不重抽 |
| 首领情报 | 起始可查看古树守卫、熔火祭司、白狼领主与最终目标，显示套装用途 |
| 区域预算 | 每区 6 时段；不结转，可提前离开。移动和整备免费，移动不回血 |
| 活动费用 | 副本 2；宝箱、奇遇、巡游敌人、招募、休整、行商补给各 1 |
| 活动次数 | 宝箱、奇遇、巡游敌人、招募每区一次；副本、休整、补给可以重复 |
| 生命资源 | 休整恢复全队最大生命的 50%；行商补给另付 25 金币，恢复 80% |
| 队伍 | 主角 + 最多 2 随从；修女治疗、游侠标记、卫士为前排加盾。队满可替换随从，不能替换主角 |
| 战前配置 | 3 主动、3 被动，主角 3 装备槽，免费换装与阵位调整。增加最大生命不会凭空回血 |
| 套装 | 荆棘：受击反击 → 反击加盾；猎风：对标记增伤 → 追击；余烬：攻击附灼烧 → 灼烧治疗 |
| 掉落保护 | 首领每次必掉所属套装。按本局已获得部位，优先补缺；首次三件覆盖三个槽位 |
| 装备变化 | 部位、区域等级、普通/精良品质、坚韧/锋利/迅捷词条影响属性 |
| 自动战斗 | 回合开始按速度排列，活着的单位每回合行动一次。速度不增加行动次数。可暂停、1/2/4 倍速、快速结算 |
| 首领意图 | 第 2 回合蓄力，第 3 回合横扫全队，三回合循环；最终战影卫攻击后排 |
| AI | 修女按血量治疗；游侠先标记；卫士护住前排；坚守对齐横扫回合；其他技能就绪时自动用 |
| 成长 | 每两场胜利升一级，最多 5 级。升级补充成长的 14 生命，不全量回复 |
| 结算 | 胜利后倒下成员以 1 生命起身；全灭或超过 30 回合结束远征。击败魔王通关 |
| 持久化 | 存地图、队伍、装备、随机状态、已扣费用与战斗播放进度。奖励只结算一次 |

伤害采用简化公式：`max(1, round(攻击 × 技能倍率 - 有效护甲))`；护盾先吸收，标记降低 4 护甲，灼烧为每层 7 点真实伤害，最多三层。主动技能冷却 2 回合意为施放后两次自身行动不可再用。

## 范围与后续验证

本版完成完整可玩闭环。地形与副本位置固定；奇遇、招募、装备有随机变化。区域目前提供完整活动菜单，尚未做随机活动组合密度。主角与随从使用内嵌 SVG 示意美术，没有外部素材、音效、网络请求、支付或账号。

所有首领暂共用蓄力/横扫骨架，依靠区域成长、套装掉落和最终战影卫区分；独有首领机制、更多事件、长期横向解锁、装备强化与 Godot 移植属于后续工作。未改动 `cat-idle/` 工程，也不代表原 Godot 计划已完成。

优先观察玩家是否会为两件套主动规划路线、是否愿意牺牲一次刷装来休整、是否能从战报理解阵位和随从配合。建议先真人试玩这三点，再扩内容量。

## 验证

- `node test-engine.cjs`：11 组状态/战斗规则回归；另用 30 个种子 × 3 个构筑进行准备充分的完整远征模拟。当前 90 局全部通关，这是可达性检查，不是平衡性或难度的真人结论。
- `node test-browser.cjs`：需要 Playwright；默认使用本机 Edge，可通过 `BROWSER_PATH` 指定 Chromium 路径，`MVP_URL` 指定地址。
- 实际浏览器验证：1440×1000 桌面完整通关、390×844 窄屏无横向溢出、招募/宝箱/事件/整备/阵位/提前离开、战斗刷新续档、离线文件启动；无页面脚本或资源错误。
- 截图生成在 `test-output/`，已忽略，不作为运行依赖。

### 文件

- `index.html`：全部界面、SVG 美术、数据、模拟逻辑与存档。
- `test-engine.cjs`：无第三方依赖的规则与通关检查。
- `test-browser.cjs`：实际点击操作、截图、存档与响应式检查。

MVP 完成标准：玩家能从村庄开始，选择分支、消耗区域预算、招募最多两人、凑出套装、观察自动战斗、通关或失败后重新开始。以上均已实现并验证。
