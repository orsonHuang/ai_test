# M2 Demo：验证重复游玩的理由

状态：未启动；前置M1验收通过。设计依据：[GDD](../GDD/README.md)、[验证清单](../GDD/08-待讨论问题.md)。

## 范围与优先级

| 优先级 | 内容 | 何时允许新增 |
|---|---|---|
| 必须 | 将事件由6扩到12，改善低价值选项；补关键音效与战报 | 玩家理解预算和构筑 |
| 必须 | 处理修女必选、无脑三刷、三件绝对支配等问题 | M1有同版本实测记录 |
| 重要 | 三种机制散件，测试两件＋散件的价值 | M1普通散件不足以支撑选择 |
| 重要 | 一个可选挑战；或首领组合变体 | 有玩家主动重复游玩 |
| 按证据选择 | 第二地图模板或随从专精，最多先做其一 | 明确重复问题来自哪一层 |
| 不做 | 新货币、强化重铸、批量新增职业 | 避免混淆核心验证 |

不把所有候选一并执行。先选最能修复已发现问题的一项，交付、测试、再决定下一项。

## Demo门槛

- [ ] 新玩家理解地图、预算与套装，不需要作者口头讲解才能完成首区。
- [ ] 至少20局完整记录，包含三预设及无修女队伍；保留种子与配置。
- [ ] 至少5名目标玩家各体验3局，记录重复兴趣和重复抱怨；不把小样本作市场结论。
- [ ] 有证据表明同一套装不是所有首领前唯一最好，失败能归因到可改变的配置/取舍。
- [ ] 熟悉后15–25分钟目标基本成立，统计阅读、决策、动画时间。
- [ ] 1280×720与1920×1080可读可操作，窗口缩放无主要遮挡。
- [ ] 支持中途退出续玩，跨当前测试版本的存档处理有明确策略。

达到门槛后才评估正式版内容预算与制作周期。Demo允许有限内容，不能把它直接改名正式版上架。
