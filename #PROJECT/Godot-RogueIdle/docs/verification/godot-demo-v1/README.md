# Godot Demo v1 实现与验收

日期：2026-10-05。目标工程：[cat-idle](../../../cat-idle/README.md)。设计依据：[GDD v1](../../../GDD/README.md)。这份记录反映引擎实现，不将 HTML 或文档静态检查算作 Godot 验收。

## 实现范围

7 个原生 `.tscn` 场景、211 个保存节点、53 份数据 `.tres` 加 1 份共享 Theme。主角与三种可招募随从、9 地区和 6 条完整路线、战争迷雾、每区 6 时段、首领/巡逻/营地/宝箱/招募/商人/事件、6 个事件、3 套装备、战前策略、全自动回合战斗、逐事件战报、最终战、续档与胜败重开均已接入。

未制作：M2 扩展事件、机制散件、局外图鉴与长期统计、最终角色美术/战斗动画/音频、手柄完整导航、Steam API、发布构建。所有流派强弱、路线公平性和乐趣仍需真人测试；一次真实输入通关只能证明该路径可完成。

旧 Battle 相关代码保留原样；主场景切换到 ExpeditionDemo，另修改了窗口布局设置和工程内 Python 忽略项。改动前文件有 [归档清单](../../archive/2026-10-05-before-godot-demo/ARCHIVE_NOTES.md)。独立候选 `rogue-idle-gd` 没有改动。

## MCP 操作证据

- 已连接用户正在打开的 cat-idle 编辑器，Godot 4.7.2-stable Steam。
- 复用已有 Godot AI 插件 2.9.0，HTTP MCP `127.0.0.1:8000/mcp`，会话 `cat-idle@65d1`，未安装或升级插件。初始化 serverInfo 报 3.4.7，而会话报告的 server/plugin 为 2.9.0；版本元数据不一致已记录，实际原生调用已验证，不据此宣称任意版本组合兼容。
- 项目本地 [mcp_bridge.py](../../../cat-idle/tools/mcp_bridge.py) 使用真实 JSON-RPC MCP，不通过生成截图冒充编辑器操作。
- 场景树由 `scene_manage`、`ui_manage.build_layout`、`node_create(scene_path)`、`node_set_property`、`script_attach` 等创建，原生节点变更进入 UndoRedo；源码与资源由 MCP 文件/脚本接口写入。
- 独立验证场景通过创建、修改、原生撤销/重做、保存、重开、运行和截图。见 `validation-native.json`、`validation-persistence.json`。
- 根节点 Playback Interval 在 Inspector 属性接口从 0.65 改为 0.45，保存、强制从磁盘重开、运行读值得到 0.45；结束后恢复 0.65，最终独立磁盘检查通过。见 [恢复与通关记录](resume-and-complete.json) 和 [结构检查](headless-scene-check.txt)。

## 验证结果

| 检查 | 结果与边界 |
|---|---|
| 原生场景结构 | 268 项检查通过；211 节点；三页、九地图块均保留 PackedScene 引用，非运行时临时搭页 |
| 规则回归 | [13 项、111 断言通过](rules-13-final.json)，覆盖选路/揭雾、时段、保底成套、招募与阵位、首胜升级、换装不回血、事件费用、确定性战斗、灼烧穿盾、CD、反击限次、战败、存档备份、测试配置隔离 |
| 配置一致性 | 53 份导入资源逐份与本轮 CSV 转换结果一致；英雄基础攻击为 24，测试强化没有写入配置文件 |
| 正常数值通关 | 实际鼠标点击：村庄→荆棘林地（招募、两次副本、休整）→苔石矿谷（副本、休整）→霜落高地（副本、休整）→魔王城；荆棘三件、主角＋修女＋游侠，魔王战 10 回合胜利 |
| 战中重启 | 在魔王战暂停并关停运行，重新启动、点击继续，战斗 ID `battle/castle/9`、回放进度与 4 件背包保持，恢复后暂停；结算后再次领取被拒绝 |
| 其他 UI | 固定种子 6 的宝箱、工坊事件、领取、背包选择换装、两次阵位交换、战术应用通过；种子和下拉选项使用测试接口设置，其余为实际按钮/鼠标输入，详见 [记录](secondary-ui-validation.json) |
| 画面 | 实际 1440×810 和 1280×720 截图检查；发现并修复地图锚点偏移与整备页底部溢出 |
| 日志 | 对应验收运行只出现 MCP helper 信息，无新的游戏运行错误；早期解析和测试失败保留在历史记录，不能把历史失败当最终结果，也未清除用户 Debugger 面板 |

早期测试中 `Resource.duplicate(true)` 未隔离外部单位资源，导致测试用攻击 2000 污染同一编辑器进程的测试缓存。已改为逐单位显式复制并重新读取磁盘基线，加入隔离回归；玩家运行进程、CSV 与磁盘 `.tres` 未使用该强化数值。初版损坏存档测试使用 `JSON.parse_string` 会记录预期解析错误，现改用 `JSON.parse` 返回值处理，回归不再产生该错误。
