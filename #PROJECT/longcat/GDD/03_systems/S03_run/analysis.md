## 问题：run 的关卡序列是固定的、随机的，还是带选择的？

状态：agent_proposal

### 广度分析

- **候选 A · 完全固定序列**：每次 run 的关卡与顺序完全相同。
  能提供：难度曲线可控；玩家可通过反复挑战提升（"我知道第 7 关怎么过"）；每日挑战可复现。
  但会带来：每次 run 体验雷同，重玩价值低；能力系统的意义被削弱（同样的关卡同样的解）。

- **候选 B · 完全随机抽取**：每次 run 从关卡池随机抽十几关。
  能提供：每次 run 都不同，重玩价值高。
  但会带来：难度曲线失控（可能连抽三关 Boss）；玩家无法形成"我在进步"的感知。

- **候选 C · 按难度带分层随机**：run 分若干段，每段从对应难度区间随机抽取，段内顺序固定为"递增 + 调剂"。
  能提供：难度曲线可控（分层保证）+ 每次 run 不同（随机保证）+ 能形成"我走到第几段"的进度感知。
  但会带来：实现比 A/B 复杂；需要处理关卡池不足时的回退。

- **候选 D · 玩家在关卡间做选择（路线图）**：每关后从 2–3 个候选关卡中选一个。
  能提供：Roguelike 的路线选择感；玩家可规避自己不擅长的类型。
  但会带来：增加决策负担；且本游戏的核心决策已经很重（空间推理），再加一层路线决策会过载。

### 深度分析

判断标准是：**run 需要同时提供"每次不同"和"我在进步"，这两者如何共存？**

候选 A 有"进步感"但无"新鲜感"；候选 B 有"新鲜感"但无"进步感"。

候选 C 是唯一兼顾的：**段（stage）作为进度刻度，段内随机作为新鲜感来源**。
玩家能说"我这次走到第 3 段了"——这是进度感；同时"第 3 段这次抽到的关跟上回不一样"——这是新鲜感。

这正好对应拆解中 Longcat 的章节化思路，也符合 Roguelike 的常规结构（如杀戮尖塔的分层随机）。

候选 D 被排除的理由值得说明：本项目的核心认知负荷已经很高（每关都要空间推理）。
再加一层"选哪条路"的决策，**认知过载**，且会稀释核心体验。路线选择属于 P2。

另外需要考虑：能力系统已经提供了"每局不同"的来源（不同能力组合 → 同一关卡不同解法）。
因此关卡序列的随机性可以是**次要的**，主要的新鲜感来自能力。这进一步支持候选 C（分层随机即可，不需完全随机）。

### 综合判断

**采用候选 C：run 的关卡序列按「难度带分层随机」生成——run 划分为若干段，每段从对应难度区间随机抽取关卡，段内按"递增 + 插入调剂关"编排。**
玩家可感知的进度刻度是"第几段"，而非"第几关"。
路线选择（候选 D）列为 P2。

## 问题：run 中断续玩如何实现，边界在哪？

状态：agent_proposal

### 广度分析

- **候选 A · 只在关卡之间保存**：玩家完成/困死一关后才写入存档。
  能提供：保存点状态简单一致（总是关卡开始处）。
  但会带来：玩家在关卡中途退出，本关进度丢失——而本关可能已经走了大半，挫败感强。

- **候选 B · 每一步都保存**：每次滑行后立即持久化。
  能提供：精确恢复到任意时刻。
  但会带来：写入过于频繁（小游戏存储 API 有性能与容量考量）；且"滑行中途"的恢复点意义不大。

- **候选 C · 在关卡内保存 body 快照，恢复时回到本关当前局面**：
  能提供：玩家回到游戏时，猫还是他离开时的形状；恢复后继续解同一关。
  但会带来：需要序列化 body 序列与 modifier 状态，存档结构略复杂。

- **候选 D · 只保存 run 元数据，恢复时重置本关**：
  能提供：存档最小最简单。
  但会带来：玩家在关卡中途退出后，本关从头开始——但命数不消耗。这个折中其实相当合理。

### 深度分析

判断标准是：**中断续玩要防止什么？**

它要防止的是**微信小游戏最致命的流失场景**：玩家打到一半被微信消息打断，退出后再也回不来。

因此核心需求是"**回来时我的 run 还在**"，而不是"回来时我的猫还是那个形状"。

候选 A 的问题：玩家在第 8 关走了 15 步（快填满了），被中断，回来后本关从头开始——这确实会烦，但**没有损失任何资源**（命没消耗、能力还在）。

候选 C 的收益：恢复到精确局面。代价是存档结构复杂化（要序列化 body）。

权衡后倾向候选 D/A 的折中：
- **run 级状态（命、能力集、段进度、当前关 ID）在每次状态变化时立即持久化** ← 这是必须的
- **关内进度（body 形状）不做持久化**，恢复时本关重置，**但不消耗命**

理由：关内重置的代价极低（本游戏一关 30 秒–2 分钟，且玩家已经理解地形，重走一遍更快），而持久化 body 会让存档结构显著复杂化，收益不成正比。

这个决策还有一个附加好处：**它天然阻止了"存档 Sl 大法"**——玩家不能通过反复退出重进来规避困死（因为本关会重置）。

不过要注意：如果玩家在本关已经消耗了命（困死过），那个命的消耗是已持久化的，不会被回滚。

### 综合判断

**采用 D/A 折中：run 级状态（命数、能力集、段进度、当前关卡 ID）在每次变化时立即持久化；关内进度（body 形状）不持久化，恢复时本关重置且不消耗命。**

- 恢复后的状态：命数与离开时一致、能力集完整保留、回到本关起点。
- 副作用（视为收益）：天然阻止通过退出重进来规避困死。

## 问题：run 结算应该展示什么，如何服务"下次能更远"？

状态：agent_proposal

### 广度分析

- **候选 A · 极简（到达第几段 + 最长猫长度）**：
  能提供：信息最少，结算最快。
  但会带来：玩家不知道自己为什么止步于此，无法形成改进方向。

- **候选 B · 结算 = 到达段数 + 最长猫 + 能力组合回顾 + 本次解锁的新能力**：
  能提供：完整回顾这次 run 的"身份"（我拿了什么能力），并明确指出获得了什么（解锁）。
  但会带来：信息偏多，需要设计信息层级。

- **候选 C · 结算 + 失败归因（在哪一关、因为什么困死）**：
  能提供：最强的学习反馈。
  但会带来："因为什么困死"需要分析玩家路径，实现复杂；且可能让玩家感到被指责。

- **候选 D · 结算 + 与历史最佳对比**：
  能提供：直接的进步感知（"我比上次多走了一段"）。
  但会带来：早期无历史数据时无意义；落差过大时反而打击。

### 深度分析

判断标准是：**结算的核心目的是什么？**

结算不是成绩单，是**"再来一局"的发射台**。它必须完成三件事：
1. 让我知道这次走到哪了（终点感）
2. 让我知道我拿到了什么（获得感）
3. 让我想再来一次（动机）

候选 B 覆盖 1 和 2，但缺 3。
候选 D 补上 3，但早期无数据。

正确做法：**B + D，但 D 做条件化**——有历史记录时展示对比，无记录时不展示（首局不打击新手）。

候选 C 的失败归因要谨慎。本游戏的失败是"我顺序错了"，玩家通常自己知道错在哪。**系统指出来反而可能让玩家觉得被说教**。而且实现需要分析路径，成本高。
不过有一个轻量版本值得做：**展示困死时的局面截图**（猫被自己堵死的形状）。这本身就是最直观的归因，零分析成本，且视觉冲击强。

### 综合判断

**采用 B + 条件化 D + 轻量归因：**
run 结算包含：
1. 到达的段数与关卡数
2. 本次 run 中最长的猫（长度 + 视觉展示）
3. 本次 run 的能力组合回顾
4. 本次解锁的新能力（获得感的核心）
5. 与历史最佳的对比（**有历史记录时才展示**）
6. 困死局面的截图（轻量归因，不做文字分析）
