## 问题：循环结构怎么定——单关独立，还是 run 连续挑战？

状态：agent_proposal

### 广度分析

- **候选 A · 单关独立**：每关独立进入、独立结算，无跨关结构。
  能提供：结构最简单，完全适配碎片时间（30 秒–2 分钟一关）；玩家随时可停；与社交比拼（每日挑战、排行榜）天然契合——比的就是单关成绩。
  但会带来：无 run 张力，无常驻目标，玩家玩完一关就可能退出。

- **候选 B · 以一次 run 为循环单位**：连续挑战多关直到命耗尽，run 内累积能力。
  能提供：张力（能走多远）、能力成长的载体、Roguelike 的"再来一局"驱动力。
  但会带来：概念阶段已决定不做 Roguelike 元层（命 + 能力三选一），此候选与概念定稿冲突。

- **候选 C · 双循环（单关 + 章节）**：单关是 30 秒–2 分钟的解谜循环，章节是 5–10 关的推进循环，提供"我到哪了"的进度感。
  能提供：短循环提供即时反馈，章节提供中期目标；玩家可随时停，不强制绑定 run。
  但会带来：章节本身不产生新机制，只是关卡的组织方式。

- **候选 D · 以「章节」为循环单位**：固定关卡序列，通关一章解锁下一章。
  能提供：清晰的进度感与内容消耗节奏。
  但会带来：无随机性，重玩价值低。

### 深度分析

判断标准是：**概念定稿要求"循环要短"且"差异在社交"，这两条能否同时满足？**

概念阶段已明确：不做 Roguelike 元层（无命、无能力三选一），差异化压在社交层（每日挑战、好友排行榜、分享奖励）。

候选 B 与概念定稿直接冲突，排除。

候选 A（单关独立）与社交比拼最契合——每日挑战比的就是单关成绩，排行榜比的也是单关最优解。但纯单关无中期目标，玩家容易"玩完就走"。

候选 C（单关 + 章节）补上了中期目标：章节给玩家"我到哪了"的进度感，章节内每关独立结算，不强制绑定。

**结论：候选 C 最优——单关独立结算（适配社交比拼），章节作为组织单位（提供中期目标）。**

### 综合判断

**采用候选 C：单关 + 章节双循环。**
- 单关（30 秒–2 分钟）：独立结算，是社交比拼的基本单位。
- 章节（5–10 关）：提供中期进度感，通关解锁下一章。
- 无 run 结构，无命数，无能力三选一。

## 问题：社交系统怎么设计——每日挑战、排行榜、分享奖励各承担什么角色？

状态：agent_proposal

### 广度分析

- **候选 A · 每日挑战为主**：全服同一关，比步数/覆盖率。
  能提供：每日回访理由，内容确定性（每天一关），社交话题（"今天那关你过了吗"）。
  但会带来：依赖后端/云开发；冷启动时无人比，体验空。

- **候选 B · 好友排行榜为主**：展示好友的关卡进度/最佳成绩。
  能提供：持续的社交对比动力，"超过某个人"的具象目标。
  但会带来：需要微信关系链；新用户无好友时效果为零。

- **候选 C · 分享奖励为主**：分享得道具/皮肤/提示。
  能提供：直接的裂变效果，拉新成本低。
  但会带来：分享疲劳（用户被各种小程序分享轰炸）；若奖励设计不当会变成功利性分享，伤害体验。

- **候选 D · 三者组合，各有分工**：每日挑战（回访）+ 排行榜（对比）+ 分享奖励（裂变）。
  能提供：完整的社交留存-裂变闭环。
  但会带来：MVP 工作量较大，需排优先级。

### 深度分析

判断标准是：**三个社交功能在留存漏斗中分别解决什么环节？**

| 功能 | 解决的环节 | 失效条件 |
|---|---|---|
| 每日挑战 | 长期回访（"明天还来"） | 无用户基数 |
| 好友排行榜 | 社交对比（"我要超过他"） | 无好友在玩 |
| 分享奖励 | 裂变拉新（"叫朋友来"） | 分享疲劳 |

三者不是竞争关系，是漏斗的不同环节：
- 分享奖励把人拉进来
- 排行榜让人有追赶目标
- 每日挑战让人每天回来

因此**三者全做，按阶段排优先级**：
- MVP：每日挑战（最小形态，本地关卡即可）+ 分享奖励（基础裂变）
- P1：好友排行榜（微信关系链接入）
- P2：群排行、赛季、UGC

### 综合判断

**三者组合，按阶段排优先级：**
- **MVP**：每日挑战（本地/CDN 关卡）+ 分享奖励（分享得提示/皮肤）
- **P1**：好友排行榜（微信原生能力）
- **P2**：群排行榜、赛季、UGC 编辑器

## 问题：单关结构怎么定——网格尺寸、步数、难度如何设计？

状态：agent_proposal

### 广度分析

- **候选 A · 小网格（4×5 ~ 6×7），单关 20–60 秒**：
  能提供：极快的反馈节奏，适配超碎片时间；求解器性能安全。
  但会带来：后期谜题深度不足（格数太少，路径变化有限）。

- **候选 B · 中网格（5×6 ~ 8×10），单关 30 秒–2 分钟**：
  能提供：参考拆解的实证区间（Longcat 平均 13 步、最长 21 步）正好落在此区间；求解器在 8×10 内可用穷举 + 剪枝。
  但会带来：8×10 的穷举求解需要较强剪枝，工程有挑战。

- **候选 C · 大网格（10×12 以上），单关 3–5 分钟**：
  能提供：谜题复杂度极高。
  但会带来：玩家无法在脑内推演完整路径，游戏从"解谜"退化成"试错"；且求解器指数爆炸。

- **候选 D · 动态网格（随章节推进变大）**：
  能提供：难度自然递增的观感。
  但会带来：网格变大 = 步数变多 = 疲劳而非难度（拆解实证：难度靠分支稀缺度不靠长度）。

### 深度分析

判断标准是：**什么约束是硬的，什么是可调的？**

来自拆解的两条硬约束：
1. **单次通关步数不超过 21–22 步**——超过就退化成试错
2. **求解器在 8×10 以上指数爆炸**——超过需改用启发式，失去"保证可解"的能力

这两条共同把网格锁在候选 B 的区间。

关键反直觉点：**难度不应该靠网格变大**。拆解实证显示 Longcat 后期步数停止增长，改用结构复杂度提升难度。网格尺寸应基本固定，难度靠墙的分布（分支稀缺度）调节。

### 综合判断

**采用候选 B：网格尺寸锁定在 5×6 ~ 8×10 区间，单关 30 秒–2 分钟。**
**网格尺寸不随难度递增**——难度靠木箱子的分布（分支稀缺度）调节，不靠放大网格。

## 问题：关卡总量与章节结构怎么定？

状态：agent_proposal

### 广度分析

- **候选 A · 少关卡 + 无章节**：50 关，线性推进。
  能提供：最快出 MVP。
  但会带来：无中期目标，无"我到哪了"的进度感。

- **候选 B · 中关卡 + 章节**：MVP 100–200 关，每章 8–10 关。
  能提供：章节进度感 + 足够的内容量；生成器保证长期供给。
  但会带来：需要手工关卡保证教学与第一印象。

- **候选 C · 大关卡 + 赛季**：500+ 关，按赛季更新。
  能提供：长期内容。
  但会带来：MVP 阶段严重超范围。

### 深度分析

判断标准是：**MVP 需要多少内容才能验证核心假设？**

本项目要验证的核心假设：**社交比拼 + 滑行填充谜题能否产生足够的回访与裂变？**

验证它需要的最小内容量：
- 手工 20–30 关（保证教学与第一印象）
- 生成 100+ 关（保证有东西可刷）
- 章节组织（每章 8–10 关，提供进度感）

长期需要 500+ 关，但**生成器的优先级高于关卡数量**——有了生成器，1900 关只是跑一晚上的事。

### 综合判断

**采用候选 B：MVP 手工 20–30 关 + 生成 100+ 关，章节组织（每章 8–10 关）。长期 500+ 关。**
**优先级声明**：关卡生成器的开发优先级高于关卡数量本身。

## 问题：收集系统做什么——能力池解锁，还是纯外观收集？

状态：agent_proposal

### 广度分析

- **候选 A · 能力池解锁（Roguelike 方向）**：每次 run 结束解锁新能力进入池子。
  能提供：长期的"变强"感知，每次 run 的多样性提升。
  但会带来：概念阶段已决定不做 Roguelike 元层，无能力系统。

- **候选 B · 纯外观收集**：猫咪皮肤、草地主题、蒲公英样式。
  能提供：情绪价值（"我在慢慢积累"），不引入数值。
  但会带来：纯外观的收集动力弱，缺乏功能性锚点。

- **候选 C · 外观 + 功能解锁混合**：外观为主，辅以功能性解锁（如新地形主题、特殊提示道具）。
  能提供：情绪价值 + 轻度功能变化，收集动力更强。
  但会带来：功能解锁若设计不当会破坏谜题纯粹性。

- **候选 D · 成就 + 图鉴系统**：关卡成就（三星、最少步数）+ 图鉴（解锁记录）。
  能提供：明确的收集目标，"全收集"的长期动力。
  但会带来：图鉴是纯展示，需要配合奖励才有驱动力。

### 深度分析

判断标准是：**概念定稿说"提供收集向内容，给予情绪价值"，什么收集形式最契合？**

概念阶段明确：不做数值系统，不做能力系统。因此候选 A 排除。

候选 B（纯外观）最安全但动力最弱。

候选 D（成就 + 图鉴）提供明确目标，且与社交比拼天然契合——排行榜比的就是成就。

**最佳方案：候选 D 为主 + 候选 B 为辅。** 成就/图鉴提供收集目标，外观作为成就的奖励。

### 综合判断

**采用候选 D + B：成就图鉴系统为主，外观收集为辅。**
- 成就系统：关卡三星评价、最少步数达成、章节全通。
- 图鉴系统：已解锁的猫咪皮肤、草地主题、蒲公英样式。
- 外观作为成就奖励，不提供任何数值优势。
- MVP 最小形态：关卡星级 + 基础图鉴页面。

## 问题：系统范围如何划定，MVP 包含哪些系统？

状态：agent_proposal

### 广度分析

- **候选 A · 最小系统集（滑行核心 + 关卡）**：只做 Longcat 本体。
  能提供：最快出可玩版本。
  但会带来：无任何差异化，验证的不是本项目。

- **候选 B · 核心 + 社交**：滑行核心 + 关卡 + 每日挑战 + 分享。
  能提供：完整验证"社交比拼 + 滑行填充"这个核心假设。
  但会带来：无收集系统，留存钩子单一。

- **候选 C · 核心 + 社交 + 收集**：五系统。
  能提供：完整闭环，可上线验证留存与裂变。
  但会带来：MVP 工作量最大。

- **候选 D · 六系统以上（+ 排行榜 + 赛季 + UGC）**：
  能提供：完整生态。
  但会带来：MVP 阶段严重超范围。

### 深度分析

判断标准是：**MVP 要验证的核心假设是什么，需要哪些系统才能验证？**

核心假设：**社交比拼 + 滑行填充谜题 + 收集情绪价值，能否产生足够的回访与裂变？**

验证它需要的最小系统集：
- 滑行核心（产生谜题）
- 关卡系统（提供内容 + 章节组织）
- 每日挑战（回访理由）
- 分享奖励（裂变拉新）
- 成就/图鉴（收集情绪价值，最小形态）

= 候选 C 的五系统，但社交与收集取最小形态。

### 综合判断

**采用候选 C，社交与收集取最小形态：**
MVP 包含五个系统——滑行核心、关卡、每日挑战、分享奖励、成就/图鉴（最小形态）。
好友排行榜归 P1，群排行/赛季/UGC 归 P2。
