## 问题：核心胜利条件，保留「填满全部格子」还是改成「收集后抵达终点」？

状态：状态：user_confirmed

### 广度分析

- **候选 A · 全覆盖（沿用 Longcat）**：必须填满每一个非墙格才能通关。
  能提供：谜题纯度最高、可解性可离线验证（本质是增量式哈密顿路径问题）、可批量生成、通关时"猫填满全屏"的视觉奇观最强。
  但会带来：一步走错就全盘皆输，容错极低；关卡一次性消耗，重玩价值弱。

- **候选 B · 收集后抵达终点**：收集完所有目标物后到达终点即可通关，不要求全覆盖。
  能提供：容错高、路径多样（同一关多种解法）、更适合程序化生成（有解率高）、挫败感低。
  但会带来：谜题纯度下降（从"存在性谜题"退化成"路径规划"）；"猫变长"的进度反馈被削弱（不再必然长）；与 Longcat 的差异变大，但也失去了"填满"的奇观。

- **候选 C · 全覆盖为主 + 收集模式作为独立玩法**：主线保留全覆盖，另开一个模式用收集规则。
  能提供：两全——核心纯粹且差异化明确。
  但会带来：MVP 要同时做两套胜利条件与两套关卡验证器，工作量翻倍；两套规则会稀释品牌认知。

- **候选 D · 全覆盖 + 覆盖率分级**：填满 100% 才是完美通关，但达到某阈值（如 85%）也算过关，只是评价更低。
  能提供：容错可调，且保留全覆盖的目标感与奇观。
  但会带来：阈值本身难以设计（多少算合格？），且"差一格"的挫败感被放大——玩家会纠结要不要重来追求 100%。

### 深度分析

判断标准是：**哪一条真正构成不可替代的体验，且能支撑长期内容生产？**

参考拆解的实证结论：Longcat 的护城河不是"填满"这个动作，而是「**可计算、可批量生成的关卡**」——50 关能扩到 1900 关，靠的是玩法本质的数学可解性（详见 `#Game-TearDown/Longcat/systems/关卡系统.md`）。

候选 A（全覆盖）是**唯一能同时保住"数学可验证"和"视觉奇观"**的选项：
- 全覆盖 = 哈密顿路径问题 → 存在性可判定、难度可量化（解的数量、首步容错率）
- 收集模式 = 一般路径规划 → 解极多、难度几乎不可量化，关卡会变成"随便走走也能过"

换句话说，**放弃全覆盖，就会同时放弃内容生成能力**——而这正是这类游戏唯一的护城河。

候选 A 的真正缺陷是"一步错全盘皆输"。但这个问题**不该在核心层解决，应该在回收层解决**：
Longcat 的缺陷不是规则错了，而是它**没有接住失败的机制**（无撤销、无提示、无跳过、无成长）。
解法是加元层（命、能力、撤销），而不是改规则。

这也符合规范 §8 的架构倾向：**规则层保持纯粹，回收层承担情绪**。

### 综合判断

**采用候选 A：核心胜利条件沿用「填满全部格子」，不做覆盖率分级，不在 MVP 引入收集模式。**
「一步错全盘皆输」的容错问题，交给元层（九条命 + 能力系统 + 撤销）解决，不动核心规则。

## 问题：差异化应该压在哪一层？

状态：user_confirmed

### 广度分析

- **候选 A · 目标层（改胜利条件）**：如上题候选 B，改收集+终点。
  能提供：与 Longcat 的即时差异感最强。
  但会带来：牺牲可生成性（见上题深度分析），且差异化只停留在"看到的第一眼"。

- **候选 B · 机制层（加特殊方块）**：引入冰块（滑得更远）、传送门、一次性方块、可推动物。
  能提供：谜题维度的扩展，玩法新鲜感直接。
  但会带来：每种新方块都要重新验证求解器（剪枝规则失效）、关卡生成复杂度指数上升；且方块一多，"滑行填充"的心智会被稀释成"又一个物理解谜"。

- **候选 C · 元层（Roguelike：命 + 能力三选一）**：核心规则不变，每次 run 连续挑战多关，每关后三选一获得规则修正能力。
  能提供：接住失败（命数缓冲）、每局不同（能力组合）、长期重玩动机、且**能力恰好能针对性地缓解"一步错全盘皆输"**（如"撤销一次""允许一次回头""高亮一条可行路径"）。
  但会带来：需要设计 run 结构与回收规则；能力若设计成数值加成会破坏谜题纯粹性。

- **候选 D · 社交层（微信特供）**：每日挑战、群排行榜、分享求提示、UGC 编辑器。
  能提供：微信生态独有红利，Longcat 完全没做。
  但会带来：依赖用户基数，冷启动无效果；编辑器是重功能，不该在 MVP。

### 深度分析

判断标准是：**哪一层能同时解决 Longcat 的缺陷，又不破坏它的优势？**

Longcat 拆解出的四个核心缺陷：
1. 一步错全盘皆输 → 需要「回收机制」
2. 卡关即流失 → 需要「缓冲 + 提示」
3. 无重玩价值 → 需要「每局不同」
4. 无社交自传播 → 需要「社交钩子」

候选 C（元层）**一个人解决前三个**，且不触碰核心规则与求解器——这是成本最低、收益最高的选择。
候选 D（社交层）解决第四个，但依赖用户量，应作为并行补充而非 MVP 主体。

候选 B（机制层）看似最"新"，但代价是**摧毁可生成性**——每加一种方块，求解器剪枝就要重做。这与"护城河是生成器"的判断直接冲突。

关键约束：**能力必须设计为「规则修正」而非「数值加成」**。
因为本游戏没有数值系统（这是它零平衡工作量的根源）。如果能力变成"伤害+10%"这类，就等于引入了一套需要平衡的伪数值系统，得不偿失。

### 综合判断

**采用候选 D：差异化压在社交层，做一个丰富社交层面的游戏。**

核心社交功能：
- **每日挑战**：全服同一关，比步数/覆盖率
- **好友排行榜**：微信小程序原生能力，展示好友进度
- **好友分享奖励**：分享得道具/皮肤，驱动裂变

不做 Roguelike 元层（命 + 能力三选一），机制层（特殊方块）降为 P1。

## 问题：目标用户该定在哪，情绪基调要不要加成长？

状态：user_confirmed

### 广度分析

- **候选 A · 纯硬核解谜玩家**：高难度、无辅助、靠关卡量堆深度。
  能提供：口碑与核心用户忠诚度。
  但会带来：微信小游戏的主流人群不是这批；留存曲线陡峭。

- **候选 B · 泛休闲用户**：极简、轻松、随时可停。
  能提供：最大用户面，与微信小游戏人群高度重合。
  但会带来：与 Longcat 完全同质，且休闲用户忠诚度低、流失快。

- **候选 C · 休闲外壳 + 解谜内核 + 成长接住**：上手是休闲的（3 秒懂、单指玩），中段是烧脑的（空间推理），失败由成长系统接住（命 + 能力）。
  能提供：既吃到泛用户，又用元层把人留住——这正是 Vampire Survivors / Brotato 类产品验证过的结构。
  但会带来：需要同时做好三层，调性统一难度高。

- **候选 D · 猫题材爱好者为主**：主打收集皮肤、可爱呈现，玩法从简。
  能提供：传播性强的题材钩子。
  但会带来：题材不是玩法，皮肤收集撑不起核心循环。

### 深度分析

判断标准是：**微信小游戏生态里，什么样的结构能同时拿到安装量和留存？**

微信小游戏的两个事实：
- **获客极便宜**（社交裂变），但**留存极难**（无安装成本 = 无沉没成本，走了就不再回来）
因此纯休闲（候选 B）在这个生态里是**流量漏斗**：进得多、留不住。
纯硬核（候选 A）则连进都进不来。

候选 C 的结构恰好对冲了这个矛盾：
- 休闲外壳负责拉新（3 秒懂、单指、30 秒一关）
- 解谜内核负责沉浸（这是 Longcat 已被验证的部分）
- 成长系统负责留存（命、能力、每日挑战——给"明天再来"的理由）

猫题材（候选 D）不是独立的用户群，而是**降低认知门槛的外壳**，应作为呈现层的选择，不应作为用户定位。

情绪基调的边界：可以烧脑，但不能受苦。
失败的正确语义是"**这次少赚了**"，不是"我打不过"。这与规范 §8「保护机制对抗挫败」一致。

### 综合判断

**采用候选 C：定位「休闲外壳 + 解谜内核 + 成长接住」的泛解谜用户；情绪基调为轻松、可爱、烧脑，但边界是"我再试一次"而非"我打不过"。**
猫题材作为呈现外壳（不是用户定位），承担降低认知门槛与传播性的职责。

## 问题：为什么是微信小游戏，这个平台约束如何影响概念？

状态：user_confirmed

### 广度分析

- **候选 A · 微信小游戏优先**：即点即玩、社交裂变、免安装。
  能提供：最大流量入口 + 社交红利（分享/群排行，这是 Poki 完全没有的）。
  但会带来：主包 4MB 限制、提审周期、无版号不可内购（只能广告变现）。

- **候选 B · 独立 App 优先**：无包体限制、可内购、可推送。
  能提供：完整的商业化自由度。
  但会带来：获客成本高、无社交裂变、需要版号。

- **候选 C · H5 多平台分发（Poki 等）**：一次开发多平台。
  能提供：海外流量。
  但会带来：微信社交能力完全用不上；需适配多平台 SDK。

- **候选 D · 双端并行**：小程序 + App。
  能提供：两边通吃。
  但会带来：MVP 阶段资源分散，且本项目的核心红利（社交裂变）只在微信。

### 深度分析

参考拆解 `notes/对微信小游戏项目的启示.md` 的结论：Longcat 走了「Fancade → 独立 App → Poki H5」三级跳，但**三个阶段玩法从未改变，只变了内容量和分发渠道**。

这说明：**平台选择影响的是"怎么分发和变现"，不影响"玩法是什么"。**
因此本题的真正问题不是"选哪个平台"，而是"**微信的约束会不会反过来伤害玩法**"。

逐条检查：
- 主包 4MB → 影响关卡存放方式（必须远程化），**不影响玩法**
- 提审周期 → 影响内容更新方式（关卡走 CDN 不提审），**不影响玩法**
- 无版号不可内购 → 影响变现方式（广告为主），**不影响玩法**

结论：**微信的约束全部落在"工程与商业"层，无一落在"玩法"层**。因此可以放心地把微信作为首发平台，且这些约束应该在架构阶段（02）一次性解决，不影响概念定稿。

反过来，微信给的两样东西是别处没有的：**社交裂变 + 免安装转化**。这两样直接支撑"休闲外壳拉新"的策略。

### 综合判断

**采用候选 A：微信小游戏作为唯一首发平台。**

项目定位：个人作品 + 试水 IAA（广告变现）游戏。
微信的约束（包体、提审、内购）推迟到架构阶段解决，概念阶段不受影响。

## 问题：题材与呈现，猫 + 体素是否沿用？

状态：user_confirmed

### 广度分析

- **候选 A · 沿用猫 + 体素方块**：与 Longcat 高度相似。
  能提供：已验证的可读性（纯色体素、零视觉噪音、全图可读）、极低的美术成本、小团队可复现。
  但会带来：抄袭观感最强，第一眼就被认为是换皮。

- **候选 B · 换题材（如水墨、贪吃蛇、机器人、管道）**：换皮保机制。
  能提供：视觉上的差异化。
  但会带来：换皮不解决同质化（Poki 上同类数十款，题材各异）；且"猫"这个题材本身有极强的传播性与低门槛感。

- **候选 C · 沿用猫，但换呈现风格（如 2D 手绘、霓虹线条、毛线质感）**：保留题材，改画风。
  能提供：题材红利保留，视觉上明显区分；"毛线/毛球"类质感与"路径变长"的语义高度契合。
  但会带来：手绘成本高；必须严格保证可读性不被画风侵蚀。

- **候选 D · 换玩法隐喻但保留猫**：猫不出场，改成"水管/电路/蛇"。
  能提供：隐喻与机制更贴（管道连通 = 路径规划）。
  但会带来：失去猫题材的传播性与情感钩子。

### 深度分析

判断标准是：**题材在哪些层面真正起作用？**

拆解研究表明，"猫"在 Longcat 里承担三个功能：
1. **认知门槛**：无需文字，玩家一眼知道"这是个什么游戏"
2. **反馈载体**：猫的长度 = 进度（这是"反馈即内容"的关键）
3. **传播性**：可爱 + 长 = 天然的话题性

这三条里，第 2 条（反馈载体）是**玩法结构性需求**——任何替代题材都必须保留"路径变长 = 进度"这个可视化能力。
第 1、3 条是**题材红利**。

因此：**题材该保留，但呈现风格必须换。**
"沿用猫 + 完全一样的体素画风"（候选 A）是抄袭观感最强的组合，必须避免。
候选 C 保留了功能，规避了观感，是正确方向。

但要注意一条硬约束：**任何画风都不能牺牲可读性**。
空间解谜的前提是全图可读——已填 vs 未填必须一眼可辨。手绘纹理、光影、粒子都会侵蚀这一点。

### 综合判断

**采用候选 C：保留猫，换呈现风格。**

具体美术方向：
- **格子** = 草地
- **起点** = 银渐层猫咪
- **移动方式** = 划线移动猫
- **填充效果** = 猫走过的地方长出白色蒲公英
- **阻挡物** = 木箱子
- **目标语义** = 让整个草地开满花

硬约束：不得降低"已填/未填"的辨识度，不得引入动态遮挡或视觉噪音。
