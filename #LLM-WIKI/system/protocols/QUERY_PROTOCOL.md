# QUERY_PROTOCOL · 查询与证据编排

> 本文决定是否查库、查到哪一层、何时核实外部事实，以及如何组合证据。Query 默认只读。

## 一、执行链

```text
理解任务与显式覆盖
→ 读取 system/registry/KNOWLEDGE_SCOPE.md
→ 选择 L0 / L1 / L2；需要时叠加 Web
→ 收集当前情境与证据
→ 检查适用性、时效与冲突
→ 输出结论、推导、行动和验证
```

专家方法与知识检索相互独立：可以 L0 使用方法，也可以查库而不显示专家身份。

## 二、检索等级

| 等级 | 触发条件 | 读取范围 | 停止条件 |
|---|---|---|---|
| L0 | 改写、整理、翻译、普通发散；任务不依赖库内证据 | 当前消息与已给上下文 | 直接回答 |
| L1 | 问题命中 `system/registry/KNOWLEDGE_SCOPE.md` 的重点主题；用户说“查询知识库” | `system/registry/quick-reference.md` → `system/registry/index.md` → 相关 domain | 无候选立即停止 |
| L2 | 诊断、方案拍板、具体设计或实现审查，且 L1 有强相关候选；用户说“深查知识库” | 默认最多 3 篇相关 Wiki；解决冲突或溯源时才读 raw | 证据足够或继续读取不再增加信息 |
| Web | 版本、价格、市场、法律政策、平台规则、数据等时效事实；用户要求联网 | 优先官方或一手资料 | 关键事实得到核实 |

Web 是独立核实轴，可与 L0/L1/L2 叠加。

### 空库行为

- `system/registry/quick-reference.md` 无候选时，报告“知识库暂无相关内容”并停止本地检索。
- 不遍历全部 Wiki、raw 或目录制造伪相关。
- 可以继续使用用户材料与 AI 推导，但须标明假设和验证办法。
- `system/registry/KNOWLEDGE_SCOPE.md` 尚未配置时，普通问题保持 L0；用户显式查询时说明范围未配置。

### 显式覆盖

- “查询知识库”：至少 L1。
- “深查知识库”：直接 L2，但仍只读相关页面。
- “不要查知识库”：本轮强制 L0；不自动关闭 Web。
- “联网核实”：强制核实时效事实。
- “不要联网”：禁止 Web；依赖最新信息时声明无法核实。

同一轴上的覆盖冲突时执行用户最后一个明确指令；无法判断则一次性澄清。

## 三、证据职责

| 问题 | 优先来源 | 其他来源的角色 |
|---|---|---|
| 当前对象实际状态 | 用户约束、项目文件、已拍板决定 | Wiki 用于对照与风险检查 |
| 稳定方法与历史案例 | Wiki，必要时回溯 raw | AI 通用知识补跨域类比 |
| 当前外部事实 | 官方 / 一手 Web | Wiki 提供稳定分析框架 |
| 新方案与未知问题 | 当前事实 + 明示的 AI 推导 | Wiki / Web 提供候选依据 |

只在来源身份影响可信度时标注：`[当前事实]`、`[知识库依据]`、`[外部资料]`、`[AI推导]`。不得给未读取材料加来源标签。

## 四、适用性与冲突

使用知识前检查对象、阶段、约束和时效是否一致。

- Wiki 与当前事实冲突：当前事实决定“现在是什么”，Wiki 只做比较。
- Wiki 与外部一手资料冲突：时效事实以更新的一手资料为准。
- 库内材料互相冲突：说明各自成立条件，不强行合并。
- 证据不足：标为假设，给出能支持或否定它的最小验证。

## 五、回答要求

答案不强制固定标题，但应能看出：结论 → 情境与约束 → 关键依据 → 映射推导 → 可执行动作 → 验证办法。

禁止只复述 Wiki、机械罗列页面名、用“通常如此”覆盖当前事实，或把 AI 建议伪装成库内结论。

## 六、内容状态与独立运行

- 仅在询问全库能力、缺口或吸收建议时读取 `system/registry/KNOWLEDGE_STATUS.md`。
- 状态页不是领域结论证据；具体命题回到 domain / Wiki。
- 独立使用时从对话和附件构建上下文；嵌入项目时可接收 `agents/CONTEXT_CONTRACT.md` 的 ContextBrief。
- 回归入口：`system/maintenance/checklists/run-query-agent-contract.ps1` 与 `system/maintenance/checklists/query-agent-behavior-check.md`。
