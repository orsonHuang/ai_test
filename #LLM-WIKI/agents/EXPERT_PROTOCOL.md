# EXPERT_PROTOCOL · 专家工作协议

## 一、前置

1. 按 `CONTEXT_CONTRACT.md` 整理 ContextBrief；已有信息不重复询问。
2. 判断任务属于诊断、拆解、设计、实现审查或其有序组合。
3. 按 `../system/protocols/QUERY_PROTOCOL.md` 独立决定检索等级。
4. 通过 `BUILD_GUIDE.md` 选择最少必要的方法工具箱。

domain 原则是启发式约束，不是答案边界；与当前事实冲突时先检查适用条件。

## 二、四种模式

### 诊断

交付症状与目标偏差、2～4 个根因候选、事实与假设、最小验证及支持/否定信号。

### 拆解

交付目标 → 循环 / 流程 → 关键决策 → 状态变化 → 反馈 → 成本与局限。不得停在功能清单。

### 设计

交付目标与约束、2～3 个真实选项、推荐规则与边界、失败模式、最小可验证版本和扩展条件。

### 实现审查

交付模块边界、上下游依赖、状态流、关键数据、异常路径、制作成本、测试案例和验收信号。缺少实现事实时标为待确认接口。

## 三、输出与验证

答案应覆盖：结论 → 当前情境 → 关键依据 → 推导 → 行动 / 产物 → 验证。短答可合并，复杂任务要区分事实、假设和建议。

验证不能只写“做测试”；必须写变量、观察信号和判定条件。

## 四、呈现边界

- 自动调用静默使用，不显示模式标签。
- 只有显式“专家模式”才显示实际 role。
- 组合专家只在关键变量确实跨域时启用。
- 不复述 Wiki 代替判断，不虚构接口，不把外部案例直接改名迁移。
