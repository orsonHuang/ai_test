# 开发阅读入口 · 暖雪 Steam 本体

以下是从公开规则整理的参考实现问题，不是原作技术架构。先读 [圣物](../systems/圣物装配.md)、[构筑](../systems/宗派与秘籍.md)、[战斗](../systems/战斗.md)，再考虑独立实现。

2026-10-16已补齐各模块P参考切片；先读[公共契约](../../_framework/参考实现公共契约.md)，然后按模块R-ID实现并执行T-ID。资料事实与新增参考参数分开，当前只有文档与结构验证，没有运行参考玩法。

| 模块 | 建议的职责边界 | 关键验收 |
|---|---|---|
| 圣物装配 | 物品定义、槽位实例、效果注册分离 | 穿脱反复操作后属性不漂移、事件不重复 |
| 构筑选择 | 候选生成与选择提交分离 | 互斥约束、重复提交、空候选回退 |
| 战斗效果 | 命中结算与表现请求分离 | 连锁触发有终止条件，低帧率不放大持续收益 |
| 神兵条件 | 条件可解释，依赖改变触发重算 | 移除前置后联动确实失效 |
| 永久成长 | 永久档与当局档职责明确 | 扣资源与激活原子完成，旧档迁移可解释 |
| 房间与首领 | 完成条件、出口、奖励独立但一致 | 结算只发一次、死亡同刻规则明确 |
| 商店改造 | 支付与结果绑定 | 重试不重复扣费、不重复随机 |
| 叙事收集 | 发现、已读与剧情条件分开 | 重复获取与存档恢复一致 |

## 一个关键状态案例：装配替换（参考）

`查看现状 → 计算候选 → 用户确认 → 校验合法性 → 解绑旧效果／绑定新效果 → 保存 → 刷新反馈`。

若候选阶段就把效果写入角色，会导致取消后残留；若保存先于合法性检查，则会持久化无效组合。采用何种事务／回滚机制由目标项目架构决定。不要在没有源码的情况下声称暖雪采用 ECS、某事件总线或某存档格式。
