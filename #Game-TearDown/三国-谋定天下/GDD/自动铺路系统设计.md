# 三国：谋定天下 — GDD：自动铺路系统设计

> 文档类型：游戏设计文档（GDD）
> 主题：自动铺路系统
> 适用范围：地块化 SLG 战争策略手游

---

## 一、系统定位

自动铺路是《三国：谋定天下》的核心减负设计之一，用于替代传统 SLG 中手动逐块占领地块的繁琐操作。其设计目标是在保留战略决策的前提下，把重复性操作交给系统，降低玩家的在线时长和操作负担。

---

## 二、功能作用

### 2.1 解决的核心痛点

| 痛点 | 自动铺路如何解决 |
|------|------------------|
| 手动逐块点击占地，操作繁琐 | 玩家只需选择目标地块，系统自动规划路径 |
| 远距离目标需要反复铺路，耗时耗力 | 系统连续占领沿途地块，无需玩家每一步都确认 |
| 新手容易因为操作复杂而流失 | 降低上手门槛，让玩家更快体验到成长和战斗 |
| 盟主/高活跃玩家需要帮同盟大量铺路 | 解放管理负担，个人玩家也能自主扩张 |

### 2.2 对游戏体验的影响

- **降低肝度**：减少玩家在地图上重复点击的时间。
- **加快节奏**：让新手保护期内的发育速度更快。
- **保留策略**：玩家决定「去哪里」，系统处理「怎么去」，战略决策权仍在玩家手中。
- **提升流畅度**：避免因为手动操作打断玩家的游戏心流。

---

## 三、功能流程

### 3.1 玩家侧流程

```
1. 玩家在地图上选择一个目标地块
2. 系统判断该目标是否可达（相邻地块是否可通行/可占领）
3. 系统计算从当前领地到目标地块的最优路径
4. 系统依次派出部队占领路径上的每一块地
5. 占领完成后，目标地块纳入玩家领地范围
```

### 3.2 系统侧流程

```
接收目标地块 → 路径搜索 → 通行性校验 → 体力/资源校验 → 排队执行 → 占领反馈
```

---

## 四、路径规划算法

### 4.1 基础算法

自动铺路本质上是一个**图搜索问题**，常用算法包括：

| 算法 | 适用场景 |
|------|----------|
| **A*（A-Star）** | 有明确起点和终点，需要最短路径时 |
| **Dijkstra** | 需要计算到多个目标的最短路径时 |
| **BFS（广度优先）** | 地图规模较小，需要寻找最近可达目标时 |

在 SLG 大地图中，通常使用 **A* 算法**，原因：
- 地图可抽象为网格图或六边形图。
- 每个地块有通行代价（距离、地形、敌方阻隔等）。
- A* 通过启发式函数能高效找到近似最优路径。

### 4.2 路径搜索的关键因素

| 因素 | 说明 |
|------|------|
| **地块连通性** | 只能从己方/盟友地块出发，逐块向外延伸 |
| **通行代价** | 距离越近越好，优先走己方/空地，绕开敌方/高级地 |
| **地形影响** | 河流、山地等不可通行或代价极高 |
| **敌方阻隔** | 敌方领地不可通行，需要绕行或作战打通 |
| **体力限制** | 每次出征消耗体力，部队需要休息恢复 |

### 4.3 路径优化目标

- **最短路径**：最小化经过的地块数量。
- **最小战损**：优先选择低等级守军地块，避免高级地造成不必要损耗。
- **最快速度**：考虑行军时间和体力恢复，规划最高效的铺路节奏。

## 五、关键规则设计

### 5.1 触发条件

- 玩家领地与目标地块之间存在可连通路径。
- 目标地块为可占领状态（未被其他玩家/同盟占领，或玩家有权限攻打）。
- 玩家拥有足够的部队和体力。

### 5.2 中断与异常处理

| 情况 | 处理方式 |
|------|----------|
| 部队体力不足 | 暂停铺路，等待体力恢复后继续 |
| 行军路径被敌方阻断 | 提示玩家需要先打通路径（详见《地块攻防与耐久度系统》） |
| 目标地块被其他玩家抢先占领 | 自动停止，提示玩家重新选择目标 |
| 玩家主动取消 | 立即停止当前铺路队列 |
| 资源/兵力不足 | 暂停并提示玩家补充 |

### 5.3 与手动铺路的共存

- 自动铺路是默认推荐方式，但保留手动单块占领功能。
- 高级玩家或特殊场景下（如精确控制领地形状、避开某个地块）可手动操作。

| 职业 | 与自动铺路的联动 |
|------|------------------|
| **神行** | 行军速度快，铺路效率更高 |

| **司仓** | 资源产出高，支撑更快的领地扩张 |
| **镇军** | 战斗能力强，可以更快打通高级地块 |

## 七、技术实现要点

### 7.1 地图数据结构

- 地图使用二维网格或六边形网格表示。
- 每个地块记录：坐标、类型、等级、占领者、地形、耐久度等。
- 地块之间的关系通过邻接表或邻接矩阵维护。

### 7.2 路径计算服务

- 路径计算可在客户端做初步规划，服务端做最终校验。
- 对于超大地图，可采用分层寻路：先规划宏观区域路径，再细化到具体地块。
- 常用优化手段：
  - **Waypoint 系统**：预计算重要节点之间的路径。
  - **缓存常用路径**：避免重复计算。
  - **异步计算**：防止大地图寻路阻塞主线程。

### 7.3 同步与并发

- 自动铺路涉及多次出征和占领，需要服务端顺序执行。
- 地块状态变化时需要实时同步给相关玩家。
- 多个玩家同时争夺同一块地时，需要冲突仲裁机制（先到达者获得）。

## 八、设计验证指标

| 指标 | 验证目标 |
|------|----------|
| 自动铺路使用率 | 验证功能是否被玩家接受 |
| 新手 48 小时占地数 | 验证自动铺路是否加速前期发育 |
| 玩家日均操作次数 | 验证是否有效降低重复操作 |
| 手动铺路占比 | 验证自动与手动的平衡 |
| 因铺路导致的流失率 | 验证减负效果 |

## 九、潜在风险与应对

| 风险 | 应对思路 |
|------|----------|
 自动铺路导致扩张过快，服务器节奏失衡 | 通过体力、资源、高级地守军限制扩张速度 |
| 路径算法出错，玩家铺路到错误位置 | 提供路径预览和取消功能，服务端二次校验 |
| 自动铺路削弱策略性 | 保留关键决策（目标选择、兵力分配），仅自动化执行 |
| 多玩家同时铺路产生冲突 | 地块锁定机制 + 先到先得的仲裁规则 |
| 大地图寻路性能问题 | 分层寻路 + 异步计算 + 路径缓存 |

## 十、与其他自动功能的关系

| 功能 | 关系 |
|------|------|
| **自动攻城** | 铺路是攻城的前置条件，自动铺路为自动攻城提供路径支撑 |
| **营帐建造** | 铺路到达前线后可建造营帐，形成前线补给点 |
| **资源采集** | 自动铺路帮助玩家到达更远的资源地 |
| **任务系统** | 主线任务可引导玩家使用自动铺路，降低学习成本 |

---

## 十一、总结

自动铺路系统的本质是**把 SLG 中低价值的重复操作自动化，让玩家把精力集中在战略决策和社交协作上**。它不是削弱策略，而是通过降低操作门槛，让更多玩家能够参与到核心玩法中。在设计实现上，需要平衡**自动化便利性**与**策略决策空间**，并通过路径算法、状态同步、冲突处理等技术手段保证稳定性和公平性。
