# 契灵与术印 · 开发参考附录

2026-10-18 · 补充设计 v2 · 默认参数均非原作配置


## 参考版内容与配置

此方案独立定义完整获取与养成流程，非原作当前数值。契灵目录固定两类：攻型提供主角攻击，守型提供主角生命；1—5星，等级1—20，不升星，星级在获得时决定；术印从攻击、生命、治疗三类中均匀无放回抽2个，分别给适用主角该属性/效果加成5%。所有效果仅在参考PVE生效，斗技不生效；跟随纯展示。

| 项目 | 默认 |
|---|---|
| 探查 | 账号60级；每次6体力；20%发现踪迹，未发现也扣费；一次只持有1条踪迹，有效30分钟 |
| 星级 | 区域层级1—5对应发现契灵星级1—5；每层首次探查胜利解锁下一层；敌人用PVE首领k=该层级 |
| 结契 | 打赢踪迹对应首领后使用式盘；普通盘成功率50%、高级盘100%；每次1盘，最多3次；成功或三次失败结束踪迹 |
| 失败 | 消耗已使用的盘，不返探查体力；战斗失败不扣盘，踪迹到期前可重试 |
| 对象容量 | 200，满时禁止开始探查；捕获结算容量变化则存领取箱 |
| 培养 | 目标等级L所需经验100×L，L=2—20；经验材料每份100，金币2/经验；不吞食契灵，纳还后转为经验池 |
| 纳还 | 未锁、未装备、未被预设引用才允许；返星级×100＋累计培养经验80%（向下取整），入经验池；金币不返 |
| 商店 | 10契忆换1普通盘，每日10；50契忆换1高级盘，每周2；探查胜利固定得2契忆 |

## 全等级曲线与消耗

等级L的攻型基础加成为`星级×(10+2×(L−1))`固定攻击，守型为该数的10倍固定生命。20级是完整上限，不借用御灵40级上限。术印百分比作用于主角基础对应属性，固定加成之后相加，防止重复放大。

| 等级区间 | 逐级经验序列 | 区间合计 | 从1级累计 |
|---|---|---:|---:|
| 2—5 | 200、300、400、500 | 1400 | 1400 |
| 6—10 | 600、700、800、900、1000 | 4000 | 5400 |
| 11—15 | 1100、1200、1300、1400、1500 | 6500 | 11900 |
| 16—20 | 1600、1700、1800、1900、2000 | 9000 | 20900 |

1→20需209份材料、41800金币；经验池优先使用且免再次收费，超过满级所需的经验不扣。一次升多级顺序应用全部等级，不重新随机术印。

## 状态与接口

无踪迹→探查中→无踪迹/有踪迹→挑战→结契→捕获/失败/到期。探查成功与奖励共用请求；每次结契有独立请求号但同一踪迹序号，校验剩余次数、盘、时间和战斗胜利凭据。捕获一旦提交不能再次用同一踪迹获取第二个对象。

装备请求校验主角与契灵所有权，一位主角一个契灵；交换时两端同时更新。保存预设记录对象引用及模式，进入斗技明确显示“不生效”，不从背包删除。术印不匹配时仍可装备，但展示当前实际生效项；不能用不存在的属性补值。

## UI与验收

探查按钮展示6体力；踪迹卡展示剩余时间、星级、挑战与剩余结契次数；结契确认显示盘种与成功率；对象页区分星级、等级、术印、适用主角和生效模式；纳还确认列出返还，不只给“确定”。

- 5星20级攻型固定攻击240，守型固定生命2400；均不含术印加成。
- 1→20经验20900、金币41800；满级继续培养被拒绝；术印不因培养改变。
- 普通盘连续失败3次消耗3盘、踪迹结束；高级盘首次成功只消耗1盘。
- 到期恰好时不允许新结契；已提交成功保持所得；同一请求重复只返原结果。
- 已装备或被预设引用对象不能纳还；先解除引用才可继续，保护状态变化需要重新预览。

## 模块交接与重复资产保护

账号等级取成长模块account.level，星级与等级只属于契灵对象，不套用式神starCaps或御灵曲线。探查先调用PVE会话，固定胜利资源与发现结果同一结算收据；失败仍扣体力、不发现踪迹也不给契忆。每层首次胜利只更新契灵区域解锁，不误写普通副本首通奖励。

契忆、式盘、契灵经验材料由资源账本持有，经验池contractBank上限1,000,000；纳还预览若会溢出则拒绝并提示先培养，避免暗中损失。参考版纳还不额外产契忆，契忆只从探查胜利取得。

## 公共提交契约与实现状态

本附录的数值、对象结构与异常策略全部属于补充参考设计。正文单独说明有来源的原作机制。当前交付为规则文档；除另行标注的前端演示与计算校验外，账号服务、数据库并发、支付和完整游戏客户端尚未实现，以下服务用例均为待执行验收要求。

- 输入含账号、请求号、动作参数、配置版本和对象预期版本；验证身份与所有权，再计算规则，最后一次提交资源、对象和收据。预览不扣费，取消没有副作用。
- 同号同参数返回原收据，同号不同参数拒绝；并发冲突不部分提交。客户端连接中断先按请求号查询，不能把超时当成失败另开一笔。
- 状态统一区分编辑、待确认、提交中、成功、明确失败、结果未决。未决禁用重复确认但允许查询；刷新从服务端收据恢复。
- 错误至少区分非法输入、权限不足、资源不足、资格不符、版本冲突、已过期、已完成与容量不足，并给可理解的处理入口。
- 资源全为非负整数；百分比使用明确精度，所有舍入点在规则中定义。随机过程由服务器生成并落盘，重试不重抽；服务器时间决定周期与到期。
- 埋点只记录必要的规则版本、阶段、耗时、错误与资源变化；分析转化时区分新手/回流/成熟账号、玩法和活动期，不把模拟数据当真实留存。
