# 行动条与鬼火战斗 · 开发参考附录

2026-10-18 · 补充设计 v2 · 默认参数均非原作配置


## 对象与完整默认配置

| 对象 | 必要字段 / 默认值 |
|---|---|
| 战斗 | 唯一战斗号、模式、配置版本、随机种子、状态、行动序号、事件日志；最多500次完整行动 |
| 单位 | 实例号、阵营、槽位、生命/上限、攻击、防御、速度、暴击、暴伤、护盾、行动进度、技能、状态；死亡生命为0 |
| 双方队伍 | 各5名式神＋1名主角；本参考不允许重复角色；主角用同一行动模型 |
| 鬼火 | 双方分别计数；初始3，上限8；本方每5次完整行动补3，上限截断；额外触发动作不推进计数 |
| 基础参数 | 生命1000、攻击100、防御100、速度100、暴击0%、暴伤150%；所有角色表必须显式覆盖 |
| 四类技能 | 普攻：0火、单敌、100%攻击；群攻：3火、全敌、80%；治疗：2火、单友、攻击200%；供火：0火、无目标、加3火、冷却2次本人行动 |
| 角色集合 | 输出：群攻；治疗：治疗；供火：供火；控制：单敌攻击80%、2火、基础50%眩晕；主角：治疗；每人都有普攻；未特别注明的技能冷却为0、无额外状态 |
| 状态 | 眩晕跳过下次动作；攻击加成20%持续2次本人行动；护盾200持续2次本人行动；同名同源刷新时长不叠强度 |

这些默认值是完整参考战斗的配置，不代表阴阳师任何角色的实际技能。未配置的技能和效果禁止载入，不自动猜效果。

## 规则与计算顺序

1. **建立快照。** 验证双方阵容与装备实例，锁定配置版本；所有单位行动进度从0开始。进入后不接受外部养成变化。

2. **推进时间。** 进度阈值10000；计算各存活单位到阈值所需时间 `(10000－进度)/速度`，取最小值并同时推进全部单位。已达到阈值者耗时0。速度至少1；同刻按速度降序、战前种子生成的固定优先序、实例号排序。

3. **本人回合开始。** 已有冷却减1，检查眩晕等限制。眩晕则跳过选技能但仍算完整行动；不能跳过状态清理和鬼火计数。

4. **确定动作。** 手动20秒；超时或自动时，优先锁定技能，非法则用普攻；攻击选生命比例最低敌人，治疗选生命比例最低友方，同值按槽位。控制失效或无合法目标时进入规则允许的空行动，不向死亡对象结算。

5. **扣除与命中。** 先检查资源、冷却和目标，再扣鬼火、设冷却。伤害=`floor(攻击×技能系数×300/(300+防御)×暴击倍率)`，有效伤害至少1；先扣护盾，再扣生命。暴击为一次独立随机判定；治疗=`floor(攻击×治疗系数)`，不暴击、不超过生命上限。

6. **状态与死亡。** 控制概率=`clamp(基础概率×(1+命中)/(1+抵抗),0,1)`；死亡即时移除待行动资格。参考版不含反击、复活和协战；扩展时必须另配事件优先级及循环上限，不能默认为原作顺序。

7. **回合结束。** 本次行动开始前已存在的持续状态减1，新施加的状态本次不减；行动进度扣10000，不足时归0；本人完整行动计入己方鬼火补给。检查一方全部死亡则结束，同时全灭或500行动为平局。

## 冷却、资源与日志算例

- 防御100、攻击100、普通攻击未暴击：`floor(100×300/400)=75`；先有50护盾，则护盾归0、生命减少25。
- 初始3火，群攻后0；供火补3；下一名群攻后0。不可因队伍“本回合总共会获得6火”而允许提前透支。
- 供火在第1次本人行动设冷却2；第2次减为1不可用，第3次减为0可用。
- 日志至少记行动者、技能、目标、资源前后、伤害/护盾/生命、状态变化及终局原因，重放用种子与配置版本一致复算。

## UI、状态与验收

准备→载入→行动→结算→关闭。技能按钮有可用、缺火、冷却、被控、无目标五种可解释状态；自动设置显示当前锁定技能，改动只影响下次尚未确认的动作。伤害与资源数字在逻辑事件提交后更新；跳过动画不跳过事件。

- 测试1：速度相同、种子相同的两次战斗日志一致；种子变化只改变允许随机的部分。
- 测试2：缺火技能不扣火、不设冷却，回退普攻；已确认动作不得在断线重连后重选。
- 测试3：眩晕、全灭、满护盾、溢出治疗、鬼火上限和第500次行动均有确定结果。
- 测试4：同一结束请求只发放一份奖励；尚未完成的战斗不给客户端自报胜利权限。

## 与已验收养成配置的装配

接入成长模块时，以growth-config.json和growth-calculator.mjs输出的角色基础属性替换本附录默认面板，不叠加第二份基础值；六位置御魂先计算基础百分比、再加固定数值，契灵按所属主角和PVE适用单独装配。临时战斗加成不写回养成对象。

养成配置已有四种技能按其等级数组读取：strike用攻击系数；attack_buff给全体友方攻击百分比；shield按施法者最大生命生成护盾；dispel按等级移除目标若干可驱散减益，按施加时间从早到晚、同时间按状态号。三种辅助技能本参考耗火均2，普攻0；冷却、持续时长以养成配置为准。同源护盾取新值替换，异源护盾分别保留、按施加时间消耗；驱散不能移除正面状态。主角使用已选两主动技能，普攻始终保留。

本附录的群攻、治疗、供火和控制属于额外测试技能，仅在明示的测试角色上配置；不自动覆盖成长模板的技能列表。所有状态记录来源、施加序号、是否可驱散和剩余时长，保证装配后可解释。

## 公共提交契约与实现状态

本附录的数值、对象结构与异常策略全部属于补充参考设计。正文单独说明有来源的原作机制。当前交付为规则文档；除另行标注的前端演示与计算校验外，账号服务、数据库并发、支付和完整游戏客户端尚未实现，以下服务用例均为待执行验收要求。

- 输入含账号、请求号、动作参数、配置版本和对象预期版本；验证身份与所有权，再计算规则，最后一次提交资源、对象和收据。预览不扣费，取消没有副作用。
- 同号同参数返回原收据，同号不同参数拒绝；并发冲突不部分提交。客户端连接中断先按请求号查询，不能把超时当成失败另开一笔。
- 状态统一区分编辑、待确认、提交中、成功、明确失败、结果未决。未决禁用重复确认但允许查询；刷新从服务端收据恢复。
- 错误至少区分非法输入、权限不足、资源不足、资格不符、版本冲突、已过期、已完成与容量不足，并给可理解的处理入口。
- 资源全为非负整数；百分比使用明确精度，所有舍入点在规则中定义。随机过程由服务器生成并落盘，重试不重抽；服务器时间决定周期与到期。
- 埋点只记录必要的规则版本、阶段、耗时、错误与资源变化；分析转化时区分新手/回流/成熟账号、玩法和活动期，不把模拟数据当真实留存。
