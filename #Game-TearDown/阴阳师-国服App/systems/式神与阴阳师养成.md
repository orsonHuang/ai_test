# 式神与阴阳师养成 · 开发参考规格

模块 onmyoji-heroes · 修订2 · 2026-10-18 · 全部为补充设计

## 1 交付范围与完成定义

实现式神经验池/升级/升星/技能/觉醒/一键育成/转换，以及阴阳师账号等级/解锁/御灵/技能点/携带配置。两种普通式神模板与一种素材模板、四位基础阴阳师为可运行配置样例；不是原作完整角色库。契灵、御魂掉落、战斗与剧情通过接口接入。

配置文件为唯一数值源：growth-config.json；growth-levels.csv为展开结果；growth-calculator.mjs是无持久化的纯计算参考。计算测试通过不代表服务器事务、全量资产或客户端已实现。客户端的文案、状态和素材合同如下，原作资料见正文。

## 2 数据结构与合法域

| 对象 | 字段与默认值 | 约束 |
|---|---|---|
| Account | accountId，revision=0，coins=0，level=1，xp=0，heroBank=0，guardianBank=0，storyFlags=[] | ID非空；数值为安全整数且非负；经验池各上限1,000,000；等级1—60 |
| Hero | instanceId，templateId，star=2，level=1，xp=0，awakened=false，skillLevels，locked=false，assigned=false，referenced=false，dispatched=false | 模板存在；每技能初始1；星级2—6；等级不超过对应星级；到上限时xp=0 |
| MainCharacter | characterId，unlocked，guardianLevel=1，guardianXp=0，skillPoints=0，milestones=[]，skillLevels，activeSkills | 晴明默认解锁；御灵不超过min(40,账号等级)；每技能1—5；默认主动为增伤/护盾 |
| ItemStack | itemId，quantity | 物品ID来自配置；每次使用数量1—1000且库存足够 |
| Soul | instanceId，star，enhanceLevel，locked，equipped，referenced | 星级1—6；本参考只接受强化0且三种保护均false的素材 |
| Quote | quoteId，accountId，operation，payloadHash，accountRevision，configRevision，before，after，cost，expiresAt | 服务端生成，60秒有效；客户端不能覆盖after和cost |
| Receipt | requestId，payloadHash，status，newRevision，before，after，cost，randomResult | 每账户requestId唯一；成功结果持久化后重试只读取 |
| Reward | rewardId，source，amount，claimed | 来自可信剧情/任务/战斗服务；不能由客户端自报 |

非法对象不自动修正。不存在的ID报NOT_FOUND；小数、NaN、负数、重复素材或非法星级报INVALID；解锁不足报LOCKED_FEATURE。目标被锁定仍允许升级，素材被锁定不可消耗。

## 3 计算公式与顺序

### R01 经验曲线与升级

1. 按模板选择普通式神100×L、素材50×L、账号200×L、御灵150×L曲线。
2. 当前经验只记录当前等级段剩余量；未满级必须小于当前阈值。计算到本次上限所需经验。
3. 实际投入=min(请求量,到上限所需量)；若为0返回CAPPED且无成本。请求量范围1—1,000,000。
4. 经验够阈值则扣阈值、等级+1，循环直到不足或上限；上限时经验为0。超额手动请求不扣，未使用量回显。
5. 式神成本=ceil(实际投入/10)金币。先校验经验池和金币足够，再一次性扣资源并保存。
6. 账号经验来自Reward，不收费；到60级后多余奖励舍弃，收据记录实际和舍弃量，不进入式神池。

例：19级1800经验的2星普通式神申请500，只需100到20级，扣100经验/10金币。1级0经验申请650，扣650经验/65金币，变成4级50经验。

### R02 经验入池

· 小/大经验札每件1,000/10,000经验，按选择数量扣背包，免费入式神池。不能把经验札记成原作达摩的固定经验值。

· 御魂入御灵池：逐实例检查星级、+0和保护，贡献查soulXp；不合格对象整笔拒绝。金币成本0。

· 两池独立；容量超过上限整笔拒绝，不自动丢弃、拆分或转移。确认前显示池余额变化。

### R03 升星

目标星级s为2—5且等级满，要求恰好s个同星素材实例；素材等级在合法域内即可，不要求素材满级。必须属于同一账户、互不重复、不含目标，并且所有保护标记为false。扣s×10,000金币与素材；目标star+1，level不变，xp保持0，技能/觉醒/装备不变。6星返回CAPPED。

### R04 式神技能

每次只用一个同名普通式神或一个技能达摩；不接受素材模板和目标自己。同名以templateId判定，不能只比较显示名。被消耗同名实例已有技能等级不继承，本参考不支持原作“反喂”特例，确认页要明确这一损失。

候选集合=该目标所有等级<5的技能。空集合拒绝；否则服务端均匀抽一个，+1级。金币10,000。预览只返回候选集合/等概率，不返回未来结果；随机只在成功事务中产生并写入收据。重试不重抽，失败不消耗。技能达摩与同名实例不同时投入。

### R05 觉醒与属性

按template.awakening读取A/B配方；null为不适用，已觉醒拒绝。检查全部材料再统一扣除，金币0，置awakened=true。

普通属性先算base+growth×(level−1)，再乘星级倍率，最后乘觉醒倍率，整个乘积末尾向下取整：2/3/4/5/6星=1/1.1/1.2/1.3/1.4；觉醒时攻击/生命/防御再×1.1，速度固定+5。技能等级不自动变化，外观切换awake资源键。它是本参考的确定效果，不代表原作每名式神的觉醒收益。

两普通模板与素材模板的基础/成长值、配方、技能在配置中完整列出；素材模板无觉醒。装备与模式加成由外部战斗装配阶段另算，不写回基础属性。

### R06 一键育成与等级转换

一键育成输入目标实例、目标星级/等级和用户明确选择的素材集合；不自动挑选被保护或稀有对象。服务端在状态副本中依次模拟“升至当前上限→升星→继续升级”，每个升级步骤分别计算向上取整金币，最后合并总账。素材必须已经达到所需星级；本参考不递归培养素材。任一步缺资源则返回缺口和完整预览，不部分执行。确认后整个计划一笔提交。

转换只允许两只相同经验曲线类别的不同式神，双方未上阵/预设引用/派遣且无进行中操作；锁定不妨碍转换，因为对象不销毁，但必须二次确认。扣1张转换券，只交换star/level/xp，技能、觉醒、模板、装备和身份保持原位。两边状态一起提交；不允许普通式神与经验减半素材互换以套利。

### R07 阴阳师账号等级与解锁

Reward先按rewardId去重，再按账号曲线升级；成功收据保存实际经验。story-03/07/15对应神乐/源博雅/八百比丘尼，剧情服务提供已完成标记。初始晴明已解锁，各角色御灵、技能独立。角色解锁不补发过去账号等级的御灵技能点。

阴阳师属性用正文四条公式：每次读取根据账号/该角色御灵等级重算。例账号10级、御灵5级：攻击210、生命2100、防御103、速度100。

### R08 御灵升级与技能点

必须角色解锁，按guardian曲线和min(40,账号等级)上限从御灵池扣实际经验，金币0。每跨5级里程碑加入milestones并发1点。服务端以已领取集合去重；多级跨越逐项处理。不要用“等级恰好模5为0”作为唯一发奖条件，否则跨多级会漏发。

技能点由玩家指定未满技能消耗1点升1级；主动/普攻均可升级，上限5。没有点或技能满则拒绝；与原作历史随机升级区别须在参考说明中保留。全技能满时余额保留，不能扣掉换空气。

### R09 技能配置与战斗效果合同

普攻固定；从增伤、护盾、驱散选择两个不同技能。必须角色已解锁，技能属于该角色且等级合法。配置不收费，不在战斗中修改当前快照。

| 技能 | 等级1—5效果 | 目标/时序 |
|---|---|---|
| 普攻 | 攻击100/110/120/130/140% | 单敌；无冷却，伤害基础值向下取整，防御处理交战斗模块 |
| 增伤 | 攻击+10/12.5/15/17.5/20% | 我方全体，持续各目标2次自身回合结束；不叠加，同来源覆盖并刷新 |
| 护盾 | 施法者最大生命10/12.5/15/17.5/20% | 我方全体；每个对象独立护盾，2次自身回合结束后清除；同来源覆盖刷新 |
| 驱散 | 移除1/1/2/2/3个可驱散减益 | 单友方，按施加时间最早优先，再按effectId；不足则移除全部 |

三个主动技能都0鬼火、冷却3个施法者回合。施放回合结束不递减；随后每次施法者回合开始减1，减到0可用。不可驱散状态不进入候选；无减益目标可选但提示“没有可移除状态”，确认后仍按一次合法施法进入冷却。这些全为参考效果。与原游戏四位主角实际技能无一一对应承诺。

## 4 交易与接口

### R10 预览、提交、重试

1. PreviewGrowth(accountId, operation, payload)读取最新对象/库存/配置，按规则得到quote；预览不扣、不抽随机、不修改状态。
2. ConfirmGrowth(accountId, requestId, quoteId)鉴权；先查该账户requestId收据。已成功且payloadHash相同返回原结果；同ID异载荷报IDEMPOTENCY_CONFLICT。
3. 未处理请求检查quote属于账户、未过期、accountRevision与configRevision仍一致。数据库事务锁账户与所有相关实例，重新校验余额/保护/前置。
4. 事务内产生必要随机、扣全部成本、更新所有对象与revision、写收据；原子提交。任何失败回滚，不能发GrowthApplied。
5. 网络断开前端进入UNKNOWN；QueryReceipt查原requestId。未查到时可用相同请求重试，不直接换新ID。余额不足/过期报价重新预览并使用新requestId。
6. 成功事件GrowthApplied带receiptId、operation、changedIds、before/after及cost；外部任务按receiptId去重。账户更新由养成服务拥有，库存操作必须同事务或等价原子边界，不依赖客户端补偿。

| 错误 | 结果 | 前端处理 |
|---|---|---|
| INVALID/NOT_FOUND | 不扣不改 | 指出非法对象，清除无效选择 |
| PROTECTED | 不扣不改 | 指出锁定/上阵/方案占用 |
| INSUFFICIENT/CAPACITY | 不扣不改 | 显示逐资源差额或容量 |
| CAPPED/NOT_APPLICABLE | 不扣不改 | 满级/不支持操作，关闭确认 |
| STALE/EXPIRED | 不扣不改 | 强制重新报价并让用户再次确认 |
| FORBIDDEN | 不泄露他人对象 | 返回无权限，退出操作 |
| UNKNOWN | 不猜结果 | 保留请求号并查询 |
| IDEMPOTENCY_CONFLICT | 不重做 | 拒绝同请求号的不同内容 |

## 7 外部依赖与扩展边界

· 战斗：只接收准备完成的角色/技能/属性快照及版本；战斗内临时增益不写回养成。结算以唯一rewardId回传。

· 剧情：发放storyFlags；养成只消费标记，不自行判断对话推进。

· 御魂：提供实例、强化级与装备/预设引用；本模块消耗前必须与御魂方案服务重新校验。

· 契灵：单独服务管理获取、培养、术印与模式限制；本模块只接收有效加成，不把契灵配方塞进御灵表。

· 新角色：新增模板、技能配置和资产后先通过合法域校验，再进入目录。未给配方或技能的角色不以默认零成本上线。
