# 召唤与角色获取 · 开发参考附录

2026-10-18 · 补充设计 v2 · 默认参数均非原作配置


## 参考卡池与资源表

此卡池是独立演示设计，不复刻原作现行概率。所有概率用百万分整数；一个基础池包含R01—R10、SR01—SR05、SSR01—SSR03、SP01—SP02，角色仅用于标识和验收，真实技能需另配。

| 项目 | 自设默认值 |
|---|---|
| 稀有度概率 | R 79%、SR 19%、SSR 1.5%、SP 0.5%；同稀有度内等概率 |
| 单次费用 | 优先1张召唤券；不足部分每次100勾玉，确认显示两种资源各用多少 |
| 保底 | 连续59次未得SSR/SP，第60次在SSR/SP中按3:1抽取；获得SSR或SP均重置计数0 |
| 碎片合成 | R20、SR30、SSR50、SP60片合成对应1个角色；角色必须在已发布列表 |
| 重复 | 默认保留独立实例；可选转换返该角色碎片：R5、SR10、SSR15、SP20；锁定/装备/方案引用/唯一实例禁止转换 |
| 库存 | 角色实例上限1000；抽取前按最大可能结果预留，空间不足禁止开始 |
| 召唤记录 | 保存每次结果、消耗、前后计数、池版本、请求号；十连是一笔请求内10次有序结算 |

SSR内部1.5%分给3名各0.5%，SP0.5%分给2名各0.25%，全池概率之和100%。保底时SSR三名各25%，SP两名各12.5%。禁止先抽基础再额外补一张保底，否则会多发结果。

## 状态与规则

1. 卡池预告→开放→关闭→记录可查；开放窗口采用`开始≤服务器时间<结束`。截止后未开始的请求拒绝，已提交抽取按锁定版本完成。
2. 确认前校验池号、账号、余额、容量和显示的规则版本；规则版本变化返回重新确认。
3. 十连开始时一次保留全部资源和容量；按顺序逐次判定保底与抽取，早出稀有会影响本次十连后续计数。整个十连结果一次提交，不允许前5次成功后后5次丢失。
4. 动画只读取已提交结果。跳过、重放、断线查询都返回同一结果；客户端随机数不参与结果决定。
5. 活动印花若启用，使用独立状态：基础1%、连续39次未中第40次必中、五种未拥有印花均匀优先；全有后重复印花转10指定碎片。这些是针对历史结构的自设完整补充，非通用原作活动规则。
6. 参考活动结束：保底与印花不跨池继承；已提交奖励永久保留，印花兑换保留7天，之后每片转1000金币、邮件保留30天。提前在规则页明示。
7. 合成与转换均为材料扣除和角色增删的同一事务；不能使用已被其他请求消耗的实例。

## UI与异常

池主页展示完整角色范围、基础概率、触发保底后的概率、当前累计和截止时间；单抽与十连旁各有消耗；付费资源替代需确认，不自动弹购买。结果页区分新角色、重复实例和活动进度，提供养成入口与记录查询。

- 禁用：余额不足、容量不足、池关闭、规则变更、正在提交；每种状态给对应处理入口。
- 未决：断线时保留请求号，先查结果；动画失败仍可打开结果列表。
- 合成失败：不扣碎片；角色定义已下线时解释原因并停止兑换，不生成空角色。

## 验收算例

- 计数58时十连，第1次普通使计数59，第2次必为SSR/SP并清零；后8次逐次继续，不能十连结束才判断。
- 7券＋300勾玉可十连；7券＋299勾玉拒绝且余额不变。
- SR30碎片合成后减少30并增加1实例；重复请求不再次合成。
- 主保底与印花计数分别从59/39进入保证结果，各自按各自的结果重置；互不覆盖。
- 抽取截止时刻等于结束时间拒绝；截止前已提交的结果仍可查询。

## 与成长和库存的交接

召唤池19个角色类型各有独立类型号，用于收集、碎片、同队去重及展示；战斗/成长样例暂按类型数字奇数映射reference_attacker、偶数映射reference_support。新实例统一2星1级、未觉醒、技能1级，不按稀有度额外乘面板。这样能实现获取到培养的全流程，但19个类型共用两套能力，不能称为已制作19名差异化角色。

角色转换所得是本模块的定向碎片；作为升星材料则走养成模块的原有同星素材规则。两种操作互斥并共享实例版本，不能让同一对象同时转换和升星消耗。

## 公共提交契约与实现状态

本附录的数值、对象结构与异常策略全部属于补充参考设计。正文单独说明有来源的原作机制。当前交付为规则文档；除另行标注的前端演示与计算校验外，账号服务、数据库并发、支付和完整游戏客户端尚未实现，以下服务用例均为待执行验收要求。

- 输入含账号、请求号、动作参数、配置版本和对象预期版本；验证身份与所有权，再计算规则，最后一次提交资源、对象和收据。预览不扣费，取消没有副作用。
- 同号同参数返回原收据，同号不同参数拒绝；并发冲突不部分提交。客户端连接中断先按请求号查询，不能把超时当成失败另开一笔。
- 状态统一区分编辑、待确认、提交中、成功、明确失败、结果未决。未决禁用重复确认但允许查询；刷新从服务端收据恢复。
- 错误至少区分非法输入、权限不足、资源不足、资格不符、版本冲突、已过期、已完成与容量不足，并给可理解的处理入口。
- 资源全为非负整数；百分比使用明确精度，所有舍入点在规则中定义。随机过程由服务器生成并落盘，重试不重抽；服务器时间决定周期与到期。
- 埋点只记录必要的规则版本、阶段、耗时、错误与资源变化；分析转化时区分新手/回流/成熟账号、玩法和活动期，不把模拟数据当真实留存。
