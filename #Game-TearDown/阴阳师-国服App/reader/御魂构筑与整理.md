# 御魂构筑与整理：好装备必须放进队伍里判断

阴阳师 · 国服 App · 装备 / 构筑 / 资源整理

## 设计目的与功能

御魂让角色能力从固定答案变成可调整方案。它同时承担装备成长和长期掉落目标；随之而来的问题，是玩家如何从大量单件中认出“对这套队伍有用”。

- **位置与属性：** 六个装备位置、主属性与副属性形成组合条件。

- **套装效果：** 常见两件与四件组合提供属性或机制，不能只比较单件数字。历史首领御魂更新还引入了面向怪物战斗的专用组合。[首领御魂公告，2018](https://www.taptap.cn/moment/15217123987030075)

- **强化与整理：** 强化后的属性结果改变保留价值；整理需要结合未来用途，不能把当前未装备等同于无价值。位置和强化结构参考[历史入门说明](https://www.taptap.cn/moment/15210316736497577)。具体词条池与概率仍待当前面板核对。

## 选择流程

```mermaid
flowchart TD
  A[确定队伍职责与条件] --> B[筛选位置、主属性与套装]
  B --> C[比较候选整体方案]
  C --> D{满足必要条件吗}
  D -->|否| B
  D -->|是| E[决定强化或暂存]
  E --> F[在目标玩法验证]
  F --> A
```

图解是构筑分析方法，不是原作自动配装算法。

## 为什么数值更高也可能更差

- **条件收益：** 历史狂骨分析将伤害收益与鬼火关联。同样的套装，在不同耗火环境中价值不同；这里采用这一关系，不照抄旧文里的配队推荐与系数。[御魂分析，2022](https://www.taptap.cn/moment/257945364034748643)

- **整体约束：** 一件装备提高输出速度，却可能让它跑到供火或增益角色之前。因此对比面板必须有“队伍条件”这一层。

- **替换成本：** 强化、拆分和重新配装会占用资源与时间。收藏一件潜力装备也有管理成本，筛选器应帮助表达用途，而不是只给稀有度排序。

## 六个位置如何限制配装

历史御魂资料支持下面的位置结构。强化等级与星级是两条轴：强化改变当前单件，不能把低星御魂直接升为高星。位置表依据[御魂资料页](https://onmyoji.fandom.com/zh/wiki/御魂)，是历史机制整理，精确词条值仍需当前客户端面板校核。

| 位置 | 主属性候选 | 构筑时的意义 |
|---|---|---|
| 一号位 | 固定攻击 | 提供底座，主要比较套装与副属性 |
| 二号位 | 攻击 / 生命 / 防御加成、速度 | 把行动时机与面板收益放在同一选择中 |
| 三号位 | 固定防御 | 以副属性和套装适配为主 |
| 四号位 | 攻击 / 生命 / 防御加成、效果命中、效果抵抗 | 在输出、生存和控制可靠性之间取舍 |
| 五号位 | 固定生命 | 提供生存底座，兼顾副属性用途 |
| 六号位 | 攻击 / 生命 / 防御加成、暴击、暴击伤害 | 暴击尚未达标和已达标时，评价会改变 |

- **成长节点：** 历史机制为最高强化至15级，在3、6、9、12、15级增加或强化副属性，最多四条副属性。随机结果与每次升级固定增加主属性不同，UI应分开表达。

- **套装关系：** 常规配装要考虑两件、四件效果是否成立；首领御魂还带来面向怪物战斗的组合。不要把“凑齐六件同套”当唯一目标。

- **筛选顺序：** 先排除不满足位置、套装、速度和关键属性的方案，再在可用方案里比较输出。速度失败的高攻击方案不应排在可用方案前面。

## 掉落、强化、保留与处理

```mermaid
flowchart TD
 A[获得单件] --> B{位置与属性有潜在用途吗}
 B -->|有| C[锁定或加入候选]
 B -->|暂时没有| D[标记待整理]
 C --> E[分节点强化并观察结果]
 E --> F{满足队伍约束吗}
 F -->|是| G[保存方案并验证战斗]
 F -->|否| H[保留其他用途或退出培养]
 D --> I[批量处理前检查保护状态]
 H --> I
 I --> J[确认对象与返还资源]
```

这张图是整理建议。它不包含“垫刀”“特定时段出好属性”等未经证明的概率技巧。

### 强化成本必须能算清

原作各星级完整经验表、强化金币、材料返还率没有在本轮统一版本下核实。附录提供独立的1—15级经验与金币表、主属性曲线、副属性生成池及材料价值；所有数字标明为补充设计。玩家文档展示实际规则和未知，开发者仍能拿到一套不缺档的参考配置。

### 比较要有场景

- **短线输出：** 看能否在预定行动内结束战斗；溢出的生存可能没有实际收益。

- **长线首领：** 看资源能否持续、增益覆盖和长期存活，不只看开局爆发。

- **竞技：** 看对手是否破坏启动条件；同一套高速方案可能牺牲抵抗或生存。

- **库存整理：** 未装备不等于无用。保护状态、方案引用和锁定应优先于批量规则。

## 整理与保护的参考设计

1. 先过滤用途，再选择候选，避免在全库中逐个翻找。

2. 显示已装备、锁定和被方案引用的状态；批量处理默认排除它们。

3. 在确认前预览具体对象和收益；筛选变化后重新计算，不能继续处理旧选择。

4. 操作结果可追溯；网络重试不得重复扣除。此处是开发建议，原作服务器实现未知。

## 评价与边界

最值得借鉴的是装备与队伍条件的连接；最需要控制的是“有用的随机”变成“无止境整理”。本版原型只验证条件反馈，不模拟真实掉落、强化随机或全库优化。
