# 参考实现公共契约 v1

> **本篇全部为 P：参考设计。** 这是为本批文档选择的实现约定，不是三款游戏的源码、后台或真实数值。各模块通过 R-ID 和配置覆盖本篇的默认行为。目标是可以据此实现和联调一个范围明确的参考版本。

## 责任边界

模块负责自己的业务状态；钱包、背包、存档、奖励、时间分别是公共依赖。单机由本地领域层实现这些服务，联网产品由权威服务端实现；客户端负责输入和显示，不自行确认财产变化。技术栈不限定。模块文档引用的服务在本篇定义，不把“调用服务”当成遗漏规则的借口。

## 命令、事务与恢复

请求封套：`{requestId:string, actorId:string, expectedRevision:int>=0, configVersion:string, command:string, payload:object}`。参考 requestId 使用 UUID；同一动作重试复用原 ID，新动作生成新 ID。

响应：`{requestId, code, revision, result, events[]}`。code 枚举 `OK / STALE / INVALID / LOCKED / INSUFFICIENT / CAPACITY / EXPIRED / NOT_FOUND / RETRYABLE`；失败响应含机器可读 reason 与最新可见状态。UI 根据 code 展示，不解析服务器中文文案。

处理顺序固定为：查已提交 requestId → 校验配置版本和 revision → 校验身份、状态、条件与容量 → 计算变化 → 一次提交状态、钱包、物品、去重记录 → 返回结果。重复 ID 不重新抽随机数、不再次扣款。相同 ID 不同 payload 返回 INVALID。版本过期返回 STALE，任何资源都不变化。

单机提交采用临时快照＋校验和＋原子替换；保留上一份有效快照。保存失败则整次操作不成功，UI 保持旧状态；重启恢复最近有效提交。联网采用同一事务或可靠事务日志，绝不把“先扣费、稍后尽力发奖”当成功。等待 8 秒无响应进入“确认结果中”，允许查询原 requestId；查询未知则同 ID 重试。不得因为客户端超时就另发一次新购买。

## 资源、背包与奖励

钱包使用资源 ID→非负整数（64 位；JSON 超出安全整数时用十进制字符串）。Spend 不足则整次失败；Grant 超过模块配置上限时保留为待领取，不静默丢弃。可交易／不可交易资源必须不同 ID。

参考背包以实例 ID 保存非堆叠装备，以 `(itemId, bindType)` 保存可堆叠物。默认容量 100 个非堆叠实例、每堆上限 9999；这些是通用原型参数，不是原作背包结论。装备中的实例仍占容量。接收奖励前模拟整个批次：容量足够一次入库；不足全部进入待领取队列，不部分扣除奖励。队列默认无过期、按创建时序显示，领取可逐条；正式运营容量与回收政策须单独设计。锁定／已装备物品不可销毁；需要先显式解锁／卸下。

奖励封套：`{rewardId, sourceType, sourceInstanceId, grants[], createdAt}`。同一 rewardId 只发一次。领域模块决定“谁有资格及何时结算”，奖励服务只负责幂等发放与容量处理。UI 可显示待领取不代表已经获得可消费余额。

## 时间、随机与数值

战斗参考逻辑步长 50ms，表现插值独立。定时事件使用逻辑 tick，暂停时不推进；联网经济时间用服务端 UTC，展示时转时区。计数器到 `now >= endAt` 即到期。日周重置按模块指定时区和边界，默认 UTC+8 每日 00:00、每周一 00:00；不是所有游戏原作通用规则。

百分比用基点整数，10000=100%。抽奖输入整数权重，排除不合法项后按剩余权重归一；权重总和必须大于 0。选择随机整数 `r∈[0,total-1]`，按稳定 itemId 排序累计区间；示例权重 2、3 对应区间 [0,1]、[2,4]。随机序列与配置版本绑定；结果在提交时保存，重新打开界面不改变。联网不向客户端暴露可预测的未来随机序列。

最终伤害默认 `max(1, floor(base × (10000+addBonusBps)/10000 × multiplierBps/10000 - defense))`；各模块不用伤害公式时无需引用。多段攻击逐段结算，最终段不补小数；属性上限及不同类别乘区由模块明确。业务数值不使用显示后四舍五入的字符串反算。

## 事件与版本

事件封套：`{eventId, aggregateId, revision, tickOrTime, kind, payload}`。订阅方按 eventId 去重；表现可重复刷新，奖励不可重复领取。当前快照保存 `schemaVersion / configVersion / revision`。读档时先迁移结构；缺少配置 ID 时使用存档中最后有效快照并标记待迁移，禁止默默替换成另一件物品。关卡途中固定规则版本，更新在下一局启用。

## UI 与可访问性基线

按钮六态：可用、按下、禁用（附原因）、请求中、成功、失败。危险操作明确列出目标与损失；返回只关闭未提交编辑，不撤销已提交事务。财产性动画可以跳过，跳过不影响结算。颜色同时配图标／文字；参考触控热区不小于 44×44 CSS px，最终游戏像素密度由项目换算。

原型资产使用占位图。每模块 UI-ID 表中的图标、状态、动效是交付清单；原图只作为有来源的观察证据，不要求直接复制原作资产。音效设置提供独立总开关，重复事件合并播放以免连点叠声。

## 联调基线与测试状态

需准备：可控时钟、固定随机序列、模拟断网／保存失败、钱包与背包快照、事件记录。每模块 T-ID 为待执行验收用例；本文是设计交付，**尚未开发这些参考模块，也未运行玩法验收**。结构校验和图片检查不能替代这些用例。

全局必测：同 ID 重放不重复发奖；旧 revision 不修改资源；交易失败所有状态回滚；断线恢复与有效快照一致；无效配置无法开启新局；用户看见的扣款和实际状态一致。

模块单测默认使用隔离夹具：未在用例给定中声明的装备、天赋、技能、侍从、权益均不生效。整游联调则启用显式方案快照，不可直接拿无加成的伤害算例套在完整初始阵容上。模式覆盖优先于模块默认（如副本免混沌石、合作不暂停），覆盖表必须在开战配置中显式存在，缺失则拒绝该模式启动。
