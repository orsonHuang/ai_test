# 作者正文与排版

用于本库的游戏分析、系统文章及其网页导出。2026-10-17 用户通过蔚蓝星球样稿确认以下阅读要求。

## 文章层次

- 游戏分析覆盖产品名与平台、项目介绍（类型、美术、玩法、逐项亮点及有日期的市场数据）、核心循环、前中后期节奏、商业化、可点击系统地图、数值框架。
- 系统文章说明目的与边界、功能、玩家流程、具体规则与取舍、UI 区域及交互状态、数值关系、评价与适用条件。原作缺失规则保留未知；可开发补充放独立附录并明确标注。
- 公开正文不展示文件目录、内部规则编号或未经解释的 F/I/P/U。来源随事实就近引用；分析标题和措辞表达观点属性，补充示意图在图旁标注。删去重复免责声明，但保留影响结论的版本、范围与证据缺口。

## 段落与列表

- 有执行顺序、先后阶段或操作步骤，用 Markdown 有序列表 `1. 2. 3.`；并列功能、独立观点和分段说明用无序列表，网页统一显示 `·`。不可为了看起来整齐把并列项编号成流程。
- 每个列表项讲清一个要点，可用“**要点：** 解释”开头。长列表项先拆成独立信息，不把整个章节塞进一个项目。普通导语、图注可保留短段落。
- 段落、列表项之间留空行；标题与正文分开。网页必须有实际段间距，不能依赖被 CSS reset 清除的 Markdown 空行。
- 使用语义化 `ul/ol/li`，通过 CSS 控制中点标记；不手工把 `·` 塞进普通段落，不用连续空格或空 `<p>` 排版。嵌套仅用于明确从属关系。
- 正文左对齐，控制行宽，标题前留白大于标题后。中文正文从 15px、约 1.9 行高、约一行的段间距起调，桌面和 320/390px 窄屏实际检查；不照搬英文字符数与行高。

## 简洁与作者视角

- 直接写观察和判断：“合作界面中……”代替“从已查看的合作界面来看……”；“这一设计……”代替重复的“我的分析是……”。保留论据、因果、代价，删除叙述研究过程的套话。
- 观点要落到具体选择或体验。例如比较合成前后整条防线的变化，而非只写“提升策略深度”。必要的第一人称可以保留，不要求每段自我介绍。
- 不因精简而把建议改写成原作事实，或删掉会影响结论的限定。

## 网页阅读验收

- 顶部明确游戏名、平台及当前是整游还是系统分析；系统标题区域右上方放收藏。
- 目录上方提供“返回上一层”和“返回主页”，向下滚动仍可访问。主页指游戏种子案例库首页。
- 从整游地图进入系统后，上一层返回整游文章并恢复进入前的阅读位置；关联系统跳转、刷新及浏览器前进后退也要保留对应访问的上下文。直达系统无来源时，上一层回所属游戏。
- 检查真实点击、长文滚动、流程图加载后的定位、收藏持久化及移动端布局；正文规则与渲染样式共同验收。
