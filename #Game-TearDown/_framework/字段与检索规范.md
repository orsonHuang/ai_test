# 字段与检索规范 v1

## 文件布局

每款游戏使用 `README.md`、`game.json`、`sources.json`、`systems/*.md`、`assets/`、`roles/`。机器读元数据，读者读 Markdown；正文不重复存到 JSON。共享目录 `catalog.json` 从各游戏的 game.json 生成。

## 游戏记录

| 字段 | 形式 | 语义 |
|---|---|---|
| schemaVersion | 1 | 格式版本 |
| id / title | 唯一英文 ID／显示名 | ID 不随标题调整而改变 |
| platform / region / build | 字符串或 null | 用户指定平台，无法核实的构建号为 null |
| asOf / scope / excluded | 日期／范围说明／排除项数组 | 资料截止日与研究边界 |
| playModes | 数组 | solo / coop / pvp；可组合 |
| businessModels | 数组 | premium / iap / ads / subscription / dlc；未核实用空数组，并列入 unknowns |
| operationModels | 数组 | complete / expansion / live-service / seasonal |
| evidenceStatus | 状态枚举 | 不代表游戏品质 |
| systems | 案例记录数组 | 见下表 |
| unknowns | 字符串数组 | 游戏层缺口 |

## 系统案例记录

| 字段 | 形式 | 语义 |
|---|---|---|
| id / title / type | 稳定 ID／标题／系统类型 | 同类跨游戏可筛选 |
| presence | present / unknown / absent / out-of-scope | presence 不替代证据成熟度 |
| status / depth | evidenceStatus／overview 或 deep | 深入程度与证据级别分开 |
| path / revision | 相对游戏目录的正文路径／整数 | 收藏绑定 id，修订递增 |
| tags | 数组 | 已证实的机制标签；推断标签不进事实筛选 |
| facts | 数组 | 每项 id、claim、sources（来源 ID 数组） |
| media | 数组 | id、path、kind、caption、sources、publication |
| related | 案例 ID 数组 | 关联系统，不复制正文 |
| specStatus / referenceStatus | reviewable / specified-slice-unimplemented | 规格可评审、参考切片有定义但未实现；不表示原作已验证 |
| platformApplicability | 范围说明或 shared-unverified | 共用旧图无法核实目标平台时须明确 |
| attributes / referenceAttributes | 原作／参考属性对象 | 两个筛选命名空间，不能合并 |

系统类型：combat、build、inventory、equipment、progression、economy、level、arena、coop、social、narrative、collection、monetization、liveops、onboarding、settings。一个主要 type + 多个 tags；新增类型先定义边界。

## 模块筛选

| 模块 | 可扩展属性 | 比较前需要的上下文 |
|---|---|---|
| 背包 | 容量模型、堆叠、锁定、筛选、批量处理、扩容付费、整理是否参与玩法 | 物品获取频率、平均保留量、装备绑定、误操作代价 |
| 竞技场 | 同步/异步、匹配依据、赛季重置、奖励分配、养成属性带入 | 账号阶段、模式、参赛次数、付费影响证据 |
| 养成 | 局内/永久、随机/确定、分支/线性、重置成本、追赶 | 目标玩家阶段、资源来源、上限、内容周期 |

扩展属性为对象，值允许 null；布尔字段必须支持 true / false / null。默认筛选只匹配已知值；“包含未知”由用户主动开启。空字段既不命中“没有付费”，也不命中“有付费”。

“优秀”筛选转换成具体目标：低整理成本、强构筑空间、误操作保护、便于移动触控等。每个判断附依据和条件；没有测量时不要伪造效率排名。

## 网页与收藏交接

网页通过 catalog 的 gameId、systemId、path 找同一份正文。卡片显示游戏／平台、系统、机制标签、证据状态、资料日期和一条适用条件。详情页显示图文、相关系统和来源，支持按岗位跳读。

收藏结构建议为 `{systemId, revisionSeen, collectionId, note, createdAt}`。收藏夹用于“正在做的项目／要解决的问题”，不只是点赞。跨版本对比提醒 platform/build/asOf 不同。默认媒体导出只带 original / authorized；来源链接可以保留。当前规范不表示网页已接入。

## 首批实际交接

运行 `node _framework/scripts/build-catalog.mjs 暖雪-Steam 永远的蔚蓝星球-App 英雄没有闪-微信小游戏`（工作目录为本库，带空格路径需shell引用）。输出根目录`catalog.json`与`public-media.json`。catalog正文路径相对库根，URL使用逐段编码，不能把目录名中的`#`当浏览器锚点。

catalog的defaultDiscoverable只依据presence=present；展示时仍必须显示历史日期和平台边界，不能把历史证据称“现版本已验证”。presence未知的6份微信案例可在“含待核实/参考方案”视图出现。referenceAttributes只在用户选择“看参考设计”时用于筛选。

public-media只是允许公开的图片清单，不是完整发布包。原Markdown仍含研究引用图片；网页公开导入时，对不在清单中的媒体显示原来源链接与说明，不能照搬本地图片路径或直接把整个assets目录发布。首次接入需要把正文、图注、来源一起渲染，并检查Mermaid支持；无Mermaid支持时本地SVG概览仍可读。

建议导入验收：27个ID唯一；引用路径可读；6个unknown案例不默认命中原作筛选；参考锁定/分解功能不污染原作属性；收藏在标题变化后仍由ID定位；研究引用图片不进入默认公开包。当前没有改动或重新部署现有游戏种子网页。
