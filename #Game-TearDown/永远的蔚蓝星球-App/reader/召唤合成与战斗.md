# 召唤、合成与局内强化

永远的蔚蓝星球 · 手机 App · 核心玩法 / 战斗

**这一系统要解决的问题：让玩家在不完全可控的条件下，持续组织一条能应对当前威胁的防线。** 它的设计价值在于把“获得单位”与“决定如何使用单位”安排在同一局里。随机结果提供问题，合成和强化提供调整手段。

## 设计目的与系统边界

- **战斗目的：** 验证英雄配置、养成投入和临场选择能否应对当前威胁。

- **局外条件：** 英雄等级与装备决定带入战斗的能力。

- **局内变化：** 单位星级、场面和强化只作用于本局，需与永久培养分开理解。

- 官方介绍明确列出随机召唤、技能搭配与合成进化。[玩法依据](https://www.taptap.cn/app/713683)。具体随机权重、完整合成限制与所有模式的资源规则，本次没有得到同一版本的完整规则面板。

## 系统功能：四件事形成一个决策过程

| 功能 | 玩家在做什么 | 设计问题 |
|---|---|---|
| 召唤 | 把可用的局内资源变成场上单位 | 新单位能否改善当前短板，玩家是否还能补救随机结果？ |
| 合成 | 调整场上单位，追求更高星级与新的能力组合 | 收益是否足以补偿当下场面的变化？ |
| 强化选择 | 在本局提供的选项中确定方向 | 选项是在改变打法，还是只有数值大小的差异？ |
| 威胁处理 | 观察敌人、防线与技能表现，再调整 | 玩家能否读出危险来自哪里，并及时行动？ |

```mermaid
flowchart TD
    A[观察本局威胁] --> B{当前最缺什么}
    B --> C[补充单位与场面]
    B --> D[合成与阵容成型]
    B --> E[用强化补能力短板]
    C --> F[观察清怪与防线变化]
    D --> F
    E --> F
    F --> A
```

这是决策示意，不是原作的代码执行顺序。三种行动并不保证随时可用，实际操作要受资源、场上条件与强化出现时机约束。

## 规则与策略：为什么“更高星”不应成为唯一答案

- 合成首先改变场面，再带来收益。需要比较合成前后的整条防线，而不只比较一个单位的面板：是否失去正在承担清怪任务的单位？是否减少关键效果覆盖？高星单位的收益能否及时生效？这些问题能解释为什么相同操作在安全波次和危险波次可能有不同价值。

- 一个具体的历史样本来自竞技场玩家攻略：作者对闪电之子的场上数量、相邻关系与剑圣的星级提出了不同侧重。这说明至少在该攻略讨论的配置里，英雄并不共享同一种培养目标。[2025-07-16 玩家攻略](https://www.taptap.cn/moment/694655628546670613)。不能据此把推荐阵容定为当前最优，但可以据此建立分析视角：**有的能力依赖数量，有的依赖单体质量，有的依赖连接关系。**

- 对于随机性，我会分别记录随机发生的位置、玩家提前知道多少、出现不理想结果后能做什么。如果只有结果随机而没有补救动作，失败更容易被归因于运气；如果每种结果都能通过不同操作转化为可用条件，重复开局才有学习空间。

## 从一张阵列读懂数量、星级与位置

![竞技场阵列](../reader-assets/arena-board.png)

- **数量决定覆盖：** 图中同一英雄可以占据不同位置。保留多个单位，会增加同时工作的攻击来源；把它们合成后，必须确认剩余火力能否承担当前压力。

- **位置决定关系：** 相邻增益与射程使“放在哪”成为独立问题。这张图只展示阵列，不能据此量出道路长度、所有格位或攻击范围。

- **局内星级不等于永久等级：** 前者改变这一局的场面，后者属于账号培养。战报若把两者合成一个战力值，就无法说明问题出在开局条件还是临场处理。

### 一次合成的复盘顺序

1. 先记录合成前的输出单位、控制来源、空格和接近城墙的威胁。
2. 再记录被消耗的单位及合成结果；不要只记结果星级。
3. 对比随后一段时间的漏怪、击杀和可再次召唤的时间。
4. 判断收益来自新能力、腾出空间还是随机好运。不能把同一场胜利归因于全部操作都正确。

### 新机制怎样补救随机结果

S1 的空间宝石允许通过拖动交换英雄位置，移动存在冷却；这是赛季预告里的特定机制，不是普通主线默认操作。[官方赛季机制说明](https://www.taptap.cn/moment/841069082835944939)

我认为它的作用是把部分“召到了却位置不对”的挫败转成可处理的问题。交换次数或冷却仍会保留选择成本。研究时要分别测量合成结果是否随机，以及位置是否可调整，不能用一句“全看运气”概括两者。

## 战斗数据应该记录什么

| 观察项 | 记录方式 | 用来解释什么 |
|---|---|---|
| 首个稳定输出形成时间 | 从开战到能持续处理普通波的时间点 | 随机开局与养成的启动差异 |
| 合成后火力缺口 | 合成前后同长度窗口的清怪、漏怪 | 升星收益有没有及时兑现 |
| 强化兑现条件 | 选项、适用英雄、实际触发次数 | 是否选到当前阵容用不上的效果 |
| 防线损失来源 | 敌人类别、抵达时间、控制状态 | 缺输出、缺覆盖还是关键控制断档 |
| 失败后的调整 | 下一局更换配置与局内行动 | 玩家是否能从失败学到可执行方法 |

这些是研究采样字段，尚无实测样本，不能给出通过率或平均局长。

## UI 分析：把危险与可操作对象放在一起读

上图是为分析整理的功能线框，**不是原作界面复刻**。现有原图未覆盖完整战斗 HUD，因此下面列的是补充设计建议，不能作为原作已有功能。

| 区域 | 应表达的信息 | 交互与状态建议 |
|---|---|---|
| ① 战况 | 当前波次、防线状态与主要危险 | 危险变化持续可见；不要只用瞬时飘字表达失败原因 |
| ② 战场 | 敌人类型、位置与技能作用范围 | 优先保证关键威胁可辨识，特效不能长期遮住危险对象 |
| ③ 阵列 | 单位身份、星级和可合成关系 | 选中时说明合法目标；无效操作告诉玩家缺少什么条件 |
| ④ 决策区 | 召唤成本、当前资源、强化选项 | 资源不足时保留成本；选项写出效果对象和条件 |

强化选项的文字应回答“改了谁、改了什么、何时生效”。例如“提高伤害”信息不足；若是限定某英雄、某星级或某种敌人，就需要在选择时看见。具体表现可以简洁，但关键条件不能藏在另一个页面里。

## 数值关系与阶段变化

按单局推进顺序，可分为三个阶段（分析划分，并非原作固定波次）：

1. **建立场面：** 补充单位，先维持基本清怪能力。

2. **配置成型：** 让关键能力尽早进入循环。

3. **稳定防线：** 维持阵型，覆盖主要威胁。

- 评估收益时至少同时记录“能力多大”与“何时生效”。一次较晚到来的高收益，可能无法挽回前面已经失去的防线。还要区分总伤害与有效伤害：打在已经必死的小怪上的溢出，不等于处理了真正威胁。这些指标比单独累计合成次数更有解释力。

## 我的评价与迁移条件

- 值得借鉴的是让相同基础操作服务不同英雄目标。它能在较少操作类型下产生组合深度。但前提是英雄差异可读、合成后果可解释、危险来临前有决策窗口。若自己的项目只需轻度放置体验，过多阵型和条件规则反而可能增加负担。

- 下一轮实机应录下完整的一胜一败，逐次标注召唤、合成、强化、危险变化与失败原因。只有这样，才能判断这里描述的决策空间在真实操作中有多大。
