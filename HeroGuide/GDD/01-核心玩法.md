# 01 · 核心玩法

## 1. 玩法概述

玩家不直接操控勇者移动，而是通过**放置有限物品**改造地图，间接影响勇者的自动寻路结果。

**核心公式**：

```
勇者 = 永远走最短路径 + 完全无视危险
玩家 = 用有限物品让"最短路" = "安全路"
```

勇者是"蠢但勇"的——他只会沿几何最短路径冲向魔王，不会绕开陷阱、不会主动避开守卫视野、不会寻找守卫背后。玩家唯一能做的，就是用石头堵路、用传送门搭桥，迫使寻路算法重新计算，让新的最短路径恰好绕开所有危险。

---

## 2. 双阶段循环

```
┌─────────────────────────────────────────────┐
│              准备阶段（策略）                 │
│                                             │
│  观察地图 → 放置物品 → 查看预计路径（虚线）  │
│      ↑                    ↓                 │
│      └── 调整物品 ← 路径不安全？ ──┘         │
│                    ↓                        │
│              路径安全 / 玩家满意              │
└──────────────────────┬──────────────────────┘
                       ↓
┌─────────────────────────────────────────────┐
│              执行阶段（观看）                 │
│                                             │
│  勇者按最短路径自动行走 → 触发事件 → 结算     │
│                                             │
│  到达魔王 → 胜利                             │
│  踩陷阱 / 进守卫视野 / 困死 → 失败            │
└─────────────────────────────────────────────┘
```

### 2.1 准备阶段

| 行为 | 说明 |
|------|------|
| 观察地图 | 查看墙壁、陷阱、守卫朝向与视野、魔王位置 |
| 放置物品 | 从有限物品栏中选择物品，放置到合法格子上 |
| 查看路径 | 勇者预计最短路径以虚线实时显示 |
| 调整策略 | 可移除已放置物品（退还到物品栏），重新放置 |
| 启动执行 | 确认布局后点击"出发"按钮，进入执行阶段 |

**实时反馈**：每次放置/移除物品，虚线路径立即重算。若无可达路径，虚线变红并提示。

### 2.2 执行阶段

| 行为 | 说明 |
|------|------|
| 自动行走 | 勇者按准备阶段确定的最短路径行走，玩家不可干预 |
| 事件触发 | 经过陷阱 → 死亡；进入守卫视野 → 被抓；经过守卫背后 → 击杀守卫 |
| 结果结算 | 到达魔王 → 胜利结算；任何致死事件 → 失败结算 |

**执行阶段不可暂停干预**（MVP 版本）。玩家在准备阶段就必须确保路径安全。

> V2 考虑：执行阶段引入"紧急停止"或"限时放置"机制，增加紧张感。MVP 不做。

## 3. 地图与网格

- **网格制**：地图为 N×N 方格网格（MVP 推荐 8×8 ~ 12×12）。
- **坐标系**：左上角为原点 (0,0)，x 向右增，y 向下增。
- **格子类型**：

| 格子类型 | 可通行 | 勇者寻路视为 | 说明 |
|----------|--------|-------------|------|
| 普通地面 | ✅ | 可通行 | 基础格子 |
| 墙壁 | ❌ | 障碍 | 不可放置物品 |
| 陷阱 | ✅ | 可通行 | 踩上即死（勇者不知道） |
| 石头（玩家放置） | ❌ | 障碍 | 堵路用 |
| 传送门入口 | ✅ | 可通行（特殊） | 瞬移到出口 |
| 传送门出口 | ✅ | 可通行 | 被动等待 |
| 守卫本体 | ❌ | 障碍 | 无论正反都是障碍 |
| 守卫视野格 | ✅ | 可通行 | 走入即被抓（勇者不知道） |
| 守卫背后格 | ✅ | 可通行 | 安全，经过时触发击杀 |
| 魔王格 | ❌ | 目标 | 勇者到达相邻格触发击杀 |
| 死胡同 | ✅ | 可通行 | 勇者走进去出不来（无路可走时失败） |

> **关键设计**：陷阱、守卫视野格对勇者的寻路算法来说是**可通行的**，不是障碍。勇者会"傻乎乎"地走进去。这正是玩家需要解决的问题。

---

## 4. 胜负条件

### 4.1 胜利条件

勇者沿最短路径行走，**安全到达魔王相邻格** → 触发击杀动画 → 胜利。

> 魔王格本身是障碍，勇者走到魔王相邻格时自动触发击杀（无需玩家操作）。

### 4.2 失败条件

| 失败情况 | 触发时机 | 反馈 |
|----------|----------|------|
| 踩中陷阱 | 勇者走到陷阱格 | 陷阱动画 + 失败提示 |
| 进入守卫视野 | 勇者走到守卫视野格 | 守卫抓捕动画 + 失败提示 |
| 走入死胡同 | 勇者走到无后续可通行格的位置 | 勇者原地困惑 + 失败提示 |
| 无可达路径 | 准备阶段就无法找到通往魔王的路 | 虚线变红，无法启动执行 |

> **死胡同判定**：勇者走到某个格子后，排除来路，没有任何可通行相邻格 → 失败。注意：陷阱格和守卫视野格虽然"致命"但算"可通行"，所以勇者会走进去而不是判定为死胡同。死胡同特指"真的没有路可走"的格子。

## 5. 操作方式（微信小游戏 · 竖屏触控）

### 5.1 准备阶段操作

| 操作 | 效果 |
|------|------|
| 点击物品栏物品 | 选中该物品（高亮） |
| 点击地图空格 | 在该格放置选中的物品（若合法） |
| 点击已放置物品 | 移除该物品（退还物品栏） |
| 长按守卫 | 高亮显示其视野范围 |
| 点击"出发"按钮 | 进入执行阶段 |

**放置合法性**：
- 不可放置在墙壁、守卫本体、魔王格上
- 不可放置在守卫视野格内（守卫面前不能放障碍物）
- 传送门必须成对放置（选入口格 + 选出口格）

### 5.2 执行阶段操作

| 操作 | 效果 |
|------|------|
| 无（自动播放） | 勇者按路径行走 |
| 点击屏幕 | 加速播放（2x） |

## 6. 核心设计原则

1. **勇者永远"蠢"**：勇者不会学习、不会避让、不会主动绕后。他的行为 100% 由最短路径算法决定，玩家的乐趣来自"操纵算法"。
2. **实时反馈是生命线**：准备阶段每次放置物品，虚线路径必须即时更新。延迟 > 100ms 会破坏体验。
3. **失败不惩罚**：失败后 3 秒内可一键重开，保留玩家上次放置的物品布局（可微调）。
4. **一关一谜**：每关只考验一个核心技巧，避免信息过载。
5. **多解鼓励**：除最优解外，允许玩家用不同物品组合过关。星级只看"用物品数"，不限方式。

## 7. 与旧 DragonQuest-Maze GDD 的本质区别

| 维度 | 旧 GDD（回合制） | 本项目（引导寻路） |
|------|-----------------|-------------------|
| 玩家角色 | 直接操控勇者，每步决策 | 旁观者 + 引导者，放物品影响路线 |
| 勇者行为 | 玩家决定走哪格 | AI 自动走最短路径 |
| 核心张力 | "我下一步走哪" | "怎么用有限物品让最短路 = 安全路" |
| 节奏 | 每步思考 | 准备阶段慢思考 → 执行阶段快观看 |
| 参考原型 | 推箱子 / Sokoban | Lemmings / Bridge Constructor |
